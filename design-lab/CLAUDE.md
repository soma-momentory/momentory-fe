# Momentory Design Lab — Claude 작업 지침

## 목적

이 디렉터리는 Momentory 전체 UI/UX를 탐색하고 웹에서 상호작용을 검증하는 독립 프로토타입 환경이다. 운영 앱을 구현하거나 기존 Expo 앱을 웹으로 이식하는 곳이 아니다.

## 시작 전에 읽기

1. `../docs/redesign/SCREEN_INVENTORY.md`
2. `README.md`
3. `../docs/redesign/current-screens/`의 현재 화면 이미지
4. 필요할 때만 기존 앱의 해당 라우트와 컴포넌트 코드

화면 인벤토리와 코드가 다르면 실제 코드를 우선하고 차이를 문서에 기록한다.

## 경계

- 수정 범위는 원칙적으로 `design-lab/` 내부다.
- 기존 앱의 `app/`, `src/`, `assets/`, `app.config.ts`, 루트 `package.json`과 lockfile을 수정하지 않는다.
- 기존 디자인 리소스를 복사·이동·삭제하지 않는다.
- 실제 API, 소셜 로그인, OS 권한, 알림, 캘린더, 위치, 분석 SDK를 연결하지 않는다.
- 프로토타입 데이터는 화면 안 fixture 또는 Lab 전용 상태로 둔다. 실제 사용자 데이터를 사용하지 않는다.
- 새로운 기능을 기존 기능처럼 표현하지 않는다. 제안 기능에는 “신규 제안” 표기를 붙인다.
- 디자인 방향이 합의되기 전에는 토큰·브랜드 스타일을 정본으로 선언하지 않는다.
- 외부 UI 라이브러리를 추가하지 않는다. React와 기본 CSS로 해결하기 어려울 때만 근거를 남기고 추가한다.

## 구현 규칙

- 화면은 `src/screens/`, 재사용 요소는 `src/components/`, CSS는 `src/styles/`에 둔다.
- 375, 390, 430px 프레임에서 확인한다.
- 마우스뿐 아니라 키보드 포커스, 버튼 이름, `aria-current`, `aria-pressed`, dialog 의미를 유지한다.
- 라우트는 현재의 가벼운 해시 라우팅을 우선 사용한다. 중첩 라우트나 데이터 라우팅이 실제로 필요해질 때만 라우터 패키지를 검토한다.
- 한 화면의 주요 상태를 URL 또는 화면 내부 명시적 컨트롤로 재현 가능하게 한다.
- 시안 화면에는 기본/로딩/빈/오류/권한 거부/저장 중/완료 상태를 누락하지 않는다.
- 현재 화면 이미지는 `virtual:current-screens`와 `ReferenceImage`를 사용한다. 상대 경로를 우회해 복사본을 만들지 않는다.
- CSS 이름은 Lab 도구 UI와 시안 UI가 섞이지 않도록 역할을 드러내게 작성한다.

## 디자인 판단 기록

새 디자인을 시작하면 각 화면 또는 흐름에 다음을 남긴다.

- 근거가 된 기존 화면/코드
- 유지한 사용자 행동과 변경한 사용자 행동
- 확인된 구현 사실과 새 제안의 구분
- 상태별 화면 차이
- 375/390/430px 검토 결과
- 접근성 및 키보드 동작

큰 방향을 확정하기 전에는 여러 탐색안을 서로 독립된 화면/경로로 유지한다. 탐색안을 기존 정본처럼 덮어쓰지 않는다.

## 검증

변경 후 최소 검증:

```bash
npm run build
```

인터랙션을 변경했다면 `npm run dev`에서 다음도 확인한다.

- 프레임 폭 375/390/430 전환
- 내부 탭과 브라우저 뒤로/앞으로
- 새로고침 후 현재 해시 경로 유지
- 오버레이 열기/닫기와 키보드 포커스
- 현재 스크린샷이 있을 때 목록/이미지 로딩

빌드 산출물 `dist/`와 `node_modules/`는 커밋하지 않는다.
