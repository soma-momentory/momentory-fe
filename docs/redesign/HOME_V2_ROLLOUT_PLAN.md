**행 기하 — 고정 `ROW_PITCH` 를 실측 한 칸으로 바꾼다(P2).** 지금 `ScheduleList` 는 한 칸을 상수
`ROW_PITCH = 24 + 20 = 44`(`ScheduleList.tsx:34~36`)로 두고 **줄 위치(`top: index * ROW_PITCH` · 206행) · 목록 높이
(`count * ROW_PITCH` · 99행) · 빈 슬롯 위치(103행) · 끌기 칸 수(`Math.round(dy / ROW_PITCH)` · 81행) · 비켜서는 거리(197~199행) ·
줄 높이(243행)** 를 전부 그 수로 계산한다. 큰 글꼴 배율에서 제목 줄이 24 보다 커지면 줄이 겹치고, 끄는 거리와 놓이는 자리가
어긋난다. LY-1 임계값이 「글꼴 배율을 반영한 실측 1행」을 쓰므로 **목록 기하와 임계값이 같은 값을 써야** 한다.

- **한 값 `pitch`**: `ScheduleList` 가 첫 줄 내용의 `onLayout` 높이(없으면 `ROW_CONTENT × PixelRatio.getFontScale()` 로 시작)
  \+ 줄 간격 20 을 한 칸으로 잰다. 위 여섯 자리가 **전부 이 `pitch` 하나**를 쓴다(상수 직접 참조 금지 · 내보내던 `ROW_PITCH` 는
  「배율 1 의 기본값」으로만 남긴다). 줄 높이가 고르다는 전제(제목 한 줄 · `numberOfLines={1}` 말줄임)는 그대로 둔다 —
  줄마다 다른 높이를 지원하지 않는다. 바뀐 `pitch` 는 끄는 중에는 반영하지 않고 끌기가 끝난 뒤 반영한다(끄는 도중 칸이 바뀌지 않게).
- **LY-1 과 연결**: `ScheduleList` 가 잰 `pitch` 를 `onRowPitch` 로 올리고, `homeLayoutMode` 의 「1행 높이」는 **이 값**이다(따로 재지 않는다 · §2.4).
- `appearance: "paper"` 의 v2 시각(체크 24 · 히트 44)에서 내용 높이가 달라지면 그 기본값만 `paper` 쪽에서 바꾼다 — 계산 경로는 하나다.
- 접근성 동작(「위로/아래로 이동」 · S11)은 칸 수로 옮기므로 `pitch` 와 무관하다.

### 2.4 하단 고정 주간 감정과 목록 스크롤의 공존(HD-7 · WK-1)

- **레이아웃**: 바깥은 스크롤하지 않는 `View`(flex 1), 그 안에 고정 영역 → 목록 `ScrollView`(flex 1 · `minHeight: 0`)
  → 도크 자리만큼의 아래 여백. 도크는 v2 처럼 절대 배치(탭바 위 · `layout.tabBar + inset` 위로)이고, 목록의
  `contentContainerStyle.paddingBottom` 에 **도크 높이 + 간격**을 더해 마지막 줄이 도크 뒤에 숨지 않게 한다.
- **v2 `docked` 의 한계**: v2 는 `fixedContent` 를 `overflow:hidden` 으로 자르고 목록만 `nestedScrollEnabled`
  로 돌린다(`HomeView.tsx:267~274 · 383`). 운영판은 **바깥 스크롤이 없으므로 중첩 스크롤이 생기지 않는다** —
  `nestedScrollEnabled` 는 필요 없다(Android 에서 끌기와 스크롤이 다투는 원인을 없앤다).
- **끌기 중 스크롤 잠금**: 지금은 바깥 `ScrollView` 를 잠근다(`HomeView.tsx:163`) — 운영판은 **목록
  `ScrollView`** 를 잠근다. 끄는 줄이 목록 경계를 넘으면 자동 스크롤하지 않는다(지금도 없다 · 범위 밖).
- **메뉴 아래 여백**: 지금의 `menuBottomInset`(`home.tsx:69` — 탭바 + 아래 안전 영역)에 **도크 높이 + 간격**을 더한다 —
  ⋮ 메뉴가 도크를 덮지 않는다.
- **목록 자리가 너무 좁을 때(LY-1)**: 360dp · 큰 글꼴 배율 · 짧은 기기(667pt)에서 고정 영역 + 도크 + 탭바가 화면을
  거의 다 먹으면 목록이 한두 줄만 남는다. 그때는 배치를 **두 가지 모드**로 나눈다.

  | 모드             | 언제                                   | 고정                            | 스크롤                                         |
  | ---------------- | -------------------------------------- | ------------------------------- | ---------------------------------------------- |

## 4. 날씨 FE/BE 계약(제안)

### 4.1 엔드포인트

```
POST /api/v1/weather/current
Authorization: Bearer <access>
Content-Type: application/json

{ "latitude": 37.57, "longitude": 126.98 }
```

**좌표는 URL 에 싣지 않는다(WX-2).** 쿼리스트링은 접근 로그 · 프록시 · CDN · 브라우저 기록 어디에나 남기 쉽다 —
본문은 HTTPS 안에서만 지나가고 기본 로그 형식에 들어가지 않는다. 조회지만 `POST` 인 것은 이 때문이며,
**부작용이 없다**(서버 상태를 바꾸지 않는다 · 재시도해도 안전하다)는 점을 계약 설명에 적는다.

| 항목      | 제안                                                                                                                                                                                                                              |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 요청 본문 | `latitude` −90~~90 · `longitude` −180~~180 · 숫자(문자열 아님) · **소수 둘째 자리**(FE 가 반올림해 보내고, BE 가 다시 반올림한다 — 신뢰하지 않는다). 그 밖의 필드는 무시. 일기 `PUT /diaries/{id}/weather` 본문과 같은 모양       |
| 인증      | 필요(`authedRequest` · 비로그인 호출 없음). 남용 방지 사용자별 속도 제한(예: 분당 30)                                                                                                                                             |
| 저장      | **좌표를 DB 에 저장하지 않는다.** 응답에도 좌표를 되돌려 주지 않는다                                                                                                                                                              |
| 로그      | 서버 · 리버스 프록시 · APM · 에러 리포터에서 이 경로의 **요청 본문 로깅을 금지**한다(요청 본문 캡처 끔 · 검증 실패 메시지에 값을 넣지 않음 · 예외 스택에 DTO `toString` 이 찍히지 않게). 실제로 지켜지는지는 PV-1 검증 항목(§4.8) |

| 시간 초과 | BE → MET 5초 · FE → BE 10초(`timeoutMs: 10_000` · 일기와 같다)                                                                                                                                                                    |

### 4.2 BE 몫 — 캐시 · MET 이용 약관

- MET Norway **Locationforecast 2.0 `compact`** 를 쓴다(일기 날씨와 같은 클라이언트를 공유).

  - 키 = 반올림 좌표(0.01° 격자 ≈ 1.1km) **하나뿐** — 사용자 id · 토큰 · IP · 기기 정보를 키에도 값에도 넣지 않는다.
    값은 MET 응답에서 쓰는 필드(조건 · 기온 · 시각)만.
  - **보관 기간 = `min(MET Expires, 60분)`**, `Expires` 가 없으면 30분. 만료되면 지운다(조회 시 무효화가 아니라 저장소가
    스스로 지우는 TTL). 재검증은 `If-Modified-Since`.
  - 저장소는 **프로세스 메모리**(예: Caffeine · 최대 항목 수 상한)를 기본으로 한다. Redis 등 공유 저장소를 쓰면 키에
    `EXPIRE` 를 반드시 걸고, 스냅샷(RDB/AOF) · 백업에 남는지 PV-1 에서 확인한다.
  - 이 보관 기간은 웹 처리방침 · 스토어 신고(§4.8)의 「보존」 항목의 근거가 된다 — 바꾸면 그쪽도 함께 바꾼다.
- **이용 약관**: 식별 가능한 `User-Agent`(앱 이름 + 연락처) · 좌표 소수 넷째 자리 이하 · 초당 20요청 이하 · `Expires`
  존중 · 403/429 에 물러서기. 출처 표기(CC BY 4.0)는 FE 가 HW-5 시트에서 한다.
- **바람**: MET `symbol_code` 에는 바람이 없다. `windy` 는 BE 가 `wind_speed`(m/s · 10m)로 판정한다 — 문턱 값은 BE 상수
  (제안: 10.8 m/s · 보퍼트 6). 강수 · 뇌우 · 안개가 있으면 그쪽 그림이 먼저다(§4.3 우선순위).
- **04:00 경계와 무관** — 홈 날씨는 「지금」이다. 하루 전환 시 FE 가 다시 묻는 것은 화면을 새로 고치기 위해서다.

### 4.3 조건 코드 체계(HW-2 · WX-1)

코드 = `family` + 수식어(고정 순서): `{family}[.{intensity}][.showers][.thunder][.{daylight}]`.
`intensity` 는 `light | heavy`(보통은 생략), `daylight` 는 `day | night`(`polartwilight` 는 BE 가 `day` 로 접는다 —
한국에서 나오지 않는다). `windy` 는 코드가 아니라 플래그다(강수가 없을 때만 그림에 쓰인다).

**MET `symbol_code` → family**(접미사 `_day/_night/_polartwilight` 를 떼고 본다 — MET 원문의 오타
`lightssleetshowersandthunder` · `lightssnowshowersandthunder` 도 BE 가 같은 줄로 받는다)

| MET 기본형(41종)                                                                                     | family          | intensity     | showers | thunder |
| ---------------------------------------------------------------------------------------------------- | --------------- | ------------- | ------- | ------- |
| `clearsky`                                                                                           | `clear`         | —             | —       | —       |
| `fair`                                                                                               | `fair`          | —             | —       | —       |
| `partlycloudy`                                                                                       | `partly_cloudy` | —             | —       | —       |
| `cloudy`                                                                                             | `cloudy`        | —             | —       | —       |
| `fog`                                                                                                | `fog`           | —             | —       | —       |
| `lightrain` · `rain` · `heavyrain`                                                                   | `rain`          | light/—/heavy | —       | —       |
| `lightrainshowers` · `rainshowers` · `heavyrainshowers`                                              | `rain`          | light/—/heavy | ✓       | —       |
| `lightrainandthunder` · `rainandthunder` · `heavyrainandthunder` (+ `…showersandthunder` 셋)         | `rain`          | light/—/heavy | (✓)     | ✓       |
| `lightsleet` · `sleet` · `heavysleet` (+ `…showers` 셋 · `…andthunder` 셋 · `…showersandthunder` 셋) | `sleet`         | light/—/heavy | (✓)     | (✓)     |

**FE 그림 고르기 — 자동으로 내려가지 않는다(WX-1 · MF-WX1)**. `src/features/home/model/weather.ts` 의
`stickerKeyFor(condition)` 은 **명시적인 표 두 장만** 본다. 코드를 잘라 가며 상위 계열(`rain` · `snow` · `thunder`)로
떨어지는 연쇄 규칙은 두지 않는다 — 그런 규칙이 있으면 「그림이 없는 조건은 숨긴다」는 WX-1 이 강도 · 소나기 · 복합에서 조용히 깨진다.

1. **전용 그림**: `condition.code` 와 **똑같은 키**의 그림이 `WEATHER_STICKERS` 에 있으면 그것(예: 나중에 `rain.heavy` 그림이 들어오면 `rain.heavy` 코드만 받는다).
2. **공통 그림 허용 표**(`SHARED_STICKER_CODES` — 아래 표): 1 이 없고 코드가 이 표의 **한 줄에 글자 그대로** 있으면 그 줄의 공통 그림.
   바람은 코드가 아니라 플래그라(§4.3 머리) 「`windy == true` · family 가 하늘 넷」 한 줄로 따로 적는다 — 강수 · 안개 코드에는 바람 그림을 쓰지 않는다.
3. **둘 다 아니면 숨김**(HW-4 · WX-1) — `unknown` · 표에 없는 복합(`sleet.*` · `snow.heavy.showers.thunder.night` 같은 눈 + 뇌우 등) 전부.

⚠ **낮/밤을 건너 대신 쓰지 않는다** — `clear.night` 에 해 그림(`sunny.png`)을 쓰면 틀린 날씨가 된다. 허용 표에도 넣지 않는다.

**공통 그림 허용 표**(`SHARED_STICKER_CODES` — 기존 6장 · 이 표에 없는 코드는 전용 그림이 생길 때까지 숨는다)

| 공통 그림     | 키          | **허용하는 조건 코드(글자 그대로 · 이것만)**                                                                                                                                                                                                                                          | 허용하지 않는 것(숨김)                                                                                          |
| ------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `sunny.png`   | `clear.day` | `clear.day`                                                                                                                                                                                                                                                                           | `clear.night` · `fair.*`(그림 검수에서 해 그림이 「대체로 맑음」을 말한다고 판정되면 `fair.day` 한 줄만 더한다) |
| `cloudy.png`  | `cloudy`    | `cloudy`                                                                                                                                                                                                                                                                              | `partly_cloudy.*` · `fog`                                                                                       |
| `rainy.png`   | `rain`      | `rain` · `rain.light` · `rain.heavy` · `rain.showers.day` · `rain.showers.night` · `rain.light.showers.day` · `rain.light.showers.night` · `rain.heavy.showers.day` · `rain.heavy.showers.night`                                                                                      | 뇌우가 섞인 `rain.*thunder*`(→ 아래 `thunder.png` 줄) · `sleet.*`                                               |

**새로 그릴 그림**(우선순위 — 그림 제작은 별도 · 그림이 들어오면 **파일 + 매핑**만 더한다. 그림의 키와 같은 코드는
자동으로 받고(규칙 1), 그 그림을 다른 코드에도 쓰려면 허용 표에 그 코드를 **한 줄씩** 더한다 — 예: `rain.heavy` 그림을
`rain.heavy.showers.day` 에도 쓰려면 그 코드를 명시적으로 적는다)

| 2    | `fair.day` · `fair.night` · `rain.light` · `rain.heavy` · `snow.heavy` · `rain.showers.day` | 강도 · 소나기 구분                                  |
| 3    | `thunder.snow` · `thunder.night` · `wind.night` · `sleet.heavy`                             | 드문 복합                                           |

`@/design` 금지 규칙과 같은 이유).

### 4.4 기존 `PUT /diaries/{id}/weather` 와의 관계

- **경계**: 홈 조회는 일기 날씨를 **쓰지 않고**, 일기는 홈 날씨를 **읽지 않는다.** 일기의 날씨는 「일기를 기록한
  시각」의 값이라 서버가 한 번만 기록하고 유지한다(`DESIGN.md` 1055행). 홈은 언제나 「지금」이다.
- **공유하는 것**: BE 의 MET 클라이언트 · 캐시 · 한국어 번역표 · 코드 체계. 같은 시각 같은 격자면 두 값이 같다.
- **제안(선택)**: `DiaryResponse` 에 `weatherCondition`(§4.3 객체 · nullable)을 더해 일기에도 같은 그림을 쓸 수 있게
  한다. 이번 계획의 범위 밖이고 하위 호환(필드 추가)이다. 기존 `weather` 문자열은 그대로 둔다.
- FE 의 위치 조회만 공통으로 끌어낸다(§4.5).

  구현 전 최종 검토):
  제목 「오늘 날씨도 함께 볼까요?」 · 본문 「지금 있는 곳의 날씨를 홈에 붙여 둘게요. 위치는 날씨를 찾는 데만 쓰고
  저장하지 않아요.」 · 주 버튼 「위치 허용하기」 · 보조 「다음에」.
  ⚠ **「저장하지 않아요」 문장은 조건부다(CP-1)** — §4.8 의 PV-1 검증(서버 로그 · 캐시 · DB · 외부 전송)이 「좌표가 남지
  않는다」로 끝난 뒤에만 쓴다. 검증 결과 캐시 · 외부 전송이 남으면 「위치는 날씨를 찾는 데만 써요.」로 줄이고,
  처리방침 링크(`links.ts` `privacy`)에 맡긴다. 문안은 P4 PR 전에 이 표의 확정판으로 다시 승인받는다.
- **일기 날씨가 이미 물은 사람**: 권한이 `granted` 면 안내 없이 바로 날씨, `denied` 면 안내 없이 숨김. 안내는
  「아직 아무도 묻지 않은(undetermined)」 사람에게만 한 번이다.
- **거부 후 다시 묻지 않는다** — 홈은 OS 설정으로 보내는 길도 두지 않는다(오류 · 거부를 말하지 않는다 · HW-4).
  일기 쪽 요청(`diaryWeather.ts:14`)은 지금 동작을 유지한다 — 안드로이드에서 한 번 거부해도 일기가 다시 물을 수 있다.
- **HW-4 숨김 사유**: 권한 거부 · 위치 서비스 꺼짐 · 12초 시간 초과 · 좌표 이상 · 서버 4xx/5xx · 10초 시간 초과 ·
  형태 이상 · `unknown` 조건 · 그림 없음. **전부 같은 결과(스티커 없음)이고 문구가 없다.** 계측에만 사유를 남긴다(§5.6).
- **표시 상태를 비우는 규칙(HW-4)** — 이전 값을 남겨 두지 않는다:

  | 무엇이 일어났나                                                                                             | 표시                                                                                                                 | 이전 값                     |
  | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------- |
  | 새 조회 실패(위 사유 전부 — 시간 초과 · 4xx/5xx · 형태 · 그림 없음)                                         | **즉시 숨김**                                                                                                        | 버린다(TTL 안이어도)        |
  | 복귀 · 포커스 때 권한이 `granted` 가 아니다(설정에서 철회 · 「이번만 허용」 만료)                           | **조회 전에 즉시 숨김** · 안내도 다시 띄우지 않는다                                                                  | 버린다                      |
  | 복귀 · 포커스 때 위치 서비스가 꺼져 있다(`isLocationServiceEnabled()` → `false` · **TTL 안이어도** — MF-2A) | **조회 전에 즉시 숨김**                                                                                              | 버린다                      |
  | 조회 중 위치 서비스가 꺼졌다(`locateRounded()` → unavailable)                                               | 즉시 숨김                                                                                                            | 버린다                      |
  | 조회가 진행 중일 때 권한 철회 · 서비스 꺼짐 · 로그아웃 · 사용자 변경을 확인했다                             | 즉시 숨김 · `fetchGen` 을 올린다 — 그 조회가 **나중에 성공해도 버린다**(MF-2B)                                       | 버린다 · 늦은 응답도 버린다 |
  | TTL 이 지났다(권한 `granted` 확인 뒤)                                                                       | 다시 조회 — 진행 중(최대 위치 12초 + 서버 10초)에는 이전 스티커를 두고, **결과가 실패면 즉시 숨김** · 성공이면 새 값 | 결과로 바꾼다               |
  | 권한 `granted` · TTL 안                                                                                     | 이전 스티커 그대로(다시 묻지 않는다 · 깜빡이지 않는다)                                                               | 유지                        |

  즉 **이전 스티커가 남는 경우는 「권한을 방금 다시 읽어 `granted` 이고 위치 서비스도 켜져 있으며, 조회를 하지 않았거나 그
  조회가 아직 끝나지 않은」 때뿐**이다 — 실패한 조회 뒤에는 어떤 경우에도 남지 않는다.
  권한 · 위치 서비스 확인은 TTL 과 무관하게 **매 포커스 · 매 복귀 · 매 하루 전환** 한다(OS 설정 · 제어 센터에서 돌아오는 길은
  `onForeground` 가 잡는다 — `src/lib/appState.ts`). 철회 · 서비스 꺼짐 뒤 다시 켜고 돌아오면 TTL 이 남았어도 버린 값이므로
  새로 조회한다.

- **늦은 응답 버리기(MF-2B)**: 조회는 시작할 때의 `fetchGen` 을 들고 간다. 위 표에서 「버린다」 행이 일어나면 그 자리에서
  `fetchGen` 을 올리므로, 철회 · 서비스 꺼짐 **전에** 출발한 `locateRounded()` · `weatherApi` 가 **뒤에** 성공으로 돌아와도
  번호가 달라 스티커를 되살리지 못한다. 실패 응답도 같은 방식으로 버린다(이미 숨겨져 있다 · 계측 사유만 남기지 않는다).
  무효화된 조회가 아직 끝나지 않았어도 다음 포커스의 새 조회를 막지 않는다(중복 방지는 **같은 세대** 안에서만).

### 4.7 권한 문구 · 네이티브 빌드 · 개인정보(PV-1)

- `app.config.ts:239` 문구를 홈까지 포괄하게(CP-1 채택 · 구현 전 최종 검토): 「**홈과 일기에** 지금 있는 곳의 날씨를

  통과하지 못하면 첫 문장만 쓴다. 목적(홈 · 일기 날씨)은 **반드시** 적는다(심사 반려 사유).

## 5. 알림함 FE/BE 계약(제안)

### 5.1 무엇이 알림함 항목이 되나(NB-1)

- **서버가 만든 항목만** — `NOTICE`(공지) · `NEWS`(운영 소식). 운영자가 관리 도구 또는 DB 로 발행한다(관리 화면은 이
  계획의 범위 밖 · 문의하기 선례처럼 DB 로 시작 가능).
- 로컬 회고 · 낮 기록 알림은 **알림함에 넣지 않는다**(서버는 로컬 알림을 모르고, 기기에서 기록을 만들면 「기기마다 다른
  알림함」이 된다). `reminders.ts` · `notifications.ts` 는 바뀌지 않는다.
- `type` 은 **열린 문자열**이다. FE 는 아는 값(`NOTICE` · `NEWS` · `CRITICAL_NOTICE`)만 이름표를 달고, 모르는 값도
  제목 · 본문으로 그린다(앱 업데이트 없이 새 유형을 보낼 수 있다). 리포트 소식 등 새 유형은 UX A-3 과 함께 따로 정한다.
- **보이는 범위 · 보존(NB-3)** — 판정은 **전부 서버**가 하고 FE 는 받은 목록을 그린다:

  | 유형                           | 누구에게                                        | 언제까지                                                 | 가입 전 발행분                         |
  | ------------------------------ | ----------------------------------------------- | -------------------------------------------------------- | -------------------------------------- |
  | `NOTICE` · `NEWS`(일반)        | `published_at ≥ 가입 시각` 인 항목만            | 발행 후 **90일** 지나면 목록에서 숨김                    | 보이지 않는다                          |
  | `CRITICAL_NOTICE`(서비스 필수) | 서버가 정한 노출 대상(`audience` — 전체 · 조건) | 서버가 정한 **`expires_at` 까지**(필수 · 90일 규칙 없음) | 보이되 **기본 읽음**(점을 켜지 않는다) |
  - 목록에서 숨긴 항목은 `hasUnread` 판정에서도 빠진다 — 보이지 않는 항목 때문에 점이 켜지지 않는다.
  - 「기본 읽음」은 읽음 행을 미리 쓰지 않고 **조회 때 파생**한다(`published_at < 가입 시각` 이면 읽음으로 간주 ·
    응답의 `readAt` 은 가입 시각). 신규 가입자의 첫 홈에 점이 뜨지 않는다.
  - 가입 **후** 발행된 `CRITICAL_NOTICE` 는 일반 항목처럼 읽지 않음으로 시작한다.
  - 90일 · `expires_at` 은 **목록 숨김**이다. 행을 지우는 보존 기간은 BE 운영 정책으로 따로 정하고 `docs/api/README.md` 에 적는다.

- 설정 store 의 `news`(「새로운 소식」 스위치 · 꺼짐)는 **푸시를 위한 자리**로 그대로 둔다 — 알림함은 이 스위치와 무관하게
  보인다(푸시가 생기면 그때 함께 정한다).

### 5.2 엔드포인트

| 메서드 · 경로                           | 요청                                | 응답                                                                                 |
| --------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `GET /api/v1/notifications`             | `?cursor=<opaque>&size=20`(최대 50) | `200 { items: Notification[], nextCursor: string \| null }` — 최신순                 |

| `POST /api/v1/notifications/read`       | `{ "ids": ["<id>", …] }`(1~50개)    | `204` · **적힌 ID 만** 읽음 · 멱등 · 이 사용자에게 보이지 않는 ID 는 조용히 건너뛴다 |

⚠ **「모두 읽음」(`read-all` · 시각 경계 `until`)은 두지 않는다(MF-1A)**. 시각 경계로 읽음을 정하면 ① 첫 쪽(20개)만 받고도
그 시각 이하의 **받지 않은** 오래된 항목까지 읽음이 되고, ② 같은 `createdAt` 에 발행된 새 공지가 경계 안에 들어간다.
읽음의 단위는 **FE 가 실제로 화면에 보인 항목의 `id`** 뿐이다 — 시각 · 커서 · 「여기까지」 같은 범위 표현을 계약에 두지 않는다.
50개를 넘으면 FE 가 나눠 보낸다.

`Notification`:

| 필드        | 타입                   | 규칙                                                                                                |
| ----------- | ---------------------- | --------------------------------------------------------------------------------------------------- |
| `id`        | `string`(int64 문자열) |                                                                                                     |
| `type`      | `string`               | 열린 enum — `NOTICE` · `NEWS` · `CRITICAL_NOTICE` · …                                               |
| `title`     | `string`               | 1~40자 · 평문                                                                                       |
| `body`      | `string`               | 0~500자 · **평문**(HTML · 마크다운 없음)                                                            |
| `createdAt` | ISO 8601               | 발행 시각                                                                                           |
| `readAt`    | ISO 8601 \| `null`     | 이 사용자가 읽은(또는 읽음으로 간주된 — 가입 전 `CRITICAL_NOTICE` 는 가입 시각) 시각                |
| `link`      | `string` \| `null`     | **앱 내부 경로만**(`/` 로 시작). FE 허용 목록에 없으면 누를 수 없는 항목으로 그린다 · 외부 URL 금지 |

오류: `401`(공통) · `404 NOTIFICATION_NOT_FOUND`(읽음 처리 대상이 없거나 남의 것) · `400 INVALID_CURSOR`.
FE 시간 초과는 공통 기본값.

**BE 저장 모델(제안)**: `notifications(id, type, title, body, link, audience = ALL | USER | <조건>, user_id null, published_at,
expires_at)` + `notification_reads(user_id, notification_id, read_at)`. `CRITICAL_NOTICE` 는 `expires_at` 필수 ·
일반 유형은 `expires_at` 이 없으면 `published_at + 90일`. 보이는 범위 · 기본 읽음 규칙은 §5.1(NB-3).
**탈퇴 시** 그 사용자의 `notification_reads` 와 `audience = USER` 항목을 지운다(`DELETE /users/me` 와 같은 트랜잭션).
알림 본문에 사용자 개인 정보를 넣지 않는다.

않으며, 다음 **성공한** 서버 응답이 바로잡는다(복구). 「실패하면 끈다」는 쓰지 않는다 — 읽음 처리가 실패해 서버에 미확인이
남았는데 점만 꺼지는 어긋남이 생긴다.

### 5.4 알림 모달(NB-2)

- **화면이 아니다** — 홈 `overlay` 슬롯에 그린다(라우트 · 스택 없음 · 뒤로가기 = 닫기).
- **자리**: 종 아래에 붙는 카드(폭 = 화면 − 32 · 최대 360 · 최대 높이 = 화면의 60%). 바깥(투명 딤)을 누르면 닫힌다 —
  글로벌 `Menu` 의 「바깥 탭 닫힘 · 앵커 아래 배치」와 같은 방식이고, 위치 계산은 `menuTopFromPageY` 를 재사용한다.
- **머리**: 「알림」 + 오른쪽 **설정 아이콘**(`IconButton` · 접근성 「알림 설정」) → 모달을 닫고 `ReminderSheet` 를 연다.
- **목록**: 내부 `FlatList`(많으면 안에서 스크롤 · 끝에 닿으면 `loadMore` · 보인 항목을 아래 「본 것」 규칙으로 모은다). 항목 = 제목(읽지 않음이면 점 + 굵게) ·
  본문 두 줄 말줄임 · 날짜(「10월 15일」). `link` 가 있으면 누르면 `markRead` → 닫기 → 이동. 없으면 눌러 펼쳐 본문 전체.
- **빈 알림함**: 「아직 도착한 소식이 없어요」 한 줄. **조회 실패**: 「알림을 불러오지 못했어요」 한 줄 —
  재시도 버튼 · 경고 아이콘 없음(규칙 4). 불러오는 중: `Spinner`. 둘 다 CP-1 채택 문안(짧고 차분하게 · 구현 전 최종 검토).
- **읽음 처리 — 점은 서버가 마지막으로 확인한 값만 따른다(NB-1 · NB-3 · 옵티미스틱 없음 · MF-1B)**. `hasUnread` 를 바꾸는 것은
  **성공한 서버 응답 둘뿐**이다 — ① `GET /unread` 의 값(참 · 거짓 모두), ② 목록 응답에 `readAt == null` 항목이 하나라도
  있으면 `true`(목록은 「미확인이 있다」만 확인할 수 있다 — 첫 쪽에 없다고 전체에 없다는 뜻이 아니므로 `false` 로는 쓰지
  않는다). 화면 동작(모달 열기 · 닫기)과 **실패 응답은 점을 바꾸지 않는다.**
- **무엇을 「본」 것으로 치나(MF-1A)**: 모달 목록은 `FlatList` 로 그리고 `onViewableItemsChanged`(항목 면적 50% 이상 · 0.5초
  이상 보임)로 **실제로 화면에 나타난 항목**만 `seenIds` 에 모은다. 받기만 하고 스크롤해 내려가지 않은 항목(예: 첫 쪽 20개 중
  모달 높이 밖 · 다음 쪽 10개)은 들지 않는다. 읽음으로 보내는 것은 `seenIds` 중 목록 응답에서 `readAt == null` 이던 것뿐이다.
  시각 경계를 쓰지 않으므로 같은 `createdAt` 에 발행된 다른 공지가 섞이지 않는다.

  | 사건                                                   | 하는 일                                                                                                                         | 점(`hasUnread`)                                                        |
  | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
  | 모달을 연다                                            | 목록 첫 쪽 조회                                                                                                                 | **그대로**(서버가 답할 때까지 바꾸지 않는다)                           |
  | 목록 조회 성공                                         | 받은 대로 그린다 · 보이는 항목을 `seenIds` 에 모으기 시작                                                                       | 미확인 항목이 있으면 `true`, 없으면 **그대로**                         |
  | 목록 조회 실패                                         | 실패 한 줄 · 읽음을 보내지 않는다(본 것이 없다)                                                                                 | 그대로                                                                 |
  | 모달을 닫는다(바깥 · 설정 아이콘 · 뒤로 · `link` 이동) | `seenIds` 중 미확인이던 것이 있으면 `POST /read{ids}`(50개씩) · 없으면 바로 `refreshUnread()`                                   | 그대로(응답을 기다린다)                                                |
  | `POST /read` 성공(204)                                 | 곧바로 `refreshUnread()`                                                                                                        | 그 응답 값 — 보지 않은 미확인 · 연 뒤 도착한 공지가 있으면 **켜진 채** |
  | `POST /read` 실패 · 시간 초과                          | 다시 보내지 않는다(조용히 · 규칙 4) · 서버에는 여전히 미확인이다 · 그래도 `refreshUnread()` 는 한 번 묻는다                     | 그 응답 값(성공 시) · 그것도 실패면 **그대로**                         |
  | 항목을 누른다(`link` 이동 · 펼침)                      | `PATCH /{id}/read` → 성공하면 `refreshUnread()`                                                                                 | 그 응답 값                                                             |
  | 홈 포커스 · 포그라운드 복귀                            | `refreshUnread()`                                                                                                               | 그 응답 값 — 새 공지가 도착했으면 켜진다                               |
  | `refreshUnread()` 실패                                 | —                                                                                                                               | **그대로**(마지막 확인 값 유지 · `null` 이면 점 없음)                  |
  | 로그아웃 · 탈퇴 · 사용자 변경                          | `reset()` — `sessionGen` 을 올리고 `items` · `seenIds` · `nextCursor` 를 비운다 · **닫힘에 따른 `POST /read` 도 보내지 않는다** | `null`(점 없음)                                                        |
  | `reset()` 전에 출발한 요청의 응답이 그 뒤에 도착       | **성공이어도 버린다** — 목록 · `hasUnread` · `seenIds` 어디에도 반영하지 않고, 이어지는 `refreshUnread()` 도 부르지 않는다      | 현재 세션의 `hasUnread` 를 변경하지 않음                               |

  **연속 실패 · 복구 예시(MF-1B)**:
  - 앞서 `GET /unread` 가 `true` 였다 → 복귀 때 조회 실패 → 모달을 열어 목록 성공 · 다 보고 닫음 → `POST /read` 실패 →
    `GET /unread` 실패: 점은 **켜진 채**다(마지막 확인 값 `true` · 서버에도 미확인이 남아 있다). 다음 복귀에서 `GET /unread`
    성공 → 그 값으로 복구된다.
  - 로그인 직후 `GET /unread` 가 실패해 `null`(점 없음)인데 서버에는 미확인이 있다 → 모달을 열어 목록이 성공하면 미확인
    항목이 보이므로 `true` 로 켜진다 → 이어서 읽음 · 재조회가 실패하면 **켜진 채** 남는다(서버 상태와 같다).
  - 점이 `null` 이라 꺼져 있는 동안은 「모른다」이지 「없다」가 아니다 — 이 상태를 오래 두지 않도록 포커스 · 복귀마다 다시 묻는다
    (폴링은 하지 않는다).
  - **늦게 온 응답이 이기지 않게**: `refreshUnread` · 목록 조회 · `POST /read` · `PATCH` 는 하나의 세대 번호를 공유한다.
    `hasUnread` 는 **마지막으로 반영한 응답보다 나중에 시작한** 요청의 성공 응답만 바꾼다(예: `POST /read` 전에 출발한
    `GET /unread` 가 `true` 로 늦게 와 점을 되살리지 않게 · 읽음 뒤 재조회의 `false` 를 앞선 목록의 `true` 가 덮지 않게).
  - **사용자가 바뀐 뒤 도착한 응답(MF-N1)**: 위 세대 번호는 한 세션 안의 순서만 다룬다. 그 위에 **세션 세대 `sessionGen`** 을
    따로 둔다 — 네 요청은 출발할 때 `sessionGen` 과 그때의 `userId` 를 함께 받고, `reset()`(로그아웃 · 탈퇴 · 다른 사용자로
    로그인)이 `sessionGen` 을 올린다. 응답은 **받은 `sessionGen` 이 지금 값과 같고 `userId` 가 지금 사용자와 같을 때만** 반영한다 —
    다르면 성공이어도 버리고(목록 · 다음 쪽 · `hasUnread` · `seenIds` 모두), 그 응답에 이어지는 후속 호출(`POST /read` 뒤
    `refreshUnread()` 등)도 하지 않는다. 그래서 사용자 A 의 조회가 진행 중일 때 로그아웃하고 B 로 들어와도 A 의 항목이 B 의
    모달에 끼거나 A 의 `true` 가 B 의 점을 켜지 않는다. `useHomeWeather` 의 `fetchGen`(§4.6)과 같은 원칙이다.
  - 모달이 열린 채 `reset()` 이 오면 모달을 닫되 **읽음을 보내지 않는다**(본 것은 이전 사용자의 것이고, 토큰도 이미 폐기됐다).
  - 이번에 연 동안에는 목록 응답의 `readAt == null` 항목에 「읽지 않음」 표시를 남겨 무엇이 새것인지 보이게 하고, 다음에 열 때
    받은 목록대로 그린다 — 보지 않고 닫은 항목은 다음에도 「읽지 않음」으로 남는다.
  - 모달을 연 뒤 도착한 공지는 목록에 없으므로 `seenIds` 에 들 수 없다 — 서버가 미확인으로 남기고, 닫은 뒤의 `refreshUnread()` 가 점을 켠다.

- **종**: 접근성 이름 「알림」 / 「알림, 읽지 않은 소식 있음」(CP-1 — 읽지 않음 상태를 이름에 반영) · 점은 숫자가 없다 · OS 배지를 올리지 않는다(`shouldSetBadge: false` 유지).
- **마이 경로 유지**: 마이의 「알림」 줄 → 같은 `ReminderSheet`. `my.tsx` 는 추출한 시트를 쓰도록만 바뀐다.
