## 1. 기준이 되는 가치와 원칙

모멘토리의 중심 고리는 **회고 → 자기 이해 → 작은 행동 변화**다.

```
          ┌────────────── 하루 고리 (매일) ───────────────┐
  오늘 ──▶ 회고(돌아보기) ──▶ 이해(일기·감정·바람) ──▶ 작은 행동(선택)
   ▲                                                       │
   └──────── 다음 날부터 사흘 · 다시 만나기 · 실천 · 느낀 점 ◀──┘
                         │
          한 주 = 고리의 흔적을 평가 없이 비춰 보기
          하루 기록 = 하루들의 원본

  쉼터 = 고리 밖에서 「지금 나를 돌보는 곳」 — 회고 없이도 언제든 · 회고 마무리에서 조건부로 하나를 권한다
```

설계 원칙(리디자인 착수 시 합의):

1. 일기 작성 자체보다 **회고 이후의 행동 변화**가 중요하다.
2. 기록에 대한 부담을 줄인다.
3. 감정 · 행동을 평가하거나 점수화하지 않는다(진행률 · 연속 일수 · 점수 · 배지 금지 — `RULES.md`).
4. 따뜻하고 잔잔한 분위기를 지향한다.
5. 기존 기능을 무조건 유지하지 않고 필요성을 검토한다.
6. 서버/API 변경이 필요한 제안은 따로 표시한다.

       │                     마무리 ├ 자세히 보기 ─▶ 방금 만든 카드 ─▶ 마무리

       │                            ├ 지원 정보 다시 보기(이 회고에서 위기 안내 · 주) ─▶ 지원 정보
       │                            └ 오늘로 돌아가기 ─▶ 오늘
       ├ 이번 주 감정(기록이 있는 주만) ─▶ 기록 › 한 주(이번 주)
       ├ 오늘 일정 ─▶ 일정 추가 · 수정(시트)
       ├ 지난 한 주 카드(조건부) ─▶ 기록 › 한 주(그 주)

### 4.1 오늘 (U-5)

**U-5 — 오늘은 상태별 우선순위로 구성한다.**

| 순서 | 영역                     | 조건 · 상태                                                                                                            |
| ---- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| —    | 날짜 + 종 아이콘         | 언제나(🟢 · 종 아이콘의 목적지만 🟡 §4.4)                                                                              |
| 1    | **작은 행동 영역**       | §7.2 의 카드가 있으면 **맨 앞**. 실천을 기록한 날에는 **같은 자리에 축소 완료 카드**(Q-2). 「나중에」 날에는 없다(Q-1) |
| 2    | **회고 영역**            | 작은 행동 영역이 없으면 **맨 앞**. 회고 전 = 회고 진입 · 회고 후 = 「오늘을 돌아봤어요」 + 오늘의 하루 상세로 가는 길  |
| 3    | 이번 주 감정             | 🟡 **핵심 영역(1 · 2) 뒤의 간결한 미리보기**(A-1). 이번 주 기록이 없으면 **숨긴다**. 누르면 기록 › 한 주(이번 주)      |
| 4    | 오늘 일정                | 🟢 추가 · 수정 · 완료 · 순서 · 캘린더 일정 숨김 그대로                                                                 |
| 5    | **지난 한 주 진입 카드** | 일정 **다음**에, U-4 조건일 때만(§6.2)                                                                                 |

- 회고 후 상태가 생겨 「이미 마쳤어요」 대화로 들어가는 막다른 길이 오늘에서 사라진다. 서버의 하루 한 번 가드(409)는 그대로다.
- **버튼 위계(A-2)** — 작은 행동 영역이 회고 영역보다 **먼저 놓여도 주 CTA 는 「하루 돌아보기」**(회고 진입)다. 「해봤어요」는 **보조 버튼**이다. `DESIGN.md` 「Solid Primary CTA 는 화면당 1개」와 함께 선다.
- 이번 주 감정 미리보기는 현 홈의 감정 줄과 같은 데이터(`features/report/model/report.ts` 의 이번 주 감정 줄 계산)를 쓴다 — 미리보기의 모양 · 「기록 없음」 판정의 입력은 상세 설계에서 정한다.

### 4.2 쉼터 (D8)

- 쉼 콘텐츠 넷과 공통 규칙(설명 카드 · 기분 쪽지 · 이용 기록 · 지난 보물)은 🟢 그대로다.
- 일기를 쓴 날의 쉼 추천 시트(차이 #44)는 🟢 남는다. 마무리 화면에서의 선택이 그날 시트를 억제하는 조건은 §7.3.
- 「세 번 연달아 닫음」 억제는 🟢 그대로다(현재 동작은 V-5).
- 🟡 [배치] 허브 맨 위의 바람카드 진입 카드가 빠진다.

### 4.3 기록 (D3 · U-6 · U-8)

| 보기      | 담는 것                                                                                     | 출처                             |
| --------- | ------------------------------------------------------------------------------------------- | -------------------------------- |
| **하루**  | 달력(감정 스티커 · 일정 점 · 고른 날의 일기 · 일정) / 목록(검색 · 감정 필터 · 기간)         | 현 보관함 A1 · A2 🟢 [배치]      |
| **바람**  | 바람카드 전부 — 행동이 없는 카드 포함. 기한 없이 조회 · 실천 기록(U-2 · Q-6 의 범위 안에서) | 현 쉼터 › 바람카드(R2) 🟡 [배치] |
| **한 주** | 주간 리포트 + 과거 주 선택                                                                  | 현 리포트 탭(W1) 🟡 [배치] · §6  |

**U-8 — 기록 탭의 기본 보기.**

- 기록 탭에 **처음** 들어가면 **하루**를 보여 준다.
- 세션 중에는 **마지막 보기**를 유지한다(U-7 과 같은 세션 범위).
- **딥링크 · 명시적 화면 이동의 목적지가 우선한다** — 예: 지난 한 주 카드 → 한 주(그 주) · 오늘의 이번 주 감정 → 한 주(이번 주) · 한 주의 「기록 보기」 → 하루(그 주) · 회고 알림 → 하루 상세.
- **A-10** — 기록 탭으로의 **일반 이동**(탭 선택 · 딥링크 · 위의 명시적 이동)은 **마지막 탐색 상태를 갱신**한다 — 그렇게 열린 보기가 그 뒤의 「마지막 보기」다.
- **예외** — 회고 마무리의 「자세히 보기」(Q-8)로 바람카드를 **임시로** 확인할 때는 **기존 탐색 상태를 보존**하고 마무리 화면으로 돌아간다(§7.3).

**하루 상세**(현 일기 상세 A3)는 기록 아래에 둔다. 담는 것: 일기 · 그날의 바람카드 · 그날 일정.

- 🟡 [기능] 그날 일정은 **그날 날짜로** 조회한다(현재는 오늘 일정 store 만 참조해 과거 일기에서 빠질 수 있다 · 기존 `GET /api/v1/schedules?date=`).

**U-6 — 하루 상세에서도 작은 행동의 실천 기록을 지원한다.** 🟡 [기능]

- 그날의 카드에 **작은 행동이 있으면**(Q-6) 「해봤어요」 · 느낀 점(선택)을 기록할 수 있다.
- **완료 취소와 수정은 명시적 메뉴**(⋮ 등)로만 제공한다 — 카드 면을 누르는 것으로 되돌려지지 않는다(차이 #23 이 걱정한 오해를 이 방식으로 막는다).
- **A-5 — 수정 대상은 실천 여부와 느낀 점뿐**이다. 바람과 작은 행동 문구는 **읽기 전용**이다(문장 수정 API 가 없다 · N-4 는 범위 밖).
- 완료 취소 때 이미 쓴 **느낀 점을 보존할지**는 **API 동작을 검증한 뒤 처리한다**(V-4).
- **오늘 · 기록 › 바람 · 하루 상세의 상태를 동기화**한다 — 한 곳에서 바꾸면 나머지가 같은 값을 그린다(V-4).

### 4.4 마이

🟢 현행 그대로(`SCREEN_INVENTORY.md` §4.9). 기본 정보 편집(닉네임 · 나이 · 성별 · 관심 분야 · 쉬는 방법)도 그대로다 — U-11 은 **초기 입력**만 말한다.
🟡 [기능] 오늘의 종 아이콘이 마이로만 가던 것을 **알림 설정 시트를 바로 여는** 것으로 바꾼다(접근성 이름 「알림 설정」과 결과를 맞춘다).

### 4.5 회고 (U-10)

**U-10 — 별도 회고 일정 확인 화면(C2)을 없애고, 회고 대화 시작 부분에 일정 요약을 통합한다.**

| 항목             | 내용                                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 화면             | 🔴 `C2`(`/retro/confirm`) 제거 → 회고는 **대화 화면에서 바로** 시작한다                                                       |
| 일정 요약        | 대화 시작 부분에 오늘 일정 **최대 3개 미리보기 + 펼쳐보기**. 읽기 전용                                                        |
| 일정이 없을 때   | **회고를 그대로 시작할 수 있다.** 요약 자리의 표현은 상세 설계                                                                |
| 서버로 가는 것   | 🟢 그대로 — 대화가 시작될 때 지금처럼 오늘 일정(숨긴 일정 제외 · id · 완료 여부)을 `POST /api/v1/retrospect` 에 싣는다        |
| 오늘 이미 회고함 | 🟢 대화 화면의 기존 처리(「회고는 하루에 한 번이에요」 · 서버 409)가 맡는다. 오늘의 회고 후 상태에서는 진입 자체가 없다(§4.1) |

- 구현 사실: 일정은 C2 가 아니라 **대화 화면이** `useDay` 에서 직접 조립해 보낸다(`app/retro/confirm.tsx` 머리말 · `app/retro/talk.tsx`). C2 를 지나든 말든 서버로 가는 값은 같다.
- 대화 흐름(일기 작성 → 분기점 「감정을 더 알아볼래요」/「일기 확인하러 갈래요」 → 감정 탐색) · 일기 확인은 🟢 그대로다(U-1).
- 저장 뒤는 언제나 공통 마무리 화면이다(U-3 · §7.3).
- 일정이 아직 store 에 없을 때(콜드 스타트 · 알림 진입 · 온보딩 직후) 세션을 언제 시작할지 → **V-2**.

### 4.6 온보딩 (U-11 · U-12)

**U-11 — 온보딩을 6단계로 줄인다.**

```
현재  환영 → 닉네임 → 나이 → 성별 → 관심 분야 → 쉬는 방법 → 회고 시간 → 캘린더 → 완료   (9)
U-11  환영 → 닉네임 ───────────────────────────▶ 쉬는 방법 → 회고 알림 시간 → 캘린더 → 완료   (6)
```

- 🔴 나이 · 성별 · 관심 분야 화면을 **초기 입력에서 제외**한다. 마이의 기본 정보 편집은 그대로다(§4.4).
- 쉬는 방법은 남는다 — 쉼 추천이 쓴다(`features/rest/model/recommend.ts`).
- ⚠ **서버 필수 필드 여부와 선택값 생략 가능 여부는 구현 전 확인한다**(V-1). 반입 스냅샷의 `CompleteOnboardingRequest` 는 `gender` · `interestAreas` 를 **required** 로 적고 있다 — 생략이 되는지는 **미확인**이다.

**U-12 — 온보딩 완료 화면에서 「지금 하루 돌아보기」와 「먼저 둘러보기」를 제공한다.** 🟡 [기능]

| 선택                   | 이동                                                                         |
| ---------------------- | ---------------------------------------------------------------------------- |
| 「지금 하루 돌아보기」 | 온보딩 저장(`PUT /api/v1/users/me/onboarding`) 성공 → 회고(대화 화면 · U-10) |
| 「먼저 둘러보기」      | 온보딩 저장 성공 → 오늘(회고 전 상태)                                        |

- **자동으로 회고를 시작하지 않는다.** 완료 화면을 **별도 단계로 추가하지 않는다** — 지금의 완료 화면(`10` · `10-b`)이 두 선택지를 갖는다.
- 첫 회고를 미뤘다는 이유로 **추가 압박을 주지 않는다** — 오늘의 회고 전 상태가 평소와 같고, 따로 상기시키는 장치를 두지 않는다.
- 저장 실패는 지금처럼 버튼 아래 한 줄 · 같은 버튼으로 다시 시도한다(🟢).

### 4.7 탭 탐색 상태 (U-7)

**U-7 — 탭 이동 후 탐색 상태를 세션 동안 유지한다.**

| 항목          | 내용                                                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 유지하는 것   | 탭 안의 **탐색 상태** — 예: 기록의 보기(U-8) · 고른 달 · 고른 날 · 목록의 검색어 · 감정 필터 · 기간 · 고른 주                  |
| 유지하는 기간 | 앱 프로세스가 살아 있는 **세션 동안**                                                                                          |
| 초기화        | **앱 프로세스 재시작** · **로그아웃** 때 임시 상태를 지운다. 로그아웃 때는 **사용자 데이터의 메모리 캐시**도 함께 지운다(A-11) |
| 데이터        | 상태는 유지하되 **데이터 변경은 최신으로 반영**한다 — 다른 탭에서 바꾼 실천 상태 · 지운 일기 등이 돌아왔을 때 보인다           |

**A-11 — 기기에 남는 사용자 상태.** 세션을 넘어 기기에 남는 상태는 **사용자별로 격리**하고 **필요한 기간만** 보관한다.

| 상태                           | 정책                    | 필요한 기간                                 |
| ------------------------------ | ----------------------- | ------------------------------------------- |
| 작은 행동 「나중에」 당일 숨김 | U-2 규칙 4 · Q-1 (§7.2) | 그 앱 날짜(다음 04:00 까지)                 |
| 지난 한 주 카드 숨김 · 열람    | U-4 (§6.2)              | 그 주의 노출 기간(다음 일요일 04:00 전까지) |
| 개인화 쉼 추천 당일 제한       | A-9 (§7.3)              | 그 앱 날짜 — 제한 여부와 만료 정보만        |

- 다른 사용자가 같은 기기로 로그인해도 앞 사용자의 숨김 · 제한이 적용되지 않는다.
- 로그아웃 때 지우는 것은 **탭 탐색 상태**와 **사용자 데이터 메모리 캐시**다(U-7 표의 「초기화」). 위 표의 기기 상태는 사용자별로 격리돼 있으므로 로그아웃이 아니라 **기간이 끝날 때** 지운다.
- 쉼 추천 억제(Q-5)의 **기존 해제 조건은 그대로**다(V-5).
- 키에 사용자를 넣는 법 · 탈퇴 때 처리 → **V-10**.

- 구현 사실: 탭은 지금 expo-router `Tabs` 가 아니라 `Stack` + `router.replace` 라 탭을 떠나면 화면이 매번 새로 마운트된다(`app/(tabs)/_layout.tsx` · `SCREEN_INVENTORY.md` §9) → **V-8**.
- 구현 사실: 일기 · 바람카드는 탭 진입 때 한 번 받아 세션 동안 재사용한다 — 「최신 반영」과의 관계 → **V-4**.

## 5. 핵심 사용자 흐름

`(A-n)` 은 그 단계에 적용된 결정(§11), `(V-n)` 은 그 단계에 걸린 **열린** 기술 검증(§12)이다.

### 5.1 첫 이용자

**Day 0 — 설치한 날**

1. 스플래시 → 로그인 → 온보딩 6단계(환영 → 닉네임 → 쉬는 방법 → 회고 알림 시간 → 캘린더 → 완료) (V-1).
2. 완료 화면에서 고른다 — 「지금 하루 돌아보기」 → 3 / 「먼저 둘러보기」 → 오늘(회고 전 상태 · 압박 없음).
3. 회고: 대화 화면 맨 앞에 오늘 일정 요약(없어도 시작) → 대화 → 분기점 → (감정 탐색) → 일기 확인 → 저장 (V-2).
4. **공통 마무리 화면**(§7.3 · 저장 성공 뒤): 바람카드가 생겼으면 발견한 바람 · 작은 행동(있을 때) · 「자세히 보기」, 그리고 조건이 맞으면 쉼 추천.
5. 「잠깐 쉬어가기」 → 추천 쉼 → 쉼터 / 「오늘로 돌아가기」 → 오늘(회고 후 상태). 추천 억제 상태 · 위기 안내가 있던 회고는 선택지가 다르다(A-7 · A-8 · §7.3).

목표 — 첫날 회고 1회. 일정 입력도, 작은 행동도, 쉼도 강요하지 않는다.

**Day 1 ~ Day 3 — 다음 날 04:00 부터 사흘**

1. 작은 행동을 정했다면 오늘 **맨 앞**에 작은 행동 영역이 선다 — 대표 바람 한 줄 + 작은 행동(Q-7).
2. 「해봤어요」 → 그 자리에 축소 완료 카드 · 느낀 점(선택). 그날은 다른 카드가 올라오지 않는다(Q-2).
3. 지금은 아니면 「나중에」 → 그날 영역 전체가 숨고(Q-1) 회고 영역이 맨 앞이 된다.
4. Day 4 04:00 에 조용히 빠진다. 카드는 기록 › 바람 · 하루 상세에서 언제든 다룰 수 있다.

**한 주가 지난 뒤**

1. 일요일 04:00 — 지난주에 **답변이 저장된 회고가 하나라도** 있으면 오늘의 일정 아래에 **지난 한 주 카드**(U-4 · A-4).
2. 카드 → 기록 › 한 주(그 주): 관찰 문장 → 감정 → 바람 → 작은 행동 → 그 주의 기록으로(U-9).
3. 열어 보거나 숨기면 그 주에는 다시 나오지 않는다. 그렇지 않아도 **최대 7일** 뒤에 빠진다 — 반복 팝업 · 주간 푸시는 없다(A-3). 더 지난 주는 과거 주 선택으로(D7).

### 5.2 재방문자

| 상황                    | 흐름                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 평일 루틴               | 아침: 오늘 맨 앞의 작은 행동 → 일정 · 저녁: 알림 → 회고 → 마무리 → 쉬어가기 또는 오늘로                             |
| 며칠 쉬었다 돌아옴      | 오늘은 오늘만 보여 준다. 사흘이 지난 행동은 오늘에 없고, 밀린 날 수 · 쌓인 카드 수를 꺼내지 않는다                  |
| 작은 행동을 정하지 않음 | 마무리에 발견한 바람만(또는 그것도 없이). 오늘에는 회고 영역이 맨 앞. 카드는 기록 › 바람에(「해봤어요」 없음 · Q-6) |
| 쉼만 필요함             | 쉼터 → 쉼 하나 → 기분 쪽지 → 쉼터. 회고를 요구하지 않는다 🟢                                                        |
| 지난날 다시 보기        | 기록(처음엔 하루) → 달력 · 목록 → 하루 상세. 다른 탭에 다녀와도 보던 달 · 필터가 남아 있다(U-7)                     |
| 지난 행동 기록하기      | 기록 › 바람 또는 하루 상세 → 「해봤어요」 · 느낀 점. 취소 · 수정은 메뉴에서(U-6)                                    |
| 주간 돌아보기           | 오늘의 지난 한 주 카드(노출 중일 때) 또는 기록 › 한 주 → 과거 주 선택                                               |
| 회고 알림을 누름        | 오늘 일기가 없으면 회고(대화 화면) · 있으면 하루 상세                                                               |

## 6. 주간 리포트 (D2 · D4~D7 · U-4 · U-9)

### 6.1 배치

- **D2** 독립 탭 없음 — 기록 › 한 주. **D3** 하루 / 바람 / 한 주 전환. **D7** 주간 리포트 조회 · 과거 주 선택 유지.

**U-4**

| 항목          | 내용                                                                                                   |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| 대상          | **종료된 직전 주**(일 ~ 토 · 차이 #34)                                                                 |
| 조건          | **지난주 기록이 있는 경우**에만 — 기록의 범위는 아래 「A-4」                                           |
| 노출 기간     | **일요일 04:00 부터 다음 일요일 04:00 전까지**(하루 경계 04:00 KST) — **최대 7일**                     |
| 위치          | 오늘의 **일정 다음**(U-5)                                                                              |
| 사라지는 조건 | **열람 성공**(그 주 리포트가 실제로 그려짐) 또는 **수동 숨김** — 이후 **같은 주에는 다시 내지 않는다** |
| 알림 방식     | 오늘 안의 카드뿐이다. **반복 팝업 · 주간 푸시를 추가하지 않는다**(A-3)                                 |
| 상태 저장     | **로컬 · 계정별 · 주차별**. 서버에 두지 않는다 — 기기 간 동기화는 N-9 · 보관 기간은 A-11(§4.7)         |

| 상태      | 조건                                                    | 오늘에서                                 |
| --------- | ------------------------------------------------------- | ---------------------------------------- |
| 없음      | 노출 기간 밖 · 지난주 기록 없음 · 이미 열람 · 이미 숨김 | 그리지 않는다                            |
| 보임      | 위 조건이 아니고 노출 기간 안                           | 카드 + 숨기기                            |
| 열람 성공 | 그 주 리포트가 ready 로 표시됨                          | 이후 그 주 동안 없음                     |
| 열람 실패 | 리포트를 못 받음(한 줄 안내 · 기존 W1 처리)             | **열람으로 치지 않는다** — 카드가 남는다 |
| 숨김      | 사용자가 숨김                                           | 이후 그 주 동안 없음                     |

**A-3 — D4 와 U-4 의 관계.** D4 의 「매일 반복 노출하지 않는다」는 노출 제한을 **U-4 가 대체**한다. 열지도 숨기지도 않으면 노출 기간(최대 7일) 동안 오늘에 남고, 그 이상의 반복 장치는 없다. D4 의 나머지(지난 한 주로 가는 진입 카드 · 한 주가 마무리된 뒤에 낸다)는 그대로다.

**A-4 — 「지난주 기록 있음」의 기준.** 지난주(일 ~ 토 · 04:00 경계)에 **사용자 답변이 저장된 회고 기록이 1개 이상** 있을 때다.

| 포함                             | 제외                                     |
| -------------------------------- | ---------------------------------------- |
| 완료 회고(일기가 저장된 회고)    | 감정만 남긴 날                           |
| 부분 회고(답변이 저장된 채 중단) | 일정만 있는 경우 · 쉼터 활동만 있는 경우 |

- 부분 회고의 답변이 서버에 남는지 · 무엇으로 판정할지(필드 · 조회)는 **검증 전**이다 → **V-7**.
- 「계정별」 키와 로그아웃 처리 → **V-10**(정책은 A-11).

### 6.3 한 주의 구성 (U-9)

**U-9 — 관찰 문장 → 감정 → 바람 → 작은 행동 → 과거 기록 연결 순서다.** 점수 · 달성률 · 실천 압박 표현을 쓰지 않는다. 현재 API 가 주지 않는 분석이나 원문은 **임의로 만들지 않는다**.

| 순서 | 덩어리         | 현재 API 필드(`GET /api/v1/reports/weekly?date=` · 스냅샷 기준 · V-7)      | 지금 화면(W1)             |
| ---- | -------------- | -------------------------------------------------------------------------- | ------------------------- |
| 1    | 관찰 문장      | `moodMessage`                                                              | 한 주 요약 한 문장        |
| 2    | 감정           | `dailyMoods` · `dominantEmotion`                                           | 쌓이는 감정 일곱 칸       |
| 3    | 바람           | `needs`                                                                    | 바람카드 — 찾은 바람 알약 |
| 4    | 작은 행동      | `practicedWishes`(+ `actionCardCreatedCount` · `actionCardCompletedCount`) | 바람카드 — 실천한 것      |
| 5    | 과거 기록 연결 | `startDate` · `endDate` → 기록 › 하루(그 주)                               | 「기록 보기」             |

- 리포트 재구성에 **서버 변경은 필요하지 않다**(필드 기준 · V-7).
- **A-6 — 기존 통계는 관련 덩어리의 보조 정보로만 둔다.** U-9 순서에 없는 셈(`scheduleTotalCount` · `scheduleCompletedCount` · `diaryCount` · 현 「이번 주 기록」)과 카드 개수(`actionCardCreatedCount` · `actionCardCompletedCount`)는 독립 덩어리로 세우지 않고, 관련 영역 안에 보조로 붙인다 — (제안) 카드 개수는 바람 · 작은 행동, 일기 · 일정 셈은 과거 기록 연결.
  - **달성률과 성과 비교 표현을 쓰지 않는다**(비율 · 퍼센트 · 지난주 대비 등).
  - **실제 응답으로 확인할 수 없는 수치는 쓰지 않는다** — 앱이 지어내거나 다시 세지 않는다(V-7).
- 주 선택(과거 주)은 🟢 그대로(D7 · 차이 #33).

## 7. 바람카드와 회고 마무리 (U-1 · U-2 · U-3 · Q-1~Q-8)

### 7.0 바탕이 되는 구현 사실

| ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |

### 7.1 바람카드의 정체성 (U-1 · Q-6)

**U-1**

- 바람카드는 **사용자의 감정과 욕구를 이해하기 위한 기록**이다.
- 작은 행동은 **선택**이며 모든 회고에서 강제하지 않는다.
- 행동이 없는 카드는 **기록에서** 확인한다.
- 행동이 있는 카드만 오늘의 행동 영역에 노출할 수 있다(§7.2).
- 기존 회고 분기와 **「바람카드」 명칭을 유지**한다 — 회고 흐름 · 서버 계약 변경 없음(N-1 채택 안 함).

**Q-6 — 행동 없는 카드의 판정과 처리**

- `targetAction` 이 **비어 있거나 공백뿐이면** 행동 없는 카드로 취급한다.
- 행동 없는 카드에는 **「해봤어요」와 실천 완료 상태를 제공하지 않는다** — 오늘 · 기록 › 바람 · 하루 상세 모두.
- 🟡 [기능] 구현 사실: 지금 R2 는 행동 없는 카드에도 「했어요」를 둔다.

**A-12 — 이미 `done=true` 로 남은 행동 없는 카드.**

- 기존 데이터는 **바꾸지 않는다** — 앱이 `done` 을 되돌리거나 고쳐 쓰지 않는다.
- 목록 · 오늘 · 기록 › 바람에서 **일반 실천 완료 배지를 그리지 않는다.**
- 상세 화면에서만 **이전 완료 이력**과 **남아 있는 느낀 점**을 **읽기 전용**으로 보인다. 느낀 점이 없으면 그 자리를 두지 않는다.
- **새 실천 통계에서 뺀다.** 서버가 센 값(`actionCardCompletedCount` · `practicedWishes`)에 이 카드가 들어가는지는 검증 전이다 → **V-7**.

### 7.2 작은 행동 노출 (U-2 · Q-1 · Q-2 · Q-7)

**U-2**

| #   | 규칙                                               | 구현 의미                                                                                                                                        |
| --- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | 카드 생성일 **다음 날 04:00(KST)부터 3일간** 노출  | 카드 날짜 `d` 에 대해 오늘이 `d+1` · `d+2` · `d+3` 인 동안 = `d+1` 04:00 ~ `d+4` 04:00 직전. 생성한 날에는 뜨지 않는다                           |
| 2   | **가장 최근 미실천 행동 1개**만                    | 후보 가운데 카드 날짜가 가장 늦은 한 장                                                                                                          |
| 3   | 「해봤어요」는 기존 완료 API · 느낀 점은 선택      | `PUT …/completion {done: true}` → 느낀 점을 남기면 같은 API 로 `reflection`                                                                      |
| 4   | 「나중에」는 **당일 숨김** · 앱 재실행 후에도 유지 | 서버에 쓰지 않는다. 기기에 **사용자별로** 남기고 다음 04:00 에 풀린다(A-11 · 키는 V-10)                                                          |
| 5   | 기간이 지나면 오늘에서 자동으로 숨긴다             | `d+4` 04:00 에 후보에서 빠진다. 알림 · 표시 · 문구 없이                                                                                          |
| 6   | 기록에서는 기간 제한 없이 조회 · 실천 상태 변경    | 기록 › 바람 · 하루 상세(U-6). 행동 없는 카드 제외(Q-6)                                                                                           |
| 7   | 미실천 · 실패 · 기한 초과 등 **압박성 표현 금지**  | 남은 날 수 · 「D-n」 · 「놓쳤어요」 · 지난 행동 개수 등 **어떤 표시도 두지 않는다**. 이 문서의 「미실천」은 `done=false` 를 가리키는 내부 용어다 |

**노출 후보.** 카드 하나가 아래를 **모두** 만족하면 후보이고, 후보 가운데 카드 날짜가 가장 늦은 한 장이 「오늘의 카드」다.

1. 작은 행동이 있다(Q-6).
2. `done = false`.
3. 오늘(04:00 경계)이 카드 날짜 `+1 ~ +3` 안이다.
4. 지워지지 않았다.

**A-13 — 오늘의 카드가 완료 취소됐을 때.** 오늘 선택된 카드의 실천 완료가 (기록 › 바람 · 하루 상세에서) 취소되면 **같은 카드만** 미실천(「보임」)으로 되돌린다.

- **다른 카드로 교체하지 않는다** — 더 이전 후보가 있어도 그날의 카드는 그대로다(Q-2 와 같은 방향).
- 「나중에」 숨김과 **원래 노출 기간**이 먼저다 — 그날 「나중에」를 골랐거나 노출 기간이 지났으면 되돌려도 오늘에 그리지 않는다.
- **다음 앱 날짜**(04:00)에 적격 카드를 처음부터 다시 고른다.

**Q-1 — 「나중에」.** 「나중에」를 고르면 **그날 행동 영역 전체를 숨긴다.** 사흘 안의 더 이전 카드로 **자동 대체하지 않는다.**

**Q-2 — 「해봤어요」 뒤.** 저장에 **성공하면** 같은 자리에 **축소된 완료 카드를 그날 유지**한다. 같은 날 **추가 카드를 보여 주지 않는다**(더 이전 후보가 있어도). 느낀 점은 선택이고, 저장에 실패하면 **다시 시도할 수 있어야** 한다.

**Q-7 — 행동 카드의 내용.** 오늘의 행동 카드에는 **대표 바람 한 줄 + 작은 행동**을 함께 보이되 **행동을 시각적으로 우선**한다. 저장된 바람이 없으면 **행동만** 보이고 설명을 지어내지 않는다. 대표 바람의 필드(`needs` · `desiredState` · `sentiment` 라벨 중 무엇) → **V-3**.

**영역의 상태 (U-5 의 1번 자리)**

| 상태              | 언제                                                                    | 보이는 것                                                                        |
| ----------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 없음              | 후보 없음 · 그날 「나중에」(Q-1) · 카드 목록을 아직 못 받음 · 받기 실패 | **영역을 그리지 않는다**(빈 자리 안내 · 오류 문구 없음) — 회고 영역이 맨 앞(U-5) |
| 보임              | 오늘의 카드가 있다                                                      | 대표 바람 한 줄(있을 때) + 작은 행동 · 「해봤어요」 · 「나중에」                 |
| 저장 중           | 「해봤어요」를 누른 직후                                                | 중복 누름 방지. 성공 판정 방식(옵티미스틱 vs 응답 대기) → V-4                    |
| 축소 완료         | 「해봤어요」 저장 성공(Q-2)                                             | 같은 자리 · 축소 완료 카드 · 느낀 점 한 줄 입력(선택). **그날 내내 유지**        |
| 느낀 점 저장 실패 | 느낀 점 PUT 거부                                                        | 쓴 글을 지우지 않고 한 줄 안내 · **다시 시도 가능**(Q-2 · 방식은 §14 #10)        |
| 완료 저장 실패    | 「해봤어요」 PUT 거부                                                   | 「보임」으로 돌아가고 한 줄 안내(현 store 롤백과 같다)                           |

**예외 조건**

| 상황                                | 처리                                                                                                                          |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 자정 ~ 04:00 사이에 회고를 마침     | 카드 날짜는 **전날**(04:00 경계) → 몇 시간 뒤 04:00 에 노출이 시작된다. 경계 규칙과 일치하므로 그대로 둔다                    |
| 앱을 켜 둔 채 04:00 을 넘김         | 하루가 바뀐 순간(`lib/dayChange.ts`)에 다시 계산 — 「나중에」 · 축소 완료가 풀리고 기간이 끝난 카드가 빠진다                  |
| 기록에서 기간 안의 카드를 완료 취소 | 다시 후보가 된다. 그 카드가 오늘의 카드였다면 **같은 카드만** 「보임」으로 되돌린다(A-13)                                     |
| 기록에서 카드를 지움                | 후보 · 축소 완료 모두에서 빠진다                                                                                              |
| 일기만 지움                         | 카드는 남으므로(차이 #22) 후보로 남는다                                                                                       |
| 다른 기기에서 「해봤어요」          | 서버 값이 정본 — 다음 조회 때 반영(V-4). 「나중에」는 기기 로컬이라 다른 기기에서는 숨지 않는다                               |
| 「나중에」 기억을 못 읽음 · 못 남김 | (제안) 못 읽으면 영역을 띄우지 않는다(쉼 추천 기억의 「권하지 않는 쪽이 먼저」와 같은 원칙) · 못 남기면 그 세션 동안만 숨긴다 |
| 같은 기기에서 다른 사용자로 로그인  | 앞 사용자의 「나중에」가 적용되지 않는다(A-11)                                                                                |

### 7.3 회고 완료 경험 (U-3 · Q-3 · Q-4 · Q-5 · Q-8)

**U-3**

1. 모든 회고는 바람카드 생성 여부와 관계없이 **공통 마무리 화면**으로 연결한다.
2. 바람카드가 있으면 **바람카드 요약**(발견한 바람 · 작은 행동)을 조건부로 표시한다.
3. **쉼 추천은 조건부**로 함께 안내한다(아래 Q-4 · Q-5).
4. 사용자는 **「잠깐 쉬어가기」** 또는 **「오늘로 돌아가기」**를 고른다. 쉼 이용은 **강제하지 않는다.**
5. 쉼 추천을 골라 이동한 경우 기존 추천 팝업이 **중복 표시되지 않게** 한다.
6. 추천을 제공할 수 없는 상황도 처리한다.

**화면 구성**(위에서부터 · 시각 · 문안은 상세 설계)

| 자리            | 조건                                                                                | 내용                                                                                             |
| --------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 마무리 한마디   | 언제나(저장 뒤) — 위기 안내가 있던 회고는 **저장 성공 확인 전 완료 문구 금지**(A-8) | 오늘 회고를 마쳤다는 조용한 끝맺음                                                               |
| 바람카드 요약   | 바람카드가 생겼다                                                                   | 발견한 바람(`needs` · `desiredState` · `sentiment` 라벨) · 작은 행동(**행동이 있을 때만** · Q-6) |
| 「자세히 보기」 | 바람카드가 생겼다(Q-8)                                                              | 요약 안의 **보조 링크**. 카드가 없으면 링크도 없다                                               |
| 쉼 추천         | 개인화 추천을 낼 수 있다(아래 표)                                                   | 쉼 이름 · 고른 이유 한 줄 · 하는 일 · 걸리는 시간(현 추천 시트와 같은 재료 · `recommendRest`)    |
| 선택지          | 언제나                                                                              | 아래 「선택지와 이동」 표                                                                        |

추천 계산은 지금 쉼터 시트와 **같은 함수 · 같은 입력**이다(오늘 일기의 첫 감정 → 온보딩 「쉬는 방법」 → 그날로 정해지는 무작위). 그래서 마무리에서 권한 쉼과 같은 날 쉼터 시트가 권할 쉼은 같다.

**개인화 추천을 낼 수 있나**

| 상황                                                         | 개인화 추천 | 근거                                                                                    |
| ------------------------------------------------------------ | ----------- | --------------------------------------------------------------------------------------- |
| 평소(감정 · 쉬는 방법이 없어도)                              | **낸다**    | 지금 계산이 무작위로 하나를 고른다 — 「추천 불가」가 아니다                             |
| **이 회고에서** 실제 위기 대응 안내가 제공됐다               | **안 낸다** | **Q-4 · A-8** — 기존 지원 안내가 우선. 판정은 기존 신호만 쓴다(새 판정 로직 금지 · V-6) |
| 같은 앱 날짜의 **중단된 회고**에서 위기 안내가 실제 표시됐다 | **안 낸다** | **A-9** — 그 앱 날짜 동안 제한한다(아래)                                                |
| **추천 억제 상태**(쉼터 시트를 3회 연속 닫음)                | **안 낸다** | **Q-5 · A-7** — 대신 「쉼터 둘러보기」(보조). 억제 해제 조건은 기존 그대로(A-11 · V-5)  |
| 추천된 쉼을 열 수 없다(쉼이 빠지거나 바뀌는 미래)            | 안 낸다     | (제안) 「쉼터 둘러보기」로 대신한다                                                     |

**선택지와 이동**

| 마무리의 상태                    | 선택지                         | 이동                                           | 그날 쉼터 자동 추천(`recommendMemory`)                                                                     |
| -------------------------------- | ------------------------------ | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 개인화 추천 있음                 | 「잠깐 쉬어가기」              | **추천 쉼으로 곧장** → 끝나면 기분 쪽지 → 쉼터 | **이동 전에** 오늘을 `accepted` 로 매듭 — 쉼터에 돌아와도 시트가 뜨지 않는다(U-3 5)                        |
| 〃                               | 「오늘로 돌아가기」            | 오늘(회고 후 상태)                             | **Q-3** — 그날 자동 추천을 **억제**하고, 3회 연속 닫기 횟수에 **넣지 않는다**(현재 `skipped` 와 같은 결과) |
| 억제 상태(Q-5 · A-7)             | **주** 「오늘로 돌아가기」     | 오늘                                           | Q-3 과 같다                                                                                                |
| 〃                               | **보조** 「쉼터 둘러보기」     | 쉼터 허브                                      | **수락으로도 거절로도 남기지 않는다**(A-7) — 억제가 풀리지도 더 쌓이지도 않는다                            |
| 이 회고에서 위기 안내(Q-4 · A-8) | **주** 「지원 정보 다시 보기」 | 이 회고에서 제공된 지원 정보                   | 지금처럼 그날을 이미 매듭지어 둔다(`skipped` · `retro/talk`)                                               |
| 〃                               | **보조** 「오늘로 돌아가기」   | 오늘                                           | 〃                                                                                                         |

- **A-7** — 추천 억제 상태에서 「쉼터 둘러보기」는 「잠깐 쉬어가기」를 **대신한다**(셋째 선택지가 아니다). 개인화 쉼 추천은 마무리에서 **뺀다.** 자발적인 쉼터 방문은 추천 수락 · 거절로 **집계하지 않는다**(§10).
- **A-8** — **현재 회고에서** 실제 위기 대응 안내가 제공됐으면 「지원 정보 다시 보기」가 주 CTA, 「오늘로 돌아가기」가 보조 CTA 다. 개인화 쉼 추천은 없다. 쉼터 직접 이용은 **제한하지 않는다**(탭으로 언제든). **저장 성공을 확인하기 전에는 완료 문구를 표시하지 않는다.** 「지원 정보」는 새로 만들지 않고 이 회고의 `safety_hold` 국면에서 보인 기존 안내를 다시 보이는 것이다(구성은 상세 설계). 이 회고에서 안내가 나왔음을 무엇으로 아는지는 → **V-6**.
- **A-9** — 이어서 얘기하지 않고 **중단된 회고**에서 위기 안내가 실제 표시됐으면, 같은 앱 날짜에 다른 회고를 마쳐도 개인화 쉼 추천을 **그 앱 날짜 동안 제한**한다.
  - 기기에는 **당일 제한 여부와 만료 정보만** 최소한으로 남긴다 — 위기 안내가 있었다는 사실 자체는 남기지 않는다(A-11 · V-6).
  - 이전 안내 사실을 **다음 일반 회고에서 자동으로 다시 보이지 않는다.** 지원 정보 다시 보기(A-8)는 **안내가 나온 그 회고**의 마무리에만 있다.
- 마무리 화면은 회고 스택을 **대체**한다 — 뒤로 가도 일기 확인 · 대화로 돌아가지 않는다. (제안) 안드로이드 뒤로가기는 「오늘로 돌아가기」와 같게.
- 회고 결과는 메모리에만 있다(구현 사실). 마무리를 **완전히 떠날 때**(쉬어가기 · 둘러보기 · 오늘로) 비운다 — 「자세히 보기」로 잠깐 나갈 때는 비우지 않는다(Q-8).
- (제안) 회고 결과가 메모리에 없으면(앱이 회수된 뒤 복귀) 오늘로 보낸다.

**중복 표시 방지(U-3 5)의 실패 지점**

| 실패 지점                        | 처리(제안)                                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------------- |
| 기억에 쓰기 실패                 | 앱 메모리에도 「오늘은 마무리에서 매듭지었다」를 두어 이번 실행 동안은 시트를 막는다         |
| 쓰기 실패 + 앱 재실행            | 그날 쉼터에서 시트가 한 번 더 뜰 수 있다 — 지금 「못 남기면 한 번 더 묻는 것뿐」과 같은 수준 |
| 쓰기가 끝나기 전에 쉼터에 들어옴 | 매듭짓기를 기다린 뒤 이동한다(시트는 0.6초 뒤에 뜬다)                                        |

**Q-8 — 「자세히 보기」**

- 마무리의 바람카드 요약 안에 **보조 링크**로 둔다. 생성된 카드가 없으면 링크도 없다.
- **방금 생성한 카드의 상세 내용**으로 이동한다(회고 완료 응답의 `wishCardId`).
- 돌아오면 **가능한 한 마무리 화면으로 복귀**한다. **회고 세션을 다시 시작하지 않는다.**
- 이 임시 확인은 기록 탭의 **마지막 탐색 상태를 바꾸지 않는다**(A-10 · §4.3).
- 지금 카드 하나만 보여 주는 화면이 없다 — 어느 화면으로 갈지(기록 › 바람의 그 날짜 · 하루 상세 · 새 카드 상세) · 탭 밖 회고 스택에서의 복귀 경로 → **V-11**.
