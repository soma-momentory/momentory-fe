## 1. 요약

- 실제 라우트 화면은 **36개**다. `_layout.tsx`, 테스트, `+native-intent.ts`, 화면 내부 바텀시트·모달·메뉴는 화면 수에서 제외했다.
- 구성은 진입/인증 2, 온보딩 9, 홈 3, 회고 4, 일기 1, 쉼터 8, 보관함 1, 리포트 1, 마이 7이다.
- 핵심 탭은 **홈 · 쉼터 · 보관함 · 리포트 · 마이** 5개이며, Expo Router의 `Tabs`가 아니라 각 탭 화면 안의 `TabScreen` + `router.replace`로 구현돼 있다.
- 핵심 사용자 흐름은 모두 실제 구현돼 있다. 다만 별도 “회고 탭”은 없고 홈의 CTA/알림 딥링크에서 회고 전체화면 스택으로 진입한다.
- 서버 데이터의 공통 경계는 `src/lib/http.ts`의 `authedRequest`이며, 화면은 주로 Zustand store 또는 `features/*/data` 어댑터를 통해 데이터를 사용한다.
- 현재 시각 체계는 크림색 바탕, 따뜻한 갈색 잉크, 세이지 초록 CTA, 모눈 배경, 둥근 카드, 손글씨 중심의 단일 라이트 테마다. 로그인만 Pretendard, Google 버튼만 Roboto를 쓴다.
- 가장 큰 UX 개선 여지는 로딩·오류·빈 상태의 구분, 탭 이동 시 화면 상태 보존, 과거 일기의 일정 데이터 완결성, 알림 진입 경로, 캘린더 연결 해제, 온보딩 입력 검증, 손글씨 본문 가독성 검증에 있다.

### 상태와 데이터 구조

- 전역/도메인 상태는 **Zustand**를 사용한다. React Query는 설치·적용돼 있지 않다.
- 인증 토큰과 캘린더 동기화 해시는 `expo-secure-store`, 쉼터 가이드 확인/추천 억제는 `AsyncStorage`를 사용한다.
- 일정, 일기, 바람카드, 주간 리포트, 프로필, 회고, 보물, 쉼 이용 기록은 서버가 정본이다.
- 알림·캘린더·위치·음성 인식은 각각 OS 권한/네이티브 API에도 의존한다.
- `AppProviders`가 폰트 로드, Safe Area, 전역 토스트, 분석 관찰자, 알림 예약 동기화, 포그라운드 캘린더 동기화, 04:00 하루 경계 갱신을 담당한다.


### 라우트 레이아웃과 가드

| 레이아웃                       | 역할                                                                                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `app/_layout.tsx`              | 전체 fade 전환, 크림 배경, 다크 글자 상태바. `home`은 투명 모달, `retro`는 가로 슬라이더와 충돌하지 않도록 iOS 뒤로가기 제스처 비활성화. |
| `app/(onboarding)/_layout.tsx` | 세션 hydrate 및 인증 가드, 온보딩 선택지 선조회. 미인증이면 `/login`.                                                                    |
| `app/(tabs)/_layout.tsx`       | 인증 가드, 콜드 스타트 캘린더 동기화, 일기/바람카드 선조회.                                                                              |
| `app/home/_layout.tsx`         | 홈 위 투명 일정 입력 바. 미인증 차단.                                                                                                    |
| `app/retro/_layout.tsx`        | 전체화면 회고, 탭바 없음, 뒤로가기 제스처 없음, 닫기는 화면의 `✕`.                                                                       |
| `app/diary/_layout.tsx`        | 탭 위 일기 상세 스택.                                                                                                                    |
| `app/rest/_layout.tsx`         | 쉼터 상세 스택 인증 가드.                                                                                                                |
| `app/my/_layout.tsx`           | 기본 정보 목록/수정 스택 인증 가드.                                                                                                      |

`/rest`라는 URL 이름은 `(onboarding)/rest.tsx`와 `(tabs)/rest.tsx` 양쪽에 존재한다. 코드 내부에서 쉼터 탭으로 확실히 복귀해야 할 때 `/(tabs)/rest`를 명시하고 있다.

## 4. 전체 화면 인벤토리

표의 API는 화면이 직접 호출하거나 해당 화면이 사용하는 store/공통 레이아웃이 호출하는 것을 포함한다. 분석 이벤트 전송은 모든 행에 반복하지 않고 제외했다.

### 4.1 진입과 인증 — 2개

| 화면/경로                                        | 목적과 주요 UI                                                                                                   | 주요 행동과 이동                                                                                                                                                   | API·데이터 의존성                                                                                               | 구현 상태                                                                                                                                      |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **스플래시**<br>`app/index.tsx`<br>`/`           | 네이티브 스플래시와 같은 얼굴 이미지, 워드마크, 빗살 로더로 세션과 온보딩 완료 여부를 판정한다. 최소 0.8초 노출. | 자동으로 `/login`, `/welcome`, `/home` 중 하나로 `replace`.                                                                                                        | SecureStore 세션, `GET /api/v1/users/me`, 인증 store, 온보딩 완료 store.                                        | hydrate/폰트 로딩 중 로더. 서버 판정 실패 시 “인터넷 연결을 기다리고 있어요”를 보이며 3초 간격 자동 재시도. 수동 재시도/최종 오류 화면은 없음. |

## 5. 화면 밖에 있지만 중요한 UI 상태

다음은 독립 라우트가 아니므로 36개에 포함하지 않았지만 리디자인 시 별도 상태로 다뤄야 한다.

- 홈: 일정 행 `⋮` 메뉴, 수동 일정 삭제 모달, 일정 삭제 토스트.
- 쉼터: 일기 작성 후 추천 바텀시트, 네 콘텐츠의 첫 방문 가이드 카드, 완료 시 기분 쪽지.
- 보관함: 목록 기간 선택 바텀시트.
- 리포트: 주차 선택 바텀시트.
- 마이: 알림 시간 휠, 캘린더 연결/기기 설정, 회원 탈퇴 확인 바텀시트.
- 온보딩: 회고 시간 휠 바텀시트, OS 알림/캘린더 권한 다이얼로그.
- 일기/바람카드: 삭제 확인 모달.
- 전역: `ToastHost`, 알림 딥링크 처리용 `ReminderRoute`, 인증 만료 시 라우트 가드.

### 데이터 로딩의 현재 특징

- 탭 레이아웃 진입 시 `useDiary.load()`가 최근 **12개월**의 일기와 바람카드를 월별로 병렬 조회한다. 최대 24개 GET 요청이며 한 번 로드되면 세션 동안 재사용한다.
- 홈 일정은 홈 마운트 시 오늘 하루를 조회한다. 실패 시 기존 값 또는 빈 목록을 유지한다.
- 보관함 일정은 달을 바꿀 때 기간 조회를 하며 가장 최근 요청만 반영한다.
- 리포트는 탭 포커스 때 이번 주를 다시 조회하고, 주를 고르면 기존 report를 비운 뒤 새 주를 조회한다.
- 쉼터의 보물/이용 기록 목록은 화면마다 직접 조회한다. 실패를 빈 배열로 변환한다.
- 대부분의 쓰기는 낙관 반영 후 서버 거부 시 롤백하거나 토스트를 띄운다. 회고 일기 본문 수정은 실패를 조용히 무시한다.

- 색상 hex는 `src/design/**`에만 두도록 린트 규칙과 설계 주석이 존재한다.
- 로그인 소셜 버튼은 서비스별 공식 색과 마크를 예외 토큰으로 관리한다.
- 쉼터의 연못/걱정상자/보물함/몸 이완은 공통 앱 팔레트와 별도의 장면 전용 토큰·이미지를 쓴다.

### 타이포그래피

- 로그인 이외 앱 전체는 `KyoboHandwriting2025lyb` 단일 파일을 사용한다.
- 로그인 본문/약관/오류는 Pretendard 4웨이트, Google 버튼은 Roboto Medium이다.
- 21개 이름의 텍스트 토큰이 있지만 교보손글씨에서는 weight 이름들이 같은 파일을 가리켜 실제 굵기 차이가 없다. 위계는 크기·색·배치에 의존한다.
- 주요 단은 워드마크 40/52, 홈 날짜 32/42, 화면 제목 24/32, 카드 제목 22/30, 본문 16/24 또는 16/26, 최소 캡션 11/14다.
- iOS에는 별도 크기 보정과 버튼 라벨 보정이 있고, 시스템 글꼴 배율은 레이아웃 파손을 막기 위해 약 1.3배를 상한으로 둔다.

### 간격, 형태, 모션, 스타일링

- 기준 프레임 375×812, 화면 좌우 패딩 20, 최소 터치 44.
- 간격은 2~48의 9개 토큰, radius는 8/12/16/20/28/full을 사용한다.

## 8. 주요 사용자 흐름과 실제 구현 여부

### 온보딩 — 구현됨

```text
스플래시 → 로그인 → 첫 메시지 → 닉네임 → 나이(선택) → 성별(선택)
→ 관심 분야 → 쉬는 방법 → 회고 시간/알림 → 캘린더 연결(선택)
→ 서버 저장 → 홈
```

- 서버 선택지와 폴백, OS 권한, 최종 서버 저장까지 구현돼 있다.
- 온보딩 초안은 메모리 상태라 앱 프로세스가 종료되면 이어서 재개할 수 없다.

### 홈 — 구현됨

```text
오늘 상태 확인 → 일정 추가/완료/정렬/수정/삭제 → 하루 회고 시작
```

- 기기 캘린더 일정과 직접 입력 일정이 같은 목록에 나타나며 수정/삭제 의미는 source에 따라 다르다.
- 오늘 일기를 이미 썼으면 회고 일정 확인을 건너뛰고 “하루 한 번” 안내로 진입한다.

### 회고 — 구현됨

```text
오늘 일정 읽기 → 서버 주도 대화 → 일기/선택 분기 → 감정·바람 탐색(선택)
→ 완성 일기 확인/직접 수정 → 저장 → 쉼터 또는 저장 완료/바람카드
```

- 별도 회고 탭은 없고 홈 CTA가 주 진입점이다.
- 회고 재개/초안 영속 저장은 구현돼 있지 않다. 진행 중 앱 종료 시 메모리 세션 UI가 사라진다.

### 쉼터 — 구현됨

```text
쉼터 허브
├─ 바람카드 날짜 탐색/실천/느낀 점
├─ 감각연못
├─ 걱정상자
├─ 오늘의 보물함 → 지난 보물
└─ 몸에 힘 빼기
   각 콘텐츠 → 완료 기분 쪽지 → 이용 기록
```

- 네 쉼 콘텐츠 모두 실제 화면과 이용 기록 API가 있다.
- 걱정 원문은 저장하지 않고, 보물 원문만 서버에 저장한다.

### 보관함 — 구현됨

```text
달력 보기 ↔ 목록 보기
달력: 날짜 → 그날 일기/일정
목록: 검색 + 복수 감정 필터 + 기간 → 일기 상세
```

- 별도 A1/A2 라우트가 아니라 한 화면 내부 모드다.

### 리포트 — 구현됨

```text
이번 주 리포트 → 기록이 있는 주 선택 → 감정/바람/집계 관찰
→ 해당 주 시작일을 들고 보관함으로 이동
```

- 데이터 집계는 화면이 아니라 서버 응답을 그대로 사용한다.

### 마이페이지 — 구현됨

```text
마이
├─ 알림 시간/끄기 시트
├─ 캘린더 연결
├─ 기본 정보 목록 → 항목별 수정 5개
├─ 문의/약관/개인정보 웹 문서
├─ 로그아웃
└─ 문구 입력 확인 후 회원 탈퇴
```

- 캘린더 재연결은 있지만 연결 해제 UI는 없다.
- 별도 알림 화면은 없고 마이 화면 내부 바텀시트다.

### 현재 구조에서 유지할 가치가 큰 점

- 되돌릴 수 없는 삭제/탈퇴만 확인 UI를 사용하고 일반 오류는 인라인 한 줄로 처리한다.
- 점수·연속 일수·달성률보다 관찰과 기록을 중심으로 문안을 구성한다.
- 선택 상태를 색만으로 표현하지 않고 두께·크기·체크·형태를 함께 사용한다.
- 서버 응답을 `features/*/data`에서 런타임 검증하고 화면이 서버 DTO를 직접 다루지 않는다.
- OS 권한 요청 전에 사용 이유를 설명하고 거부해도 핵심 흐름을 막지 않는다.
- 걱정 원문 미저장, 분석에 자유 텍스트 대신 길이/행동만 전송하는 등 민감 정보 최소화가 코드에 반영돼 있다.

## 10. 리디자인 착수 시 권장 기준선

1. 36개 라우트 화면과 위에 정리한 주요 오버레이 상태를 리디자인 범위의 체크리스트로 사용한다.
2. 각 화면 시안에 기본/로딩/빈/부분 데이터/오류/권한 거부/저장 중 상태를 함께 정의한다.
3. 홈→회고→쉼터, 리포트→보관함, 마이→권한 설정의 교차 흐름을 개별 화면보다 먼저 프로토타이핑한다.
4. 브랜드 손글씨와 장면형 쉼터는 유지 후보로 두되 긴 본문·설정 정보의 가독성을 별도 검증한다.
5. 화면 시안과 동시에 데이터 범위(오늘/한 달/12개월), 캐시와 재시도, 초안 재개 정책을 명시한다.
6. 실제 구현에 없는 별도 회고 탭, 알림 목록, 일기 편집 라우트, 캘린더 연결 관리 화면을 현행 기능으로 간주하지 않는다. 새로 제안할 경우 “신규 범위”로 분리한다.
