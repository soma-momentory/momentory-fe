### 수집·공유 표

> 2026-11-06: 아래 표는 2026-09-12 의 답이다. **현재 운영 빌드(1.3.0)와 다음 출시의 차이**는 이 절 끝의

「공유」는 **제3자에게 넘기는 것**을 말한다. 아래는 전부 **수집함 · 공유 안 함**이다
(Gemini 는 다음 절 참조).

| 데이터 유형                                                                       | 수집          | 공유          | 필수          | 목적                                                       |
| --------------------------------------------------------------------------------- | ------------- | ------------- | ------------- | ---------------------------------------------------------- |

| 금융 정보 · 메시지 · 사진 · 연락처 · 파일                                         | 아니요        | —             | —             | 코드에 경로가 없다                                         |

**캘린더가 「선택」인 이유** — 온보딩 `09` 에서 「나중에 할게요」로 건너뛸 수 있고,
권한을 주지 않아도 앱의 나머지가 그대로 돈다(`app/(onboarding)/calendar.tsx`).
나머지는 로그인·온보딩을 통과해야 앱을 쓸 수 있으므로 필수다.

**분석 둘이 「선택」인 이유** — 계측은 앱 기능이 아니라 **분석**이고, 키가 없으면 꺼진
채로 앱이 그대로 돈다. Play 는 「사용자가 끌 수 있는가」가 아니라 「이 데이터 없이 앱을
쓸 수 있는가」를 묻는다 — 쓸 수 있다.

**사용자 ID 는 왜 「필수」에 목적이 셋인가** — 같은 값이 두 곳에 쓰인다. 서버는 계정
자체로 그것을 쥐고 있고(앱 기능 · 계정 관리 · 없으면 앱을 못 쓴다 → **필수**), 계측이
켜진 빌드에서는 **같은 ID 가 Amplitude 의 `user_id` 로도 나간다**
(`features/auth/model/auth.ts` 의 `identifyAnalytics(session.userId)`). Play 의 데이터
유형은 한 줄에 목적을 여러 개 붙이는 방식이라 **줄을 나누지 않고 목적에 「분석」을
더한다.** ⚠ 이 줄을 빼면 계측이 켜진 빌드에서 **계정에 연결된 식별자를 신고 없이
보내는 것**이 된다 — 임의 기기 ID(위 줄)와는 다른 항목이다.

### 소원 연꽃 — 사용자 생성 콘텐츠가 남에게 보인다 (다음 출시 · BE `dev` `#86`)

앱에서 처음으로 **한 사용자의 글이 다른 사용자 화면에 뜬다.** 코드가 하는 일(자세한 것은
[`DATA-SECURITY.md`](DATA-SECURITY.md) §1-1):

- 띄우기 전 규칙 검사 + **Gemini 심사**(이름 · 연락처를 지운 글로 고칠 수 있다) · 연락처 정규식 한 번 더

- 지우기는 소프트 삭제(`deleted_at`) · 행은 탈퇴 때 지워진다

⛔ **팀이 정할 것** — 이 문서는 답을 정하지 않는다:

1. 데이터 보안 양식에서 소원을 「공유」로 볼지 — 다른 사용자에게 보이는 것이 Play 의 「공유」 정의에 드는지 확인

   운영 절차가 지금 코드(신고 3명 자동 내림 · 사람이 보는 화면 없음)로 충분한지. App Store 심사의 사용자 생성 콘텐츠
   항목도 같은 질문이다
3. 지운 · 내려간 소원을 언제까지 둘지 — 처리방침의 보유 기간 문안과 맞아야 한다

제공하는가」이고, 회고와 일기는 거기 해당하지 않는다.

`weekly_report_writings`(`V37`) · `weekly_happiness_entries`(`V39` · FK cascade). 탈퇴 코드(`UserWithdrawalService` → `UserDeletionService`)는 `main` · `dev` 가 같다.
⚠ 탈퇴하면 **문의도 지워진다** · 탈퇴 전의 소원 「지우기」는 행을 남긴다(`deleted_at`).

⚠ **Amplitude 는 이 cascade 밖이다** — 탈퇴해도 이미 보낸 이벤트는 Amplitude 프로젝트에
남는다. 삭제 요청이 오면 **내부 사용자 ID 로 Amplitude 쪽에서도 지워야 한다.**

## ⚠ 확인이 필요한 것 하나 — Gemini API 등급

회고 대화와 일기 생성은 **Google Gemini API 로 나간다**
(`retrospect/infrastructure/ai/GeminiApiClient` · `GeminiTurnScripter` ·
`GeminiDiaryWriter`, 행동카드 상황은 `GeminiSituationEmbedder` 로 임베딩된다).
즉 **사용자가 쓴 글이 외부 API 로 전송된다.**
(2026-11-06 대조: `GeminiTurnScripter` 는 운영 · dev 둘 다 없다 — 지금 이름은 위 「외부 서비스」 표다.
다음 출시에는 편지 · 주간 공책 · 소원 심사 · 사건 추출이 더해져 **같은 질문이 그 넷에도 걸린다.**)

Play 의 「공유」 정의는 **개발자를 대신해 처리하는 서비스 제공업체로의 전송을 제외**한다.
그래서 위 표를 「공유 안 함」으로 적었는데, **이는 Gemini 가 우리 데이터를 자기 목적으로
쓰지 않는다는 전제 위에 있다.**

- **유료(청구 계정 연결) 등급** — 입력을 모델 개선에 쓰지 않는다 → 「공유 안 함」이 맞다
- **무료 등급** — 구글이 서비스 개선에 활용할 수 있다 → **「공유함」으로 신고해야 한다**

**결제 계정이 붙어 있는지 확인하고, 무료 등급이면 위 표에서 「사용자 생성 콘텐츠」의
공유를 「예」로 바꾼다.** 이 한 줄이 양식 전체에서 가장 사실 확인이 필요한 자리다.

> 개인정보 처리방침에도 **AI 처리를 위해 대화 내용이 외부로 전송된다는 사실**이 적혀
> 있어야 한다. 양식과 방침이 어긋나면 그것도 위반이다 — `momentory.co.kr/privacy` 의
> 문구를 이 문서와 맞춰 둔다.
