# Play 데이터 보안 양식 — 코드 기준 답안

Google Play Console 「앱 콘텐츠 → 데이터 보안」에 넣을 값을, **추측이 아니라 실제로
서버에 저장되는 것**을 기준으로 정리한다. 최초 작성 2026-08-26.

> ⚠ **이 문서는 코드가 바뀌면 낡는다.** 새 필드를 서버에 보내거나 외부 서비스를 하나
> 더 붙일 때는 여기도 함께 고친다. 양식과 실제가 어긋나면 **정책 위반**이고, 구글은
> 앱을 내린다. 판단이 갈리면 `momentory-be` 의 엔티티를 정본으로 본다.

> 🔴 **2026-09-12 대조 — 양식을 고쳐야 한다.** 2026-09-05 에 **Amplitude 계측이 앱에 들어왔다**
> (`src/features/analytics/` · [`ANALYTICS.md`](ANALYTICS.md)). 아래 표의
> 「앱 활동 › 앱 상호작용 = 아니요 (분석 도구가 없다)」는 **더 이상 사실이 아니다.**
> **키가 들어간 빌드를 올리기 전에** 아래 「분석 도구」 절대로 양식을 고친다 —
> 키가 비어 있으면 수집이 꺼지지만, 스토어 양식은 **빌드가 할 수 있는 일**을 기준으로 답한다.

## 무엇이 어디에 저장되는가

서버가 실제로 들고 있는 것 (`momentory-be` 엔티티 기준):

| 테이블                                            | 담기는 것                                                                                        |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `users`                                           | 이메일, 역할, 온보딩 완료 여부                                                                   |
| `oauth_accounts`                                  | 공급자(카카오·구글·애플), 공급자 사용자 ID, 애플 refresh token                                   |
| `user_profiles`                                   | 닉네임, 나이, 성별, 관심사·쉬는 방법(기타 입력 포함), 회고 시간, 타임존, 캘린더 연동·알림 스위치 |
| `schedules`                                       | 일정 제목, 날짜, 감정, 완료 여부, 출처(기기 캘린더 여부)와 `externalId`                          |
| `retrospects`                                     | 회고 대화                                                                                        |
| `diaries`                                         | 일기 원문(`original`), 대표 감정(`primary_emotion` · nullable)과 감정 태그(`emotions`)           |
| `action_cards`                                    | **바람 카드** — 상황 · 감정 · 바람(needs) · 바랐던 모습 · 작은 행동 · 느낀 점 · 상황 임베딩      |
| `retrospect_topics` · `retrospect_topic_emotions` | 회고에서 뽑은 주 일정·키워드와 거기 붙은 감정 (주간 집계용 · BE `V22`)                           |
| `daily_memos`                                     | 그날의 메모 본문 — ⚠ **앱에는 이걸 쓰는 화면이 없다**(`12-d` 삭제). 테이블만 남아 있다           |
| `refresh_tokens`                                  | 토큰 해시 (원문 아님)                                                                            |

> 2026-09-12 갱신: 회고 v2 로 `action_cards` 가 바람 카드로 넓어졌고(`V20`), 일기가 감정
> 태그를 갖게 됐으며(`V21`·`V23`), 회고 토픽 두 테이블이 생겼다(`V22`).

앱이 **기기에만 두는 것**: 세션 토큰과 캘린더 동기화 상태(`expo-secure-store` · 사용자별).
~~지운 행동카드 id 묘비~~ 는 **없어졌다** — 서버에 카드 삭제 계약이 생겼다
(`DELETE /api/v1/action-cards/{id}`). Amplitude SDK 는 자기 기기 식별자와 이벤트 큐를
기기에 둔다(아래 「분석 도구」).

## 양식 답안

### 수집·공유 표

「공유」는 **제3자에게 넘기는 것**을 말한다. 아래는 전부 **수집함 · 공유 안 함**이다
(Gemini 는 다음 절 참조).

| 데이터 유형                                                                       | 수집          | 공유          | 필수          | 목적                                                       |
| --------------------------------------------------------------------------------- | ------------- | ------------- | ------------- | ---------------------------------------------------------- |
| 개인 정보 › **이름** (닉네임)                                                     | 예            | 아니요        | 필수          | 앱 기능                                                    |
| 개인 정보 › **이메일 주소**                                                       | 예            | 아니요        | 필수          | 앱 기능 · 계정 관리                                        |
| 개인 정보 › **기타 정보** (나이 · 성별)                                           | 예            | 아니요        | 필수          | 앱 기능                                                    |
| 개인 정보 › **사용자 ID** (서비스 내부 사용자 ID)                                 | 예            | 아니요        | 필수          | 앱 기능 · 계정 관리 · **분석**                             |
| **캘린더** › 캘린더 일정                                                          | 예            | 아니요        | **선택**      | 앱 기능                                                    |
| 앱 활동 › **기타 사용자 생성 콘텐츠** (일기 · 회고 · 행동카드 · 메모 · 일정 제목) | 예            | 아니요        | 필수          | 앱 기능                                                    |
| 앱 활동 › **앱 상호작용**                                                         | **예**        | 아니요        | **선택**      | **분석** — Amplitude(아래 절)                              |
| **기기 또는 기타 ID**                                                             | **예**        | 아니요        | **선택**      | 분석 — Amplitude 가 만드는 임의 기기 ID(광고 ID 아님)      |
| **위치** (대략적 · 정확한 위치 중 무엇인지 포함)                                  | **확인 필요** | **확인 필요** | **확인 필요** | 일기 날씨가 반올림 좌표를 서버로 보낸다 — 아래 「위치」 절 |
| 금융 정보 · 메시지 · 사진 · 연락처 · 파일                                         | 아니요        | —             | —             | 코드에 경로가 없다                                         |

**캘린더가 「선택」인 이유** — 온보딩 `09` 에서 「나중에 할게요」로 건너뛸 수 있고,
권한을 주지 않아도 앱의 나머지가 그대로 돈다(`app/(onboarding)/calendar.tsx`).
나머지는 로그인·온보딩을 통과해야 앱을 쓸 수 있으므로 필수다.

**분석 둘이 「선택」인 이유** — 계측은 앱 기능이 아니라 **분석**이고, 키가 없으면 꺼진
채로 앱이 그대로 돈다. Play 는 「사용자가 끌 수 있는가」가 아니라 「이 데이터 없이 앱을
쓸 수 있는가」를 묻는다 — 쓸 수 있다.

**사용자 ID 는 왜 「필수」에 목적이 셋인가** — 같은 값이 두 곳에 쓰인다. 서버는 계정
자체로 그것을 쥐고 있고(앱 기능 · 계정 관리 · 없으면 앱을 못 쓴다 → **필수**), 계측이
켜진 빌드에서는 **같은 ID 가 Amplitude 의 `user_id` 로도 나간다**
(`features/auth/model/auth.ts` 의 `identifyAnalytics(session.userId)`). Play 의 데이터
유형은 한 줄에 목적을 여러 개 붙이는 방식이라 **줄을 나누지 않고 목적에 「분석」을
더한다.** ⚠ 이 줄을 빼면 계측이 켜진 빌드에서 **계정에 연결된 식별자를 신고 없이
보내는 것**이 된다 — 임의 기기 ID(위 줄)와는 다른 항목이다.

### 분석 도구 — Amplitude (2026-09-05 도입)

**무엇이 나가나**: 화면 조회 · 버튼 클릭 · 작업 성공 같은 **이벤트 이름과 허용된 속성**뿐이다.
사용자 식별은 **서비스 내부 사용자 ID 문자열**이고 이메일·SNS ID·토큰은 보내지 않는다.
**보내지 않는 것**(타입과 런타임 두 겹으로 막는다 · `features/analytics/events.ts`):
일기·회고·일정·바람의 **본문 전부**, 감정·욕구 코드와 이름, 알림 설정·시각.
SDK 공통 메타데이터는 발생 시각 · **임의 기기 ID** · 세션 ID · 앱 버전 · OS/플랫폼이고,
광고 ID·IDFV·App Set ID·통신사·국가·제조사 수집은 **꺼 뒀다**(`amplitude.ts`).

| 물음                     | 답                                                                                                            |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 제3자에게 **공유**하는가 | **아니요** — Amplitude 는 우리 대신 처리하는 **처리자**다(우리 프로젝트로만 들어간다)                         |
| 전송 중 암호화           | 예 (SDK 가 HTTPS)                                                                                             |
| 사용자가 삭제 요청 가능  | 예 — 회원 탈퇴로 서버 데이터가 지워지고, Amplitude 쪽은 내부 ID 로 삭제 요청할 수 있다                        |
| 데이터가 국외로 나가는가 | **예 — US 리전 프로젝트다**(`ANALYTICS.md` 「활성화」). 개인정보 처리방침의 국외 이전 항목에 적혀 있어야 한다 |

⚠ **확인할 것 둘** — (1) 「기기 또는 기타 ID」를 체크할지: Amplitude 가 만드는 것은 광고
식별자가 아니라 앱이 만든 임의 설치 ID 지만, Play 의 정의(「기기·브라우저·앱과 연결된
식별자」)에는 들어간다고 읽는 쪽이 안전하다. (2) 개인정보 처리방침에 **Amplitude 와
국외 이전**이 적혀 있는지 — 양식과 처리방침이 어긋나도 정책 위반이다.

### ⛔ 「건강 및 피트니스」는 선택하지 않는다

감정 열 가지 중에서 고르는 것은 Play 가 말하는 **건강 정보**(의료 기록 · 증상 ·
검사 결과 · 진단)가 아니다. 모멘토리는 진단하지 않고, 치료를 제안하지 않고, 건강
지표를 측정하지 않는다.

⚠ **여기에 체크하면 「건강 앱」으로 분류돼 개인 개발자 계정으로는 출시할 수 없다**
(`SETUP.md` §8 「Play Console — 개인 계정이 걸리는 둘」). 2026-08-26 에 실제로 그 이유로
거부됐다. 이건 회피가 아니라 분류의 문제다 — Play 가 묻는 것은 「규제 대상 건강 서비스를
제공하는가」이고, 회고와 일기는 거기 해당하지 않는다.

### 보안 관행

| 질문                                  | 답                                       | 근거                                                                                          |
| ------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------- |
| 전송 중 암호화                        | **예**                                   | `https://api.momentory.co.kr` · 매니페스트가 평문을 막는다(`withInsecureDevApi` 는 개발 전용) |
| 사용자가 데이터 삭제를 요청할 수 있음 | **예**                                   | 마이 › 회원 탈퇴 → `DELETE /api/v1/users/me`                                                  |
| 계정·데이터 삭제 URL                  | `https://momentory.co.kr/account-delete` |                                                                                               |
| 개인정보처리방침                      | `https://momentory.co.kr/privacy`        |                                                                                               |
| 독립적인 보안 검토를 받았음           | **아니요**                               | 받은 적 없다                                                                                  |

**삭제가 실제로 지워지는지** — `UserWithdrawalService` 가 카카오 연결 해제·애플 revoke 를
먼저 하고 `users` 행을 지운다. 나머지 테이블은 `V16__cascade_user_deletion.sql` 의
`ON DELETE CASCADE` 로 함께 지워진다: `oauth_accounts` · `refresh_tokens` ·
`user_profiles` · `user_interest_areas` · `user_rest_methods` · `schedules` ·
`daily_memos` · `retrospects` · `action_cards` · `diaries`. 2026-09 에 생긴
`retrospect_topics` · `retrospect_topic_emotions` 도 `user_id` FK 가 `ON DELETE CASCADE` 다
(BE `V22`). **남는 테이블이 없다.**

⚠ **Amplitude 는 이 cascade 밖이다** — 탈퇴해도 이미 보낸 이벤트는 Amplitude 프로젝트에
남는다. 삭제 요청이 오면 **내부 사용자 ID 로 Amplitude 쪽에서도 지워야 한다.**

## ⚠ 확인이 필요한 것 하나 — Gemini API 등급

회고 대화와 일기 생성은 **Google Gemini API 로 나간다**
(`retrospect/infrastructure/ai/GeminiApiClient` · `GeminiTurnScripter` ·
`GeminiDiaryWriter`, 행동카드 상황은 `GeminiSituationEmbedder` 로 임베딩된다).
즉 **사용자가 쓴 글이 외부 API 로 전송된다.**

Play 의 「공유」 정의는 **개발자를 대신해 처리하는 서비스 제공업체로의 전송을 제외**한다.
그래서 위 표를 「공유 안 함」으로 적었는데, **이는 Gemini 가 우리 데이터를 자기 목적으로
쓰지 않는다는 전제 위에 있다.**

- **유료(청구 계정 연결) 등급** — 입력을 모델 개선에 쓰지 않는다 → 「공유 안 함」이 맞다
- **무료 등급** — 구글이 서비스 개선에 활용할 수 있다 → **「공유함」으로 신고해야 한다**

**결제 계정이 붙어 있는지 확인하고, 무료 등급이면 위 표에서 「사용자 생성 콘텐츠」의
공유를 「예」로 바꾼다.** 이 한 줄이 양식 전체에서 가장 사실 확인이 필요한 자리다.

> 개인정보 처리방침에도 **AI 처리를 위해 대화 내용이 외부로 전송된다는 사실**이 적혀
> 있어야 한다. 양식과 방침이 어긋나면 그것도 위반이다 — `momentory.co.kr/privacy` 의
> 문구를 이 문서와 맞춰 둔다.
