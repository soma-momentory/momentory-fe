# Play 데이터 보안 양식 — 코드 기준 답안

Google Play Console 「앱 콘텐츠 → 데이터 보안」에 넣을 값을, **추측이 아니라 실제로
서버에 저장되는 것**을 기준으로 정리한다. 최초 작성 2026-08-26.

> ⚠ **이 문서는 코드가 바뀌면 낡는다.** 새 필드를 서버에 보내거나 외부 서비스를 하나
> 더 붙일 때는 여기도 함께 고친다. 양식과 실제가 어긋나면 **정책 위반**이고, 구글은
> 앱을 내린다. 판단이 갈리면 `momentory-be` 의 엔티티를 정본으로 본다.

## 무엇이 어디에 저장되는가

서버가 실제로 들고 있는 것 (`momentory-be` 엔티티 기준):

| 테이블           | 담기는 것                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| `users`          | 이메일, 역할, 온보딩 완료 여부                                                                   |
| `oauth_accounts` | 공급자(카카오·구글·애플), 공급자 사용자 ID, 애플 refresh token                                   |
| `user_profiles`  | 닉네임, 나이, 성별, 관심사·쉬는 방법(기타 입력 포함), 회고 시간, 타임존, 캘린더 연동·알림 스위치 |
| `schedules`      | 일정 제목, 날짜, 감정, 완료 여부, 출처(기기 캘린더 여부)와 `externalId`                          |
| `retrospects`    | 회고 대화                                                                                        |
| `diaries`        | 일기 원문(`original`)과 다시 쓴 글(`reframed`), 감정 둘                                          |
| `action_cards`   | 상황·행동·회고 메모, 상황 임베딩                                                                 |
| `daily_memos`    | 그날의 메모 본문                                                                                 |
| `refresh_tokens` | 토큰 해시 (원문 아님)                                                                            |

앱이 **기기에만 두는 것**: 세션 토큰(`expo-secure-store`), 지운 행동카드 id
(`deletedCardStore` — 서버에 삭제 계약이 없어서 두는 묘비).

## 양식 답안

### 수집·공유 표

「공유」는 **제3자에게 넘기는 것**을 말한다. 아래는 전부 **수집함 · 공유 안 함**이다
(Gemini 는 다음 절 참조).

| 데이터 유형                                                                       | 수집   | 공유   | 필수     | 목적                                      |
| --------------------------------------------------------------------------------- | ------ | ------ | -------- | ----------------------------------------- |
| 개인 정보 › **이름** (닉네임)                                                     | 예     | 아니요 | 필수     | 앱 기능                                   |
| 개인 정보 › **이메일 주소**                                                       | 예     | 아니요 | 필수     | 앱 기능 · 계정 관리                       |
| 개인 정보 › **기타 정보** (나이 · 성별)                                           | 예     | 아니요 | 필수     | 앱 기능                                   |
| **캘린더** › 캘린더 일정                                                          | 예     | 아니요 | **선택** | 앱 기능                                   |
| 앱 활동 › **기타 사용자 생성 콘텐츠** (일기 · 회고 · 행동카드 · 메모 · 일정 제목) | 예     | 아니요 | 필수     | 앱 기능                                   |
| 앱 활동 › 앱 상호작용                                                             | 아니요 | —      | —        | 분석 도구가 없다                          |
| 기기 또는 기타 ID                                                                 | 아니요 | —      | —        | 광고 ID 를 쓰지 않는다(`AD_ID` 권한 없음) |
| 위치 · 금융 정보 · 메시지 · 사진 · 연락처 · 파일                                  | 아니요 | —      | —        | 코드에 경로가 없다                        |

**캘린더가 「선택」인 이유** — 온보딩 `09` 에서 「나중에 할게요」로 건너뛸 수 있고,
권한을 주지 않아도 앱의 나머지가 그대로 돈다(`app/(onboarding)/calendar.tsx`).
나머지는 로그인·온보딩을 통과해야 앱을 쓸 수 있으므로 필수다.

### ⛔ 「건강 및 피트니스」는 선택하지 않는다

감정 아홉 가지 중 하나를 고르는 것은 Play 가 말하는 **건강 정보**(의료 기록 · 증상 ·
검사 결과 · 진단)가 아니다. 모멘토리는 진단하지 않고, 치료를 제안하지 않고, 건강
지표를 측정하지 않는다.

⚠ **여기에 체크하면 「건강 앱」으로 분류돼 개인 개발자 계정으로는 출시할 수 없다**
(`SETUP.md` §8 「Play Console — 개인 계정이 걸리는 둘」). 2026-08-26 에 실제로 그 이유로
거부됐다. 이건 회피가 아니라 분류의 문제다 — Play 가 묻는 것은 「규제 대상 건강 서비스를
제공하는가」이고, 회고와 일기는 거기 해당하지 않는다.

### 보안 관행

| 질문                                  | 답                                       | 근거                                                                                          |
| ------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------- |
| 전송 중 암호화                        | **예**                                   | `https://api.momentory.co.kr` · 매니페스트가 평문을 막는다(`withInsecureDevApi` 는 개발 전용) |
| 사용자가 데이터 삭제를 요청할 수 있음 | **예**                                   | 마이 › 회원 탈퇴 → `DELETE /api/v1/users/me`                                                  |
| 계정·데이터 삭제 URL                  | `https://momentory.co.kr/account-delete` |                                                                                               |
| 개인정보처리방침                      | `https://momentory.co.kr/privacy`        |                                                                                               |
| 독립적인 보안 검토를 받았음           | **아니요**                               | 받은 적 없다                                                                                  |

**삭제가 실제로 지워지는지** — `UserWithdrawalService` 가 카카오 연결 해제·애플 revoke 를
먼저 하고 `users` 행을 지운다. 나머지 테이블은 `V16__cascade_user_deletion.sql` 의
`ON DELETE CASCADE` 로 함께 지워진다: `oauth_accounts` · `refresh_tokens` ·
`user_profiles` · `user_interest_areas` · `user_rest_methods` · `schedules` ·
`daily_memos` · `retrospects` · `action_cards` · `diaries`. **남는 테이블이 없다.**

## ⚠ 확인이 필요한 것 하나 — Gemini API 등급

회고 대화와 일기 생성은 **Google Gemini API 로 나간다**
(`retrospect/infrastructure/ai/GeminiApiClient` · `GeminiTurnScripter` ·
`GeminiDiaryWriter`, 행동카드 상황은 `GeminiSituationEmbedder` 로 임베딩된다).
즉 **사용자가 쓴 글이 외부 API 로 전송된다.**

Play 의 「공유」 정의는 **개발자를 대신해 처리하는 서비스 제공업체로의 전송을 제외**한다.
그래서 위 표를 「공유 안 함」으로 적었는데, **이는 Gemini 가 우리 데이터를 자기 목적으로
쓰지 않는다는 전제 위에 있다.**

- **유료(청구 계정 연결) 등급** — 입력을 모델 개선에 쓰지 않는다 → 「공유 안 함」이 맞다
- **무료 등급** — 구글이 서비스 개선에 활용할 수 있다 → **「공유함」으로 신고해야 한다**

**결제 계정이 붙어 있는지 확인하고, 무료 등급이면 위 표에서 「사용자 생성 콘텐츠」의
공유를 「예」로 바꾼다.** 이 한 줄이 양식 전체에서 가장 사실 확인이 필요한 자리다.

> 개인정보 처리방침에도 **AI 처리를 위해 대화 내용이 외부로 전송된다는 사실**이 적혀
> 있어야 한다. 양식과 방침이 어긋나면 그것도 위반이다 — `momentory.co.kr/privacy` 의
> 문구를 이 문서와 맞춰 둔다.
