# Momentory 디자인 시스템 (MVP 확정본)

Wanted Design System(`WantedDesignSystem_cd71f6`)의 구조·컴포넌트를 그대로 쓰고,
색만 Momentory 홈 화면에서 추출한 값으로 교체한 시스템이에요.
**컴포넌트는 semantic 토큰만 참조**하고, 화면마다 새 값을 만들지 않아요.

프레임 기준: **375 × 812** (iOS) · 좌우 패딩 **20 고정** · 상태바 44 · 하단 Safe Area 34

## 2. Typography

Pretendard, 4웨이트(400·500·600·700). Wanted 스케일에서 앱용 11단만 사용해요.

| 스타일         | 크기/행간 | 웨이트 | 용도                                  |
| -------------- | --------- | ------ | ------------------------------------- |
| Title 2        | 28 / 38   | 700    | 브랜드 워드마크, 페이지 제목, 홈 날짜 |
| Title 3        | 24 / 32   | 700    | 화면 제목(마이·쉼터·보관함)           |
| Heading 1      | 22 / 30   | 600    | 카드·시트 제목, 온보딩 질문           |
| Headline 1     | 18 / 26   | 600    | 리스트 강조, 값 표시                  |
| Body 1         | 16 / 24   | 500    | 리스트·본문 기본                      |
| Body 1 Reading | 16 / 26   | 400    | 일기 본문, 대화 메시지                |
| Body 2         | 15 / 22   | 500    | 보조 본문                             |
| Body 2 Reading | 15 / 24   | 400    | 설명 문단                             |
| Label 1        | 14 / 20   | 600    | 버튼·입력 라벨, 섹션 제목             |
| Label 2        | 13 / 18   | 600    | 칩, 작은 버튼, 카드 라벨              |
| Caption 1      | 12 / 16   | 500    | 메타, 헬퍼, 탭 라벨                   |
| Caption 2      | 11 / 14   | 600    | 최소 캡션, 약관                       |

Display는 앱에서 쓰지 않아요. **Title 1은 홈 날짜(손글씨) 한 자리에만 써요**
(2026-08-22 · 32/42 — 아래 손글씨 절). 본문 기본 웨이트는 Medium 500이고
Regular 400은 입력값·플레이스홀더·읽기 본문에만 써요.

**홈의 날짜는 Title 1 손글씨예요** (2026-08-22 · 원래 Title 3 · 아래 손글씨 절). 홈에는 화면 제목이 따로 없고
날짜가 그 자리를 대신해서, 다른 탭의 제목보다 한 단 큰 것이 맞아요. 날짜가 제목 안에
들어가는 다른 자리(「…의 일기」)는 그 화면의 제목이라 Title 3 그대로예요.

### 홈 날짜와 탭 제목은 손글씨예요 (2026-08-22)

**교보손글씨 2025 이유빈** — 세 단이에요. 손글씨는 같은 크기의 고딕보다 작아 보여서
(획이 얇고 글자 면이 좁아요) 홈 날짜만 위 표에 없던 **Title 1(32/42)** 을 써요.

| 단             | 크기/행간 | 쓰는 곳                           |
| -------------- | --------- | --------------------------------- |
| Title 1 손글씨 | 32 / 42   | 홈 날짜 — **앱에서 가장 큰 글자** |
| Title 3 손글씨 | 24 / 32   | 탭 제목 셋 — 쉼터 · 보관함 · 마이 |
| Label 1 손글씨 | 14 / 20   | 홈 날짜 아래 요일                 |

**여기 다섯 자리가 전부예요.** 요일은 날짜와 한 덩어리로 읽혀야 해서 함께 가고,
14/20이 손글씨의 가장 작은 자리예요 — 획이 얇아 이보다 작아지면 읽기가 아니라
무늬가 돼요(처음엔 12로 잡았다가 같은 날 올렸어요).

손글씨는 웨이트가 하나뿐이라 굵기로 위계를 만들 수 없고, 쓰는 자리를 늘리면 위계가
굵기가 아니라 서체로 읽히기 시작해요. 본문·라벨·버튼은 Pretendard 그대로고,
일기 상세(「…의 일기」)처럼 다른 Title 3 자리도 그대로예요.

## 5. Elevation

경계는 border가 아니라 **hairline(inset shadow)** 으로 그려요.

| 단계     | 값                             | 용도               |
| -------- | ------------------------------ | ------------------ |
| Base     | `inset 0 0 0 1px Line/Neutral` | 카드 (그림자 없음) |
| Floating | `0 0 6px rgba(0,0,0,0.08)`     | 입력 바, 토스트    |
| Overlay  | `0 0 12px rgba(0,0,0,0.16)`    | 모달, 바텀시트     |

배경 격자: 32px 정격자, 라이트 `rgba(140,122,102,0.07)` / 다크 `rgba(235,222,205,0.05)`.
기기 프레임에 고정되고 스크롤과 무관해요. 콘텐츠 카드는 불투명 Elevated 면으로 격자 위에 올라가요.

# 화면별 상태 규칙 (구현용)

## 공통

- 뒤로가기 `‹`: 플로우 안에서 한 단계 뒤로 · 닫기 `✕`: 플로우 종료 후 홈 복귀
- Solid Primary CTA는 화면당 1개

- 스크롤 리스트 하단에 탭바 높이 + 20 여백

## 앱 아이콘 · 스플래시

브랜드 그림 로고(카피바라 + `Momentory`)가 서는 자리예요. 원본은 `assets/logo.jpeg`
하나이고 **파생물은 전부 여기서 뽑아요** — 원본이 있어야 다시 뽑을 수 있어요.

앱 안 진입 화면(`S0`·`S1`)의 「모멘토리」는 **손글씨 워드마크로 따로 가요**
(`wordmarkHand` · PR #98). 그림 로고는 앱 **밖**에서 보이는 자리에만 써요.

**런처 아이콘은 워드마크를 뺀 카피바라만이에요** (2026-08-24 개정). 홈 화면에서
아이콘은 손톱만 하고 그 옆에 앱 이름이 이미 적혀 있어요 — 워드마크를 같이 넣으면
읽히지도 않으면서 카피바라만 작아져요. 워드마크가 붙은 온전한 로고는 스플래시가
맡아요.

| 자산                           | 무엇                                                             |
| ------------------------------ | ---------------------------------------------------------------- |
| `icon.png`                     | **카피바라만** · 가로 67% · 알파 없음(iOS 요구사항)              |
| `android-icon-foreground.png`  | 같은 마크 · 가로 **44%** (= 66% × 67% · 아래 ⚠) · 투명 배경      |
| `android-icon-monochrome.png`  | 같은 마크·배율. 안드로이드는 **알파만 봐요**(아래 ⚠)             |
| `adaptiveIcon.backgroundColor` | `#F2E4DC` — 로고의 면. 베이지를 그리는 건 이 배경층 하나뿐이에요 |
| `splash-icon.png`              | 카피바라 **+ 워드마크** · 정사각 1024 · 내용은 안쪽 66% · 투명   |
| `favicon.png`                  | 196 · **카피바라만** — 16~32px 에서 글자는 못 읽어요             |

⚠ **안드로이드 전경만 배율이 다른 건 실수가 아니에요.** 런처는 108dp 중 **안쪽
72dp(66%)** 만 보여 주고 거기에 원·스퀘어클 마스크를 씌워요. 그 「보이는 틀」
안에서 iOS 와 같아 보이려면 마크가 틀의 67% 여야 하니 캔버스 기준으로는
0.66 × 0.67 ≈ 44% 예요. 캔버스에 67% 로 그리면 원형 마스크가 카피바라를 잘라요 —
바꿀 때 원형으로 깎아 확인해요(지금은 잘리는 픽셀 0).

스플래시 배경은 첫 화면과 같은 크림 `#F7F4ED`(`background.normal`)이에요 —
다른 색이면 `S0` 로 넘어가는 순간 바탕이 한 번 튀어요. 옛 값 `#F2E9DA`(2세대
`palette.bgMid`)는 어느 화면의 색도 아니었어요.

⚠ **스플래시도 안드로이드 12+ 가 원으로 깎아요.** 그래서 워드마크까지 안쪽 66%
안에 둬요 — `imageWidth` 는 화면에 보이길 바라는 폭이 아니라 그 1.5배예요.
원본은 내용이 6% 아래로 치우쳐 있어서, 앉힐 때 세로를 가운데로 되돌려요.
안 그러면 마스크가 워드마크 양끝(`M`·`y`)을 잘라요.

⚠ **배경을 지울 때 안쪽까지 반투명해지지 않게 해요.** 거리 90 을 넘으면 알파 1 로
못박고, 가장자리만 맞닿은 단색의 거리로 나눠요. 「이웃의 최대 거리」로만 알파를
내면 종이 질감 때문에 몸통이 236 쯤에서 멎고 눈·코 둘레가 106 까지 떨어져요 —
색으로 되돌리면 원래 배경 위에선 똑같아 보이지만, **모노크롬 아이콘은 알파만
봐요**. 얼룩진 몸통과 눈 둘레의 구멍이 그대로 드러나요.

## 로그인

소셜 3종(카카오·Google·Apple) 공식 색·마크 유지, 높이 48 · 간격 10.
Apple은 라이트 검정 / 다크 흰색. 예외 상태 없음.

### 3사 공식 규격 (2026-08-24)

「공식 색·마크 유지」를 각 사 가이드를 실제로 읽고 값까지 맞췄다.
**세 회사가 마크·간격·여백·문구를 각자 다르게 못박고 있어서, 줄마다 값이 다르다** —
보기 좋게 통일하지 않는다. 구현은 [`SocialButton.tsx`](../src/components/ds/SocialButton.tsx).

|            | 면 · 테두리               | 마크                     | 글자             | 마크~글자   | 좌우 여백   | 문구 (허용 목록)                         |
| ---------- | ------------------------- | ------------------------ | ---------------- | ----------- | ----------- | ---------------------------------------- |
| **카카오** | `#FEE500`                 | 24 (심볼 19.2×18.1)      | 16 = 48÷3        | 8           | 16          | **카카오 로그인** / 로그인               |
| **Google** | `#FFFFFF` + `#747775` 1px | 20 (그라디언트 G)        | 14 = 규격 그대로 | iOS 12 / 10 | iOS 16 / 12 | Google 계정으로 **로그인** / 가입 / 계속 |
| **Apple**  | `#000000`                 | 15.85 (로고 12.90×15.85) | 20.64 = 48×43%   | 10          | 16          | **Apple로 로그인** (`ko_KR` · `sign-in`) |

- **글자 크기는 통일할 수가 없다.** 애플 HIG 는 커스텀 버튼의 글자를 「높이의 43%」로
  **요구**하고(권장이 아니다 — `need to use the same proportions`), 카카오는 「레이블
  세로 길이 ≤ 높이의 1/3」로 **막는다**. Pretendard 한글의 ink/em 이 0.88 이라
  20.64 × 0.88 = 18.2 로 카카오 상한 16 을 넘고, 둘 다 높이 대비 **비율** 규칙이라
  버튼을 키워도 같이 커진다(카카오 상한 37.8% < 애플 요구 43%). 그래서 줄마다 다르다
- **애플 로고는 Medium 사이즈다.** 애플이 Small·Medium·Large 를 두는 이유가
  「match logo sizes in **all the sign-up buttons** you display」라서다 — 옆 줄이
  카카오 17.69 · Google 20.00 인데 Small 은 15.85 로 혼자 작았다. Medium 20.73 이
  Google 과 나란히 선다(애플 자체 렌더는 15.5 ≈ Small 이지만, 그건 애플 버튼 하나만
  놓고 볼 때의 값이다)
- **굵기는 셋 다 500 이다.** 애플 공식 렌더에서 **획 두께 ÷ 글자 ink 높이**를 재면
  0.1090 인데 Pretendard Medium 이 정확히 0.1090, SemiBold 는 0.1282(+18%)다 —
  처음 쓰던 600 은 공식 버튼보다 두꺼웠다. 구글이 규격으로 못박는 Roboto Medium 도
  같은 단이라 셋이 한 굵기로 모인다
- **이제 규격에서 벗어난 값이 없다** (2026-08-24). 색·마크·문구·크기·굵기·서체·
  여백·radius 가 전부 각 사 규격대로다
- **카카오는 심볼과 레이블의 검정이 다르다** — 심볼 `#000000` · 레이블 `#000000 85%`
- **Google 마크는 2025년에 그라디언트로 바뀌었다.** conic gradient 라 벡터로 못 그려서
  구글이 배포하는 PNG 원본을 그대로 쓴다 (`assets/brand/google-g.png`)
- **Apple 로고도 애플 공식 아트워크다** (2026-08-24). Apple Design Resources 의
  「Sign in with Apple Logo」 중 **Left-aligned / White / Small** 의 경로를 한 글자도
  고치지 않고 쓴다(`icons/AppleMark.tsx`). HIG 가 「Apple Design Resources 에서 받은
  아트워크만 쓰고 **직접 그리지 말라**」고 못박기 때문이다 — 그전까지 쓰던 Wanted 세트
  글리프가 바로 그 「custom Apple logo」였다(형태 96.3% 일치 · 가로세로비 2.8% 좁음).
  크기는 「**파일 높이 = 버튼 높이**」 규칙에서 나온다: 파일 44 안의 글리프 14.532 →
  버튼 48 에서 15.85
- **문구를 한글로 쓰는 것은 셋 다 규격 안이다** — 카카오는 가이드 표에 국문 칸이 있고,
  애플은 `locale=ko_KR` 로 애플이 직접 렌더한 문자열이며, 구글은 원문이 현지화를
  「permitted and encouraged」로 적는다. 셋 다 **우리가 번역한 말이 아니다**
- **서체도 셋 다 각 사가 지정한 것이다** — 카카오 「OS 별 기본 시스템 서체」 ·
  애플 「Prefer the system font」 · 구글 「Roboto Medium」. 앞의 둘은 `fontFamily` 를
  **비워 두는 것**이 곧 규격이고, iOS 에서는 그것이 SF Pro(한글 Apple SD Gothic Neo)라
  애플이 렌더한 공식 버튼과 같은 서체가 된다. ⚠ **그래서 이 화면의 버튼 셋만
  Pretendard 를 쓰지 않는다** — 워드마크·태그라인·약관 줄은 그대로다
- **마크 크기가 갈리는 이유**: 카카오·애플은 「컨테이너에 비례해 키우라」는 규정이고
  구글은 절대값 규정이다(표준 높이 40·44 어느 쪽에서든 마크는 20)

## 온보딩 (대화형)

- 질문 좌측 Fill 6%, 답변 우측 Primary 22% 틴트
- 지난 턴은 질문 opacity 0.48 / 답변 0.62, 삭제하지 않고 위로 쌓임
- 새 질문이 나타나면 입력창 바로 위까지 자동 스크롤
- `다음`은 입력·선택이 있어야 활성. 선택사항 항목은 우상단 건너뛰기
- 진행 표시(1/8) 없음

## 홈

날짜 + 알림 → 하루 돌아보기 CTA → 이번 주 감정 → 오늘 일정.
일정이 많으면 콘텐츠만 스크롤. 완료 일정은 취소선 + Label Neutral로 목록에 남아요.
`N개 남음`은 미완료 수예요.

## 일정

- 추가: `＋ 추가` → 하단 입력 바 + 키보드. `＋` 또는 키보드 `완료`, 빈 값이면 둘 다 비활성
- ⋮ 메뉴: 바깥 탭하면 닫힘, ⋮ 다시 누르면 열림. 수정 / 삭제(negative)
- 수정: 같은 입력 바 + Primary 링 + `일정 수정` 캡션, 취소 / 저장
- 삭제: 확인 모달 1회 (되돌리기 없음)
- 순서 변경: 꾹 누름 → 해당 행만 떠오름, 드롭하면 즉시 기본 상태
- 완료: 체크박스 한 번, 감정 입력 없음

## 일기

1. 일정 확인(읽기 전용, 완료만 초록 체크) → `다음`
2. 감정 선택 3×3, 하나 선택해야 CTA 활성
3. 대화: 자유 입력 / 선택형 / 척도 3종. 선택형·척도에서는 입력창을 숨기고 `보내기`로 확정.
   「직접 쓸게요」를 고르면 입력창으로 전환
4. 정리 중 → 일기 확인(제목 없음, 날짜·날씨·감정 + 본문 + 그날 일정) → `일기 저장하기` / `직접 고치기`
5. 저장 완료: 행동카드가 없으면 안내만, 있으면 쉼터와 동일한 카드를 함께 보여줘요

## 쉼터

R1 진입(카드 진입점 하나) → R2 날짜별 카드 → R3 상세.
R2 수행 전 `◷ 아직 하지 않았어요` + `했어요` → 직후 느낀 점 compact 입력 → 저장 후 읽기 블록 + `고치기`.
`수행 취소`로 되돌리면 입력도 초기화돼요.
캘린더는 카드 있는 날 텍스트 대비 + 수행한 날 초록 dot + 선택일 아웃라인. 배경 채움·범례 없음.

## 보관함

캘린더 / 리스트 뷰는 제목 우측 아이콘 스위처로 전환.
A1은 선택한 날의 일기+일정, A2는 검색 + 감정 필터 9종(가로 스크롤).
A3 상세는 읽기 레이아웃 + ⋮ 수정·삭제.

## 리포트

주간만. 도넛·비율·범례 없이 7일 감정 흐름 + 요약 2줄, 지표는 `9개 완료` 형태.
완료율·%·분석 같은 표현을 쓰지 않아요.

## 마이

M1 프로필 + 앱 설정(알림 설정 `매일 21:00` / 기본 정보 수정) + 지원 + 계정 + 회원 탈퇴.
M2 알림 설정은 휠 피커 + `완료` 하나.
M3 기본 정보 수정은 현재 값 목록(1줄 말줄임) → 항목 선택 → 그 항목만 수정 → `저장`.
저장은 값이 그대로면 비활성, 바꾸면 활성, 원래 값으로 되돌리면 다시 비활성. 저장 후 M3 복귀.
