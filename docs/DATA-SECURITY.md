# 데이터 보안 — 기기에 무엇을 어떻게 눕히는가

> ⚠ **이 문서는 구현 계약이지 사용자 약속이 아니다.** 상류가 `S1` 에서 암호화
> 문구를 지웠다 — 「확정 범위가 아닌 약속을 화면에 쓰지 않는다」(`RULES.md`).
> **문서가 생겼다고 화면에 약속이 되살아나면 안 된다.** 여기 적힌 것이 사용자에게
> 보여도 되는 문장이 되려면 법률 검토(상류 `R-14`)와 §2 결정을 지나야 한다.

이 문서가 막고 있던 것: **MMKV 영속화**(M3 · 첫 로컬 쓰기). 일기 본문과 감정이
민감 필드라, 어디에 어떤 상태로 눕힐지 정하지 않고는 `react-native-mmkv` 를 깔 수
없었다([`DISCUSSION.md`](DISCUSSION.md) §2 · [`TASKS.md`](TASKS.md)).

**이 문서는 기기 쪽만 정한다.** 서버 보관·삭제는 BE 답이 필요해 아래 「아직 못
정한 것」에 남는다(§1-5).

## 1. 무엇이 민감한가 — 필드 네 등급

「민감」을 한 단어로 뭉뚱그리면 **전부 암호화하거나 아무것도 안 하게 된다.** 네
등급은 성격이 다르고, 등급이 곧 저장 위치를 정한다.

| 등급                  | 무엇                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 왜                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **A · 세션 비밀**     | 모멘토리 access/refresh token                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | 유출되면 **남이 그 사람 계정으로 서버에 말한다.** 이미 SecureStore 에 있다                                            |
| **B · 자유 텍스트**   | `Diary.body` · `Diary.babaView` · `Retro.messages` · `Moment.text` · `ActionCard.{situation,targetAction,reflection}` · `Schedule.title` · 온보딩 「기타」 둘 · `Report.{insight,flow}` · `Treasure.content`(오늘의 보물함 · 2026-10-05 · 서버 `treasures` · 기기에는 화면 상태로만) · `Letter.{quote,insight}`(바바의 편지 · 2026-10-27 · 서버 `letters` · 일기를 지우면 함께 지워진다 · 기기에는 화면 상태로만 · 계측에는 본문 · 작은 일 문장을 보내지 않는다) · `Worry.content`(걱정상자에서 맡겨둔 걱정만 · 2026-10-13 · 서버 `worries` · 흘려보낸 걱정은 어디에도 남지 않는다) · **`Wish.content`(소원 연꽃 · 2026-11-04 · 🟡 BE `dev` · 서버 `wishes` · ⚠ 유일하게 다른 사용자에게 보이는 글 — 아래 1-1)** · `WeeklyHappiness.content`(주간 행복 일곱 칸 · 2026-11-06 · 🟡 BE `dev` · 서버 `weekly_happiness_entries` · 이번 주만 쓰고 지난 주는 읽기만 · 기기에는 화면 상태로만 · 계측에 넣지 않는다) · `Inquiry.content`(문의 · 서버 `inquiries` · 회신 이메일 · OS · 앱 버전과 함께) · AI 가 쓴 글(🟡 `dev` — 직접 쓴 일기의 사건 `diaries.events_json` · 주간 공책 글 `weekly_report_writings`) | **그 사람이 쓴 말 그대로다.** 일기 한 편이 새면 하루가 통째로 샌다. 회고 대화는 서버가 그 사람을 위해 생성한 문장이다 |

**`User.nickname` 은 B 가 아니라 C 다** — 본인이 정한 호칭이고 화면 곳곳에 뜬다.
다만 실명일 수 있으므로 **로그·계측에는 넣지 않는다**(3절).

### 1-1. 소원 — 처음으로 **남에게 보이는 글** (2026-11-06 대조 · BE `dev` `#86` · 운영 미배포)

지금까지 B 등급은 전부 「그 사람만 보는 글」이었다. 소원 연꽃은 아니다. BE `dev` 코드에서 확인한 것:

- **보이는 범위** — 띄운 소원은 7일(`Wish.FLOATING_PERIOD`) 동안 **다른 사용자의 연못**에 뜬다. 작성자 이름 ·
  id 는 응답에 없다(`PondWish` = id · 글 · 남은 날 · 빛 · 같이 빈 여부). 하루 하나(`uq_wishes_user_date`)
- **띄우기 전 심사** — 위기 낱말 · 욕설 규칙을 먼저 보고 **Gemini 에 글을 보낸다**(`GeminiWishReviewer`). 심사가
  이름 · 연락처를 지운 글로 고칠 수 있고, 그 뒤 연락처 정규식을 한 번 더 건다. 통과하면 30분짜리 심사 토큰을 준다
- **신고** — 신고하면 **그 작성자의 소원 전부가 신고한 사람에게 안 보인다**(`pickForPond` · `countFloatingAuthors`).
  **서로 다른 세 사람**이 신고하면 내려간다(`WishReport.TAKE_DOWN_REPORTERS = 3` · `taken_down_at`). 신고를 되돌려도
  이미 내려간 소원은 다시 뜨지 않는다. 관리자가 보는 화면 · 신고 사유는 없다
- **지우기는 소프트 삭제다** — 「지우기」는 `deleted_at` 만 찍는다. 기한이 지난 소원 · 내려간 소원도 행이 남는다
  (「지난 소원」 목록이 그것을 읽는다). **행이 실제로 지워지는 것은 탈퇴(cascade)뿐이다**
- 기기에는 남기지 않는다(화면 상태뿐) · 계측에는 글자 수 · 심사 결과만([`ANALYTICS.md`](ANALYTICS.md))

⛔ 팀이 정할 것은 §5-4 에 모았다.

## 2. 어디에 눕히는가 — 저장소 셋

```
SecureStore            A(세션 토큰) · MMKV 암호화 키                 ← OS 키체인/키스토어
MMKV "momentory.enc"   B · C                                        ← 암호화. 키는 위에서 온다
MMKV "momentory.cache" D                                            ← 평문. 지워져도 잃는 것이 없다
AsyncStorage           쉼 추천의 기억(날짜 · 연달아 닫은 횟수)          ← 평문. 등급 밖 — 본문·감정이 없다
                       설명 카드를 본 쉼터(쉼터 이름 목록)              ← 위와 같다
메모리(Zustand)         전부 — 위는 그 스냅샷이다
```

> **2026-11-06 대조 — 위는 목표 구조이고, 지금 기기에 실제로 있는 것은 아래다.** MMKV 는 아직 없다
> (`package.json`). B · C 는 **메모리에만** 산다.
>
> | 저장소            | 키                                          | 담는 것                                        | 로그아웃 · 탈퇴 때                    |
> | ----------------- | ------------------------------------------- | ---------------------------------------------- | ------------------------------------- |
> | SecureStore       | `momentory.session`                         | 모멘토리 access/refresh token · 내부 사용자 ID | 지운다                                |
> | SecureStore       | `momentory.calendarSync.<userId>`           | 캘린더 화해 해시 · 범위 · 마지막 시각          | 지운다(`clearSyncState`)              |
> | AsyncStorage      | `momentory.rest-recommendation`             | 쉼 추천 — 날짜 · 연달아 닫은 횟수              | 지운다                                |
> | AsyncStorage      | `momentory.rest-guide`                      | 설명 카드를 본 쉼터 이름                       | 지운다                                |
> | AsyncStorage      | `momentory.report.threeDayHintWeeks`        | 「3일 이상」 안내를 보여 준 주(날짜)           | 지운다(`clearThreeDayHint`)           |
> | AsyncStorage      | `momentory.music`                           | 고른 배경음악 · 틀어 두었나                    | 비운다(`useMusic.reset`)              |
> | AsyncStorage      | `home.weatherIntro.v1.<userId>`             | 홈 날씨 안내를 봤나(`"1"`)                     | ⚠ **지우지 않는다** — 아래 §4         |
> | AsyncStorage      | `momentory.store-review`                    | 별점 창을 마지막으로 요청한 시각               | 일부러 남긴다 — 기기 단위 간격이다    |
> | AsyncStorage(SDK) | Amplitude SDK 몫                            | 임의 기기 ID · 전송 대기 이벤트                | SDK 신원만 초기화(`resetAnalytics`)   |
> | OS 알림 예약      | `momentory.reminder.*` · `momentory.once.*` | 알림 문안 · 시각 — 편지 작은 일 알림은 그 제목 | 인증 상태를 보고 취소(`reminders.ts`) |
>
> 위치는 기기에 남기지 않는다 — 반올림 좌표를 요청 본문으로 보내고 버린다(`src/lib/location.ts`).
> 주간 행복에 쓴 글은 기기에 남지 않는다(화면 상태뿐) — 2026-11-06 부터 **서버에 남는다**(`weekly_happiness_entries` · 위 B 등급).

**진실은 언제나 서버이고, 기기의 것은 캐시다.** 그래서 기기 저장이 깨졌을 때
할 일은 「고치기」가 아니라 「버리고 다시 받기」다 — 아래 실패 규칙이 전부 그
전제 위에 있다.

### 2-1. 왜 MMKV 를 둘로 가르는가

한 통에 넣고 통째로 암호화하면 **비민감 플래그를 읽는 데도 키가 필요해진다.**
키를 못 읽는 상황(2-3)에서 `onboardingCompleted` 하나 때문에 진입 분기가 막히면,
사용자는 **답을 다 했는데도 온보딩을 다시 본다.** 등급 D 를 따로 두면 그 경로가
키와 무관해진다.

반대로 D 통에 B·C 를 얹지 않는다 — 「지금은 안 민감하니까」로 시작한 값이
나중에 본문을 물고 들어온다.

### 2-2. 암호화 키는 SecureStore 에 산다

```
32바이트 무작위 → base64 → SecureStore["momentory.mmkv.key"]
                              keychainAccessible: WHEN_UNLOCKED_THIS_DEVICE_ONLY
```

- **키를 코드·번들·서버에 두지 않는다.** 번들에 두면 APK 를 푼 사람이 그대로
  읽는다(`CONTRIBUTING.md` 「값을 다루는 세 등급」 ①의 교훈이 그대로 적용된다)
- **`THIS_DEVICE_ONLY` 다** — 기기 백업·기기 이전에 키가 따라가지 않는다. 새 기기는
  키가 없으니 옛 파일을 못 읽고, **서버에서 다시 받는다.** 이것이 우리가 원하는
  결과다: 기기를 옮기는 것은 복원이 아니라 재동기화다
- **`WHEN_UNLOCKED` 로 충분한 이유**: 잠긴 기기에서 도는 코드가 없다. 알림은 OS 가
  미리 예약해 두고 띄우므로(`lib/notifications.ts`) 우리 코드가 깨어나지 않는다.
  ⚠ 백그라운드 동기화·아웃박스 재생이 생기면 이 전제가 깨진다 —
  그때 `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY` 로 내린다
- 키 생성은 `expo-crypto` 의 `getRandomBytesAsync` 다. **`Math.random()` 을 쓰지
  않는다** — 예측 가능한 키는 키가 아니다

### 2-3. 키를 못 읽으면 — **평문으로 떨어지지 않는다**

기기 오류·키체인 접근 실패·복호 실패는 실제로 일어난다. 그때 규칙:

1. **암호화 저장소를 열지 않는다.** B·C 는 그 세션 동안 **메모리로만** 산다 —
   앱을 끄면 사라지고, 다음 실행에 서버에서 다시 받는다
2. **평문 통(`cache`)에 대신 쓰지 않는다.** 「이번 한 번만」이 그대로 굳는다
3. **사용자에게 오류를 띄우지 않는다.** 할 수 있는 일이 없다(`RULES.md` 4).
   앱은 서버를 보며 그대로 돈다 — 느려질 뿐 멈추지 않는다
4. **개발 빌드에서만 사유를 남긴다** — 키 없음 · 복호 실패 · 저장소 열기 실패를
   가른다(`kakaoSdk.ts` 의 `warnInDev` 와 같은 자리). **값은 남기지 않는다**

같은 이유로 **손상된 암호화 통은 고치지 않고 비운다.** 부분 복호로 살린 데이터는
어디까지 진짜인지 아무도 모른다.

## 3. 로그·계측에 남기지 않는 것

이미 정본이 있다 — [`CONTRIBUTING.md`](CONTRIBUTING.md) 「값을 다루는 세 등급」과
[`ARCHITECTURE.md`](ARCHITECTURE.md) §6. 여기서는 저장 관점으로 한 줄만 덧붙인다:

**등급 B 는 어떤 형태로도 로그에 닿지 않는다.** 토큰·본문·자유 텍스트·닉네임.
그래서 예외를 삼킬 때도 `error.message` 까지만 남기고 요청 본문은 남기지 않는다
(`http.ts` · 각 어댑터의 `warnInDev`).

⚠ **2026-09-05 갱신 — 계측이 실제로 붙었고, 감정도 보내지 않는다.** 「감정은 `emotion_id`
숫자만 보낸다」는 계측 설계 전의 문장이었다. Amplitude 파일럿의 허용 목록은
**감정·욕구 코드와 이름을 아예 뺐다**([`ANALYTICS.md`](ANALYTICS.md) 「수집 경계와 한계」 ·
`features/analytics/events.ts` 가 타입과 런타임 두 겹으로 막는다). 나가는 것은 이벤트
이름과 허용된 속성, 그리고 **서비스 내부 사용자 ID** 뿐이다.

## 4. 지우기 — 로그아웃과 탈퇴

**목록의 단일 지점은 `auth.ts` 의 `clearUserScopedStores` 하나다**
(`ARCHITECTURE.md` §3-5). 새 저장소가 생기면 **그 함수에 합류**하는 것이 규칙이고,
이 문서는 그 목록이 무엇이어야 하는지를 정한다.

| 무엇               | 로그아웃 | 탈퇴 | 어떻게                                                             |
| ------------------ | -------- | ---- | ------------------------------------------------------------------ |
| SecureStore 세션   | ✅       | ✅   | `deleteItemAsync` + 서버 refresh token 폐기(`logoutApi`)           |
| **MMKV 암호화 키** | ✅       | ✅   | 키를 지우면 **남은 파일은 복호 불가능한 바이트**가 된다            |
| MMKV `enc` 통      | ✅       | ✅   | `clearAll()` — 키 삭제만 믿지 않는다(아래)                         |
| MMKV `cache` 통    | ✅       | ✅   | `clearAll()`                                                       |
| 메모리 store 열둘  | ✅       | ✅   | 지금 이미 비운다(2026-11-06 · 「여섯」은 낡은 수였다)              |
| 아웃박스 큐(M3-3)  | ✅       | ✅   | 남기면 **다음 사용자의 세션으로 이전 사용자의 쓰기가 재생**된다    |
| 예약된 알림        | ✅       | ✅   | `features/my/model/reminders.ts` 가 인증 상태를 보고 취소한다      |
| 쉼 추천의 기억     | ✅       | ✅   | `clearRecommendationMemory` (`features/rest/data/recommendMemory`) |
| 설명 카드의 기억   | ✅       | ✅   | `clearGuideMemory` (`features/rest/data/guideMemory`)              |
| 캘린더 화해 상태   | ✅       | ✅   | `clearSyncState(userId)` (`features/calendar/data/syncStateStore`) |
| 리포트 안내의 기억 | ✅       | ✅   | `clearThreeDayHint` (`features/report/data/hintMemory`)            |
| 배경음악의 기억    | ✅       | ✅   | `useMusic.reset()` 이 빈 값을 쓴다                                 |
| 홈 날씨 안내 기억  | ⛔       | ⛔   | `clearWeatherIntroMemory` 는 있는데 **아무도 부르지 않는다**       |

**키만 지우고 파일을 남기지 않는다.** 「복호할 수 없으니 없는 것과 같다」는
맞지만, 남은 파일은 **용량으로 남고 포렌식 대상으로 남는다.** 둘 다 한다 —
`clearAll()` 이 실패해도 키가 없어 못 읽고, 키 삭제가 실패해도 내용이 없다.

**순서는 「비우고 나서 상태를 바꾼다」** — 로그아웃 판정이 먼저 서면 그 사이에
화면이 빈 store 를 읽고 그린다.

⚠ **우리가 보장할 수 없는 것**: OS 백업(iCloud·Google 백업)에 이미 올라간 사본,
파일시스템의 삭제 흔적. `THIS_DEVICE_ONLY` 키가 백업을 따라가지 않으므로
**백업본은 복호 불가**지만, 「완전히 지워졌다」고 말할 수는 없다.

> ✅ **2026-09-12 갱신 — 서버 쪽도 닫혔다.** 2026-08-21 에는 「탈퇴 엔드포인트가 없다」였는데
> 그 사이 BE 가 냈고(`#42`) FE 가 2026-08-23 에 붙였다. 지금 서버에서 일어나는 일:
>
> - **로그아웃** — `POST /api/v1/auth/logout` 이 **제출한 refresh token 하나만** 폐기한다.
>   다른 기기의 세션은 살아 있고, 같은 토큰을 두 번 보내도 결과가 같다
> - **탈퇴** — `DELETE /api/v1/users/me`(`features/auth/data/withdrawApi.ts`). 서버가
>   카카오 연결 해제·**애플 revoke** 를 먼저 하고 `users` 행을 지우며, 나머지 테이블은
>   `ON DELETE CASCADE` 로 함께 지워진다(BE `V16`·`V22` · 목록은
>   [`PLAY-DATA-SAFETY.md`](PLAY-DATA-SAFETY.md)). **구글 연결 해제는 앱이 한다**
>   (`revokeAccess()` — 서버가 든 구글 토큰이 없다)
> - **화면** — 마이 바닥의 「회원 탈퇴」가 **눌린다**. 되돌릴 수 없는 행동이라
>   확인 시트에서 「회원탈퇴」를 **글자 그대로 따라 써야** 실행된다
>
> **2026-11-06 대조 — 새 테이블도 전부 cascade 다.** BE `dev` 마이그레이션 `V24`~~`V38` 이 만든 테이블
> (`treasures` · `rest_records` · `inquiries` · `worries` · `notifications`(개인 알림만) · `notification_reads` ·
> `user_onboarding_responses` · `user_onboarding_goals` · `letters` · `letter_actions` · `wishes` · `wish_joins` ·
> `wish_reports`(신고자 · 작성자 둘 다) · `wish_rule_agreements` · `weekly_report_writings` · `weekly_happiness_entries`)는 모두 `users` 에
> `ON DELETE CASCADE` 로 걸려 있고, `UserWithdrawalService` → `UserDeletionService` 는 `users` 행 하나를 지운다.
> 운영(`main`)에는 그중 `V24`~~`V28` 의 다섯만 있다. ⚠ 탈퇴하면 **문의(`inquiries`)도 함께 사라진다**(§5-4).
>
> ⛔ **남은 것 둘**: (1) 애플 `.p8` 이 운영에 채워지기 전에는 revoke 가
> `500 APPLE_REVOKE_UNAVAILABLE` 로 실패한다 — 그때 탈퇴는 **연결 해제 없이** 지나간다
> ([`DISCUSSION.md`](DISCUSSION.md) §1-10). (2) 「모든 기기 세션 끊기」는 여전히 없다.
> (3) **Amplitude 는 이 cascade 밖이다** — 이미 보낸 이벤트는 내부 사용자 ID 로
> 별도 삭제 요청해야 한다.

### 5-1. `ageBand`·`gender` 를 정말 받을 것인가

서버에 간다. **그런데 리포트·추천 어디에도 쓰이지 않는다.**

> 때까지 묻지 않는다」이지만, 질문을 내리는 것은 상류 화면 결정이라 FE 가 못

> 잘 맞추는 데만 사용하며, 다른 사람에게 공개되지 않아요." **그 문장을 그대로
> 계약으로 삼는다**: 회고 질문 생성 밖(통계·광고·추천 학습·외부 공유)으로 쓰지

> 화면 · `draft.ts` 둘 · 서버 필드 둘이다.

**2026-10-25 · 온보딩 v2.** 나이는 지금처럼 **정수**로 받는다(사용자 결정 · 나이대 아님). 새 화면

## 6. 이 문서가 열어 주는 것 — MMKV 착수 조건

**5-1·5-2 가 닫히면 바로 시작할 수 있다.** 5-3 은 서버 쪽이라 기기 영속화를
막지 않는다.

착수할 때 함께 들어오는 의존성 둘 — 둘 다 아직 없다
(2026-11-06 대조: `expo-crypto` 는 **이미 있다** — 애플 nonce · 계측 UUID 가 쓴다. 남은 것은 `react-native-mmkv` 하나다):

| 패키지              | 무엇에                                                                    |
| ------------------- | ------------------------------------------------------------------------- |
| `react-native-mmkv` | 통 둘(`enc` · `cache`). 네이티브라 **dev client 재빌드**가 필요하다       |
| `expo-crypto`       | 암호화 키 생성(`getRandomBytesAsync`). `Math.random()` 로 대신하지 않는다 |

붙이는 순서 제안: **① 등급 D(`cache`) 부터** — 키가 필요 없어 위험이 가장 낮고,
`onboardingCompleted` 를 기기에 남기는 것만으로 「앱을 껐다 켜면 온보딩을 다시
본다」의 마지막 흔적이 사라진다. **② 키 배선과 `enc` 통** · **③ 일기·회고 이관**.
