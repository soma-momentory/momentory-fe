**온보딩 채팅 = 회고 채팅**이 같은 틀이고, 홈·보관함·리포트·마이는 목록·카드 문법을 공유한다.

| | 담당 | 화면 | 성격 |
|---|---|---|---|
| **축 A — 대화** | | 25장 | 진입 2 · 온보딩 11 · 회고 12 |
| **축 B — 목록** | | 15장 | 홈 5 · 보관함 6 · 리포트 1 · 마이 3 |

두 축이 갈라지는 지점은 **M2 부터**다. M1(공용 컴포넌트)까지는 순서가 있어서

## M1 — P0 컴포넌트 13종 + 테스트 기반

**여기가 앱 전체의 지렛대다.** 채팅 컴포넌트군 하나가 온보딩과 회고 두 축을 다 덮는다.

### M1-0 · 테스트 기반 — 가장 먼저, 혼자

```
Jest + @testing-library/react-native + jest-expo
npm run test          CI 에 test 단계 추가
```

**컴포넌트보다 먼저 한다.** 나중에 붙이면 그때는 테스트하기 어려운 구조가 이미 굳어 있다.
첫 테스트는 `ScreenBackground` 렌더 하나면 충분하다 — 배선이 되는지만 본다.

### M1-1 · 기본 3종 — 혼자 (M1-2·M1-3 을 막는다)

| 컴포넌트 | 핵심 |
|---|---|
| `AppText` | `typography.styles` 8종 프리셋. `fontFamily` 로 굵기 지정 |
| `AppButton` | h54 r14 · `motion.press`(scale .98) + `accentFillPress` · 변형 6종(primary/kakao/apple/google/ghost/disabled) |
| `Card` | fill `card` · **r18 · 테두리 ink 10% · 여백 15/17** (`momentory.css` `.card`) |

**테스트로 고정할 것**: 프리셋이 토큰 값을 그대로 쓰는가 · 탭 대상이 44pt 이상인가 ·
Reduce Motion 이면 이동/스케일 없이 색만 바뀌는가.

`app/index.tsx` 의 인라인 스타일을 여기로 흡수하고 검수 화면을 정리한다.

### M1-2 ∥ M1-3 — 여기서부터 둘이 나눈다

### `InputRow` — ✅ M2 에서 만들었다 (2026-08-07 · v2 `.tfield`)

v2 `momentory.css` 가 `.tfield` 를 정의해 추측이 필요 없어졌다 — **h56 · r14 ·
테두리 ink 24% 1.5px**, 포커스는 `.tfieldOn`(primaryDeep + 3px 링). 카운터

물건이라 `tokens.mvp.ts` 의 `timeField` 로 분리했다 — 값은 전부 `tokens.mvp.ts`
에 있고 상류가 흡수하면 지운다.

## 둘이 부딪히는 곳

파일이 겹치면 리베이스가 지옥이 된다. 아래는 **미리 합의하고 들어가는 지점**이다.

| 파일 | 왜 겹치나 | 어떻게 |
|---|---|---|
| ~~`app/_layout.tsx`~~ | ~~둘 다 Provider 를 추가한다~~ | ✅ **닫힘 (2026-08-06)** — Provider 를 `src/lib/providers.tsx` 로 옮겼다. `_layout.tsx` 는 라우트 설정만 남았고 더 건드릴 일이 없다 |
| `src/lib/providers.tsx` | Provider 를 늘리는 곳이 여기가 됐다 | 삽입 **순서가 정해져 있다**(파일 주석). 자기 자리에 넣고, 넣기 전에 알린다 |
| `package.json` | 둘 다 의존성을 넣는다 | 넣기 전에 알린다. 락파일 충돌은 `npm ci` 후 재생성이 제일 빠르다 |
| `src/components/primitives/` | M1 공용 | M1 이 끝날 때까지 **한 사람 소유**. 그 뒤엔 변경 시 알린다 |
| `src/design/theme.ts` | — | **아무도 안 고친다.** 생성물이고 CI 가 검사한다 |
| `src/design/tokens.mvp.ts` | 상류가 흡수하면 사라진다 | **MVP css 에는 있는데 `theme.ts` 에 없는 값만** 여기 담는다(카드 r18 등). 그 외에는 상류 `lib.mjs` 를 고친다. 화면 코드에 값을 흩지 않는 것이 이 파일의 목적이다 |

**PR 은 작게.** 컴포넌트 2~3개 또는 화면 2~3장이 한 PR 이다.
M1 전체를 한 PR 로 묶으면 리뷰가 불가능하고 충돌 범위도 커진다.
