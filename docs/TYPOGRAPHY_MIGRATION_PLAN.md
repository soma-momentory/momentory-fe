# 타이포그래피 정본과 단계별 이관 계획

2026-10-23 조사. 이 문서는 **목표 기준과 변경 계획**이다. 1단계 공통 토큰과 홈 v2만 시범 적용한다.
제품 디자인의 우선 기준은 `docs/DESIGN.md` §2의 새 정본이며, 아래 파일별 현황은 조사 당시 코드다.
이전 디자인 결정과 차이가 있으므로 시각 비교와 iOS·Android 실기기 검증을 거쳐 화면별로 적용한다.

**1단계 적용 상태:** 공통 역할 토큰과 홈 v2의 교보손글씨·1.5배 대응을 적용했다. Expo Web Lab의
375·390·402·430pt 기본/1.5배 경계 검사와 관련 Jest를 통과했다. Android Pixel 8 에뮬레이터
(약 411dp)에서 1.0/1.5배 홈, 도크 열기·요일 선택·스크롤 끝과 회고 이동을 확인했다.
iOS는 미검증이다. Android에서 펼친 도크의 요일 누름 영역은 약 42dp 폭으로 프로젝트의
44dp 목표보다 작아 후속 개선이 필요하다. 아래 화면별 표는 이관 전 조사 결과를 유지한다.

## 3. 제안하는 공통 토큰

폰트 패밀리는 역할을 드러내는 두 묶음으로 정의한다: `bodyFont.regular/medium/semibold/bold`
→ 네 Pretendard 파일, `handFont.regular` → `KyoboHandwriting2025lyb`. 화면에서 `fontWeight`
숫자나 파일 이름을 직접 쓰는 경우를 줄이고, `Text` 변형은 **가족·크기·행간을 함께** 정한다.

`label1Hand`, `body1ReadingHand`, `body1ReadingHandLg`는 의미가 섞인 기존 이름이다.

이관한다. 전역 `fontFamily`를 먼저 한 번에 바꾸면 이관하지 않은 화면까지 달라지므로
**새 역할 토큰을 추가하고 화면별로 선택한 후** 오래된 별칭을 제거한다. Studio 폰트 선택
목록과 승인 JSON은 해당 운영 화면을 바꿀 때 같이 갱신한다.

### 버튼과 탭 결정 근거

교보는 단일 웨이트라 400/600의 굵기 차이가 없다. 그래도 손글씨가 모멘토리의 주된
디자인 언어이므로 **짧은 버튼·탭은 교보를 우선**한다. 선택 상태는 색만이 아니라
표시·접근성 상태를 함께 쓴다. 길거나 빠르게 판단해야 하는 라벨에서만 Pretendard를
비교한다. 홈 시범 적용에서는 CTA·일정 추가·요일·리마인더·일정 제목을 교보로 유지하고,
긴 빈 상태 안내에만 Pretendard를 제한적으로 쓴다. 적용 시
동일 문구·동일 컨테이너에서 줄바꿈, 높이, 대비, 375pt/1.5배 가독성을 나란히 기록한다.

## 4. 확대 정책과 현재 1.24~1.3배의 원인

현재 `typography.ts`는 `widthScale = clamp(windowWidth/393, 1, 1.12)`,
`maxFontScale = 1.3 / widthScale`을 정한다. `Text`가 이를 `maxFontSizeMultiplier`로
전달하고 `useEffectiveFontScale()`도 `min(systemFontScale, maxFontScale)`을 반환한다.
따라서 시스템 1.5배에서 393pt 이하는 최대 **1.30**, 402pt는 약 **1.27**, 411pt는 약
**1.24**, 430pt는 약 **1.19**다. 1.24~~1.3배는 폭 393~~411pt 조건에서 맞지만 모든 폭의
값은 아니다. `typeScale`의 iOS 1.2와 넓은 화면 보정, iOS 버튼 추가 1.15는 **기본
폰트 크기를 바꾸는 별도 배율**이다. 시스템 설정의 확대 비율과 혼동하지 않는다.

| 역할                           | 목표 확대 정책                                                   | 레이아웃 동반 변경                                                                                        |
| ------------------------------ | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 본문·일기·AI 대화·긴 안내·입력 | 시스템 1.5배까지 온전히 반영. 2.0배는 다음 목표                  | 줄 수와 카드 높이 자연 증가, 입력 최대 높이와 키보드 회피 재측정, 세로 스크롤                             |
| 화면 제목·손글씨 문구          | 1.5배까지 반영. 더 큰 설정도 잘림 없이 줄바꿈·스크롤 가능성 검증 | 종이 조각 폭·높이와 옆 아이콘 재배치; 긴 제목은 정보용 Pretendard                                         |
| 버튼·칩·탭                     | 1.5배까지 반영. 2.0배는 컴포넌트별 검증 후 확대                  | `height`→필요한 `minHeight`와 세로 패딩, 칩 줄바꿈, 탭바 높이 증가·스크롤 영역 조정; 터치 영역 최소 44×44 |
| 장식 텍스트                    | 실제 정보나 행동을 담으면 위 규칙 적용                           | 순수 장식일 때만 접근성 트리에서 숨김, 필수 정보 삭제 금지                                                |

한 숫자를 1.3→1.5로 올리는 것만으로 완료되지 않는다. 공통 `Button`의 48/40/32 높이,
`Chip`의 36 고정 높이·`numberOfLines={1}`, 하단 탭바, `TextField`의 최대 높이,
홈 `DatePaper`·`HeroCard`·`WeekDock`의 확대 계산, 쉼터 2열 카드와 Studio 고정 크기를
함께 수정해야 한다. `PreviewFontScaleContext`는 Lab에서 1.5를 모사하지만 **네이티브의
실제 폰트 메트릭이나 OS 확대 정책을 증명하지 않는다**. 공통 `Text` 밖의 `TextInput`과
직접 `RNText` 사용처도 별도 조사한다. 2.0배는 우선 지원 가능성을 탐색하되, 실제
통과 전에는 지원 완료라고 적지 않는다.

## 5. 두 줄바꿈 문제의 변경안

1. **쉼터 설명의 마지막 음절:** `REST_CONTENTS`의 카드 설명에는 두 줄을 강제하는
   `\n`이 있고, `RestContentGrid`는 2열 카드·22 간격·좁은 내부 패딩에 설명을 놓는다.
   큰 글씨나 좁은 폭에서는 강제 두 번째 줄이 다시 접혀 한 음절만 남을 수 있다.
   어떤 카드·문구가 실제 사례인지는 동일 기기 캡처로 확인한다. 그 뒤 카드의 실측
   텍스트 폭을 기준으로 1열 전환을 우선하고, 설명은 의미 단위의 줄바꿈만 남긴다.
   원문 정보는 삭제하지 않는다. 일률적인 축소·말줄임·`overflow: hidden`은 쓰지 않는다.
2. **홈 히어로 안내의 단어 중간 분리:** `HeroCard` 리마인더는 `maxWidth: 160`이고
   바바는 오른쪽 아래 절대 배치다. 알림을 끈 경우 문장 전체를 폭에 맡기며,
   알림을 켠 경우 시각 뒤에만 `\n`을 둔다. 손글씨·1.5배에서 한국어 어절 중간이
   갈릴 수 있다. 문구 의미를 유지한 채 텍스트 영역을 바바의 실측 경계와 함께
   재배치하고, 필요한 폭을 못 얻는 크기에서는 리마인더를 한 줄 더 쓰거나 바바
   위쪽의 넓은 행으로 옮긴다. 강제 줄바꿈은 시간 뒤 같은 의미 경계에만 남기고,
   어절 단위 분리·버튼 및 바바와의 경계 교차를 확인한다.

## 6. 적용 순서와 확인 게이트

1. **기준선 확보:** 현재 375·390·402·430pt 및 작은 Android 폭에서 기본/1.5배,
   홈·쉼터·보관함·리포트·마이·회고를 캡처한다. Lab과 네이티브 결과를 구분한다.
   화면별 긴 합성 문구와 빈/오류 상태를 준비하며 개인 기록은 사용하지 않는다.
2. **토큰과 공통 컴포넌트:** 두 패밀리 역할 토큰을 추가하고 `Text`·입력·버튼·칩·탭의
   확대 규칙과 유동 높이를 검증한다. 기존 별칭은 이관 기간 유지한다.
3. **읽기 화면:** 회고 대화·다음 날 편지·긴 일기·보관함 상세·긴 온보딩 안내에서만
   Pretendard의 가독성 이점을 비교한다. 긴 문구와 키보드·스크롤을 먼저 통과시킨다.
4. **주요 탭:** 홈 히어로/일정/도크 → 쉼터 카드/추천 → 리포트 → 마이 순으로 화면별
   폰트와 줄바꿈을 이관한다. 각 단계에서 Lab 승인 값과 운영 공유 뷰를 함께 맞춘다.
5. **정리:** Gaegu 참조가 모두 사라지고 시각 검증이 끝난 뒤에만 등록·파일 제거를
   별도 변경으로 검토한다. `gothic` 예외와 오래된 손글씨 본문 토큰, 문서의 과거
   사용처를 갱신한다. 한꺼번에 폰트 파일이나 서체 정의를 교체하지 않는다.

각 단계의 통과 기준: 텍스트 누락·말줄임·한 음절 고립·요소 경계 교차 없음,
버튼/탭의 이름·상태·탐색 순서 유지, 44×44 이상 터치 영역, 스크롤 끝 접근 가능,
기본/1.5배에서 라벨 가독성·대비 확인. 타입 검사·린트·관련 Jest/Playwright와
기존 홈 기능 회귀를 수행하되, 웹 통과를 네이티브 통과로 대체하지 않는다.

### 수동으로 남는 확인

- Android와 iOS 실기기에서 실제 시스템 글자 1.0·1.5배 및 가능한 가장 큰 단계,
  작은 화면·긴 합성 문구·동적 날짜/닉네임을 비교한다. iOS는 이번 조사에서 실행하지 않았다.
- 교보와 Pretendard의 실제 글리프 높이, 받침·숫자·특수문자, 버튼 세로 정렬,
  입력 커서, 화면 전환 후 폰트 깜빡임을 확인한다.
- 홈 도크의 고정/본문 스크롤 전환, 날씨 스티커가 있는 히어로, 쉼터 1열 전환,
  보관함·회고 긴 글 끝까지 읽기를 확인한다.
- VoiceOver/TalkBack에서 버튼·탭 이름과 선택 상태, 큰 글씨일 때 초점 순서와
  장식 텍스트의 숨김 여부를 확인한다. 접근성 서비스가 켜졌다는 것만으로 통과로 표시하지 않는다.

이번 문서 작업은 코드 수정·새 UI 적용·네이티브 화면 검증을 포함하지 않는다.
