# 모멘토리 계측 감사

## 트리거와 범위

- 변경된 기능의 이벤트 정의와 호출 경로부터 검사한다. 전체 이벤트 사전/앱 감사를 명시적으로 요청받았을 때만 범위를 넓힌다.
- `docs/ANALYTICS.md`, `src/features/analytics/`, 관련 UI/테스트에서 이벤트명, 시점, 허용 속성, 중복 방지, 실패·취소 상태, 개발/운영 게이트를 대조한다.

## 검사 근거

- 이벤트 사전·코드 위치·테스트 결과를 증거로 제시한다. 런타임 도착이나 전환율은 실제 연결과 조회 권한이 확인된 경우에만 별도로 표시한다.
- `claude mcp list`(또는 이 세션의 MCP 도구 목록)에 Amplitude가 없으면 `MCP 미연결 / 운영 데이터 미검증`이라고 쓴다. SDK 존재를 데이터 접근 증거로 취급하지 않는다.
- 개인 일기·감정 원문, 자유 텍스트, 토큰이 속성·로그·외부 질의에 포함되는지 확인한다. 실제 사용자 데이터를 외부로 보내지 않는다. 대시보드 검토는 연결과 명시적 조회 요청이 있을 때만 공식 `analyze-dashboard` 도입을 검토한다.

## 결과 형식

`범위`, `연결 상태`, `이벤트별 사전↔호출 근거`, `누락/중복/개인정보 위험`, `확인 방법`, `미검증`으로 보고한다. `정적 확인`과 `운영 데이터 확인`을 구분한다.

## 실행 비용과 수정 승인

- 기본은 로컬 읽기와 좁은 테스트로 외부 비용 0이다. Amplitude MCP 조회, 새 계측 배포·데이터 전송은 권한과 비용 확인이 필요하다.
- 감사만 요청했으면 코드·계정·대시보드를 바꾸지 않는다. 명시적 수정 요청이면 해당 코드만 고친다. 원격 조회·전송은 별도 명시적 허가를 받는다.

## 예시

`/momentory-analytics-audit 이번 주 감정 선택 화면의 이벤트와 개인정보 경계를 점검해줘.`
