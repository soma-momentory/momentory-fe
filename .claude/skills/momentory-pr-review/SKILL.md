# 모멘토리 변경 리뷰

## 트리거와 범위

- 지정 PR 또는 로컬 diff의 변경 파일과 직접 영향받는 경로만 검토한다. 전체 앱 검수는 명시적 요청이 있을 때만 수행한다. 기준 브랜치·미커밋 변경을 먼저 확인해 출처를 구분한다.
- 화면 변화는 `momentory-screen-qa`와 `momentory-design-audit`, 문구는 `momentory-ux-writing`, 계측은 `momentory-analytics-audit`의 관련 항목만 참고한다. 작은 diff에 모든 스킬을 일괄 실행하지 않는다.

## 검사 근거

- 각 발견 사항에 파일·줄·재현 시나리오·영향을 붙인다. 코드상 가능성과 재현된 결함을 구분한다. 웹 Lab/테스트 통과로 네이티브 동작을 단정하지 않는다.
- 필요 최소의 타입 검사·린트·관련 테스트만 실행하고 기존 실패·미커밋 변경을 분리한다. 개인정보·토큰·실제 일기/감정 데이터는 외부 리뷰 도구에 보내지 않는다.

## 결과 형식

`기준/범위`, `발견 사항(심각도 순, 파일·줄·영향·재현 근거)`, `실행한 검사와 결과`, `미검증`, `판단에 필요한 질문`을 보고한다. 발견 사항이 없으면 그렇게 명시하고 남은 위험을 짧게 적는다.

## 실행 비용과 수정 승인

- 기본은 로컬 diff와 좁은 검사로 외부 비용 0이다. 전체 E2E, 클라우드 빌드, 외부 MCP 조회는 별도 비용·권한이 있다.
- 리뷰만 요청했으면 제품 코드를 수정하거나 댓글·PR을 게시하지 않는다. 사용자가 수정 요청을 하면 해당 범위에서 고친다. PR 댓글/게시와 외부 전송은 명시적 허가가 있어야 한다.

## 예시

`/momentory-pr-review 현재 미커밋 화면 변경만 리뷰하고 회귀 위험을 알려줘.`
