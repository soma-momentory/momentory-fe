# 모멘토리 디자인 감사

## 실행 조건과 기준

- 감사 요청은 읽기 전용으로 수행한다. 사용자 요청 없이 UI나 디자인 토큰을 수정하지 않는다.
- 실제 기준은 `docs/DESIGN.md`, `src/design/ds/`, `src/components/ds/`, 화면 코드 순서로 확인한다. `docs/spec/`은 화면별 문안·동작의 보조 근거다. 현재 변경 중인 파일과 미커밋 변경을 포함해 판단한다.
- 사용자가 제시한 목표와 현재 정본이 다르면 둘을 나란히 적고 결정을 요청할 지점으로 보고한다. 현재 서체 정본은 **로그인(`S1`)까지 앱 전체 교보손글씨(`KyoboHandwriting2025lyb`)**다(2026-11-08 · Pretendard는 2026-11-09에 지웠다). Gaegu는 2026-11-01에 지웠다(`docs/DESIGN.md` §2 · `src/design/ds/typography.ts`). 교보손글씨는 굵기가 하나라 굵기로 위계를 만든 곳은 결함으로 본다. 정본과 다른 요청을 자동 수정의 근거로 삼지 않는다.
- Expo 고유 디자인 시스템 점검이 필요하면 설치된 `expo-design-system`의 `SKILL.md`와 `references/audit.md`를 참고한다. 일반 예시보다 모멘토리의 기존 토큰과 공통 컴포넌트를 우선한다.

## 체크리스트

- 글자: 실제 화면별 폰트 파일, 크기, 행간, 위계와 강조 방법이 정본과 맞는가? 시스템 글자 배율에서도 잘리지 않는가? Android에서 `fontWeight`만으로 굵기를 기대하지 않는가?
- 대비: 실제 글자/배경 조합과 상태별 대비를 확인한다. 본문 4.5:1, 큰 글자와 비텍스트 핵심 요소 3:1을 기준으로 삼되 장식·비활성 등 예외와 보조 텍스트의 실제 가독성을 구분한다. `src/design/ds/__tests__/contrast.test.ts`의 기존 보정을 확인한다.
- 조작: 누르는 영역의 실제 크기와 간격, 접근성 이름·상태, 색만으로 전달되는 정보가 없는지 확인한다. 44×44는 프로젝트의 터치 목표로 점검하고, 플랫폼 지침과 WCAG 최소 기준을 혼동하지 않는다.
- 시각 체계: `src/design/ds/` 토큰, `src/components/ds/` 공통 버튼·카드·텍스트·탭바, 모눈 배경, 그림자, 간격과 반경이 같은 역할에 일관되게 쓰이는가?
- 레이아웃: 작은 폭·큰 글씨·긴 한국어·빈 데이터에서 잘림, 겹침, 가려짐, 스크롤 누락이 없는가? 안전 영역과 하단 탐색을 확인한다.
- 디자인 랩: `expo-lab/src/` 미리보기가 실제 공유 뷰를 쓰는지, 시나리오와 운영 앱의 데이터·폰트·내비게이션 차이가 무엇인지 구분한다. Web 캡처만으로 iOS·Android 통과라고 쓰지 않는다.

## 결과 형식

감사 범위와 기준 화면·폭을 먼저 적는다. 발견 사항은 `심각도 | 화면·파일 | 증거(값/재현 조건) | 사용자 영향 | 권장 조치` 표로 보고한다. 디자인 정본과 사용자 목표의 충돌은 별도 `결정 필요`로 적는다. `확인함 / 추정 / 실기기 미확인`을 구분하고, 수정은 별도 요청으로 남긴다.

## 사용 예시

- `이 화면 타이포그래피 검사해줘. 홈 v2 375px과 큰 글씨를 봐줘.`
- `전체 앱 디자인 일관성 검사해줘. 탭별 모눈 배경과 하단 탐색을 비교해줘.`
- `리포트 카드의 대비와 터치 영역만 감사해줘.`
