# AI 회고·편지 품질 평가

## 트리거와 범위

- 요청된 프롬프트·화면·출력 형식만 검사한다. 전체 AI 흐름 평가는 명시적 요청에서만 수행한다.
- 가상 사용자와 합성 일기·감정 데이터만 만든다. 실제 사용자 일기, 감정 기록, 토큰, 로그를 외부 모델·MCP·Gateway로 전송하지 않는다. 외부 모델 호출은 합성 데이터라도 비용과 승인 조건을 확인한다.

## 검사 근거와 체크리스트

- 프롬프트·응답 파서·화면의 실제 코드, 관련 제품 문서와 `momentory-ux-writing`의 톤 기준을 근거로 삼는다.
- 합성 사례는 평범한 하루, 빈 입력, 긴 입력, 모호한 감정, 거절/실패, 위기 암시를 최소로 포함한다. 출력에서 사실 왜곡, 감정 단정, 지나친 위로·행동 강요, 진단처럼 보이는 표현, 사생활 노출, 편지 시점 혼동, 구조·길이 위반을 본다.
- 정적 검토와 모델 실행 결과를 분리한다. 실행하지 않았다면 품질 점수를 실측치처럼 말하지 않는다.

## 결과 형식

`대상/버전`, `합성 사례와 입력 출처`, `평가 방식(정적/로컬/외부)`, `기준별 통과·실패와 최소 재현`, `위험도`, `수정 제안`, `미검증`을 보고한다. 실제 데이터 미사용 여부를 명시한다.

## 실행 비용과 수정 승인

- 기본은 로컬 정적 검토로 외부 호출 비용 0이다. 로컬 테스트는 실행 시간만 든다. 외부 API·유료 모델은 모델, 호출 수, 예상 비용, 보낼 합성 내용을 밝힌 뒤 승인받는다.
- 평가만 요청했으면 프롬프트·화면·로직을 변경하지 않는다. 수정 요청이 있으면 지정 범위만 고친다. 실제 사용자 데이터의 외부 전송은 이 스킬에서 허용하지 않는다.

## 예시

`$momentory-ai-quality-eval 다음 날 편지 프롬프트를 합성 사례로 읽기 전용 평가해줘.`
