# 모멘토리 제품 여정 점검

## 트리거와 범위

- 요청된 여정 또는 최근 변경 화면만 살핀다. 전체 앱 여정 감사는 명시적으로 요청받았을 때만 수행한다.
- `docs/spec/`, 실제 라우트와 화면, `docs/ANALYTICS.md`의 이벤트 사전을 연결해 진입·가치 경험·이탈·재방문 지점을 그린다. 구현과 Design Lab Mock을 구분한다.
- 활성화·유지율 관점이 필요하면 로컬 `diagnose-activation`, `diagnose-retention`의 관련 질문만 참고한다. 숫자 없는 전환율·인과 관계를 만들지 않는다.

## 검사 근거

- 경로/상태/문구는 저장소 파일과 재현 화면으로, 실측 주장은 연결된 승인 데이터와 기간·분모·세그먼트로 뒷받침한다.
- Amplitude MCP가 없거나 데이터 조회가 허용되지 않으면 `계측 설계 검토`로 표시하고 이벤트 정의·누락·가설만 다룬다. 일기 본문과 감정 원문을 외부 도구에 보내지 않는다.

## 결과 형식

`검사 범위`, `여정 단계(진입→핵심 행동→복귀)`, `근거 파일/화면/이벤트`, `발견 사항(영향·재현)`, `가설과 검증에 필요한 데이터`, `미검증` 순서로 보고한다. 실측·관찰·가설을 따로 표기한다.

## 실행 비용과 수정 승인

- 기본은 로컬 파일 읽기와 필요한 화면 1개 확인이다. Lab 실행은 로컬 브라우저·개발 서버 시간만 사용한다. MCP 조회·실기기·외부 서비스는 별도 비용·권한을 확인한다.
- 감사 요청에서는 제품 변경을 적용하지 않는다. 사용자가 수정까지 요청하면 해당 범위에서 구현한다. 외부 데이터 조회/전송, 실험 게시·계정 생성은 별도 명시적 허가가 있어야 한다.

## 예시

`$momentory-product-journey 온보딩에서 첫 기록까지의 마찰을 코드와 이벤트 사전으로 점검해줘.`
