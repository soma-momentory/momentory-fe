## 남은 차이와 네이티브 확인

- 원본은 Claude Design의 UIKit 상태바를 가져오지만 Lab은 브라우저용 SVG 상태바를 그린다. 실제 iOS/Android의 시스템 상태바와 safe area는 기기에서 별도 비교해야 한다.
- 도크의 CSS `backdrop-filter: blur(20px)`는 공유 RN View의 반투명 배경으로 근사한다. 종이 `clip-path`, 복합 곡률, 일부 inset 그림자도 RN/SVG 근사여서 픽셀 단위로 같지 않다.
- 빈 일정 설명의 마지막 줄바꿈 위치가 원본과 한 글자 다르다. 폰트 렌더러와 행간 차이로, 읽기 가능성과 카드 높이는 맞춘 상태다.
- iOS/Android 번들 내보내기는 성공했지만 네이티브 화면을 실제 시뮬레이터·에뮬레이터에서 렌더링한 것은 아니다. WebP 합성, Gaegu 글리프, 그림자/elevation, 중첩 ScrollView의 터치 제스처와 safe area는 해당 환경에서 남은 검증 항목이다.

Lab 자체를 네이티브에서 열려면 저장소 루트가 아닌 `expo-lab/`에서 `npx expo start`를 실행하고 Expo CLI의 `i`(iOS Simulator) 또는 `a`(Android Emulator)를 누른다. Expo Go는 프로젝트의 SDK 57과 일치하는 버전이 필요하다. 이 컴퓨터에는 Xcode 27.0과 사용 가능한 iOS 시뮬레이터가 있지만, Android `adb`/에뮬레이터는 설치 또는 PATH 설정이 확인되지 않았다. `npx expo run:ios`/`run:android`는 Lab에 네이티브 디렉터리를 생성하고 빌드하므로 이번 웹 비교 작업에서는 실행하지 않았다. 운영 앱의 빌드 설정은 변경하지 않았다.

이번 확인에서 Expo Web 화면이 정상 렌더링됐고, Web/iOS/Android 번들 내보내기와 루트·Expo Lab·Vite Lab 타입 검사, 린트, 기존 앱 Jest 101개 스위트/1,314개 테스트, Vite Lab 빌드가 통과했다. 번들 내보내기 성공은 실제 iOS/Android 설치·구동 성공을 뜻하지 않는다.
