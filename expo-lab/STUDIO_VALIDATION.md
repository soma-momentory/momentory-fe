# Momentory 디자인 편집기 — 사용법과 검증 기록

## 디자인 편집기 (Expo Lab 전 화면 · 2026-11-02)

다섯 탭 화면만 고치던 Design Studio 를 **실제 앱 전 화면**으로 옮겼다. 셸이 실제 앱(`app/` 라우트 전체)을 프레임(같은 출처 iframe) 두 벌로 띄우고 — **A = 지금 앱(승인본)**, **B = 시안** — 오른쪽에 편집 패널(`src/design-editor/DesignEditorPanel.tsx`)을 끼운다. 패널에서 고친 값은 B 프레임의 **모든 화면**에 걸린다.

### 어떻게 걸리나

1. 패널은 시안을 `localStorage["momentory.lab.designDrafts"]`(`DesignDraft[]` · `src/lab-contract.ts`)에 곧바로 쓰고, 편집을 ~300ms 모아 `onDraftChanged(id)` 를 부른다.
2. 셸은 그때 B 프레임을 다시 불러온다. 프레임 부트스트랩은 `Platform.OS` 를 기기 값으로 맞춘 **뒤에**, 앱 모듈을 불러오기 **전에** `applyDesignDraft(config)` 를 부른다.
3. `applyDesignDraft` 는 `config.designDraftId` 의 시안을 읽어 `src/design/ds/*` 가 내보낸 객체와 `src/design/studioDesign.ts` 의 `approvedDesign`(JSON) 객체를 **제자리에서** 바꾼다. 컴포넌트는 모듈이 올라올 때 `StyleSheet.create` 로 값을 굳히므로 그 전에 바꾸면 모든 화면이 시안 값으로 그려진다. 앱 코드는 바뀌지 않는다.
4. 결과(적용한 키 · 건너뛴 키와 이유)는 프레임의 `window.__MOMENTORY_LAB_DESIGN__` 에 남고, 패널의 「바꾼 값 → 화면에 걸렸는지 확인」이 읽는다.

⚠ 토큰 모듈은 `applyDesignDraft` **안에서** `require` 한다(`tokenModules.ts`). `typography.ts` 가 모듈이 올라오는 순간 `Platform.OS` · 창 폭으로 `typeScale` 을 재기 때문에, 정적 import 로 두면 부트스트랩이 플랫폼을 맞추기 전에 재 버린다.

어느 잎이 「계산·참조」인지는 소스를 봐야 알기 때문에 `src/design-editor/tokenSourceMap.json`(생성물)이 든다. **리터럴이 아닌 잎만** 적으므로 토큰 **값**이 바뀌어도 낡지 않고, 계산식·참조가 생기거나 없어질 때만 다시 만든다 — `node expo-lab/scripts/apply-tokens.mjs --source-map`. 낡으면 `npm run test:design-apply-tokens` 가 실패하고, 낡은 채로 열면 어긋난 `text.*` 잎은 「소스 지도가 낡았다」로 읽기 전용이 된다.

`text.*` 의 `fontSize` · `lineHeight` 는 소스의 `style("medium", 16, 24)` 인자(**기준 pt**)로 편집한다. 프레임은 그 기기의 `typeScale`(폭 보정 × iOS 1.2)을 곱해 넣는다 — 앱이 하는 셈과 같다.

키는 export 이름부터의 경로다(`primary.heavy` · `label.normal` · `text.title2.fontSize` · `homeV2.color.paper`). 묶음 경로(`color.primary.heavy` · `metrics.space.lg` · `typography.title2.fontSize`)도 받아 정규 키로 바꾼다.

**화면 속성(Studio)** — 옛 Design Studio 의 등록표 47개(`studioRegistry.ts`) — 홈·쉼터·보관함·마이·리포트 View 가 `studioApproved.json` 에서 읽는 값. 색은 6자리 hex, 숫자는 등록된 범위, 서체·정렬·자산은 선택지만 받는다. 지금 라우트가 그 다섯 화면이면 그 화면을 먼저 연다.

### 패널 — 처음 보는 사람이 따라가는 순서

맨 위 「순서」 네 칸이 지금 단계를 굵은 테두리로 보인다(시안 없음 → 1 · 바꾼 값 없음 → 2 · 바꾼 값 있음 → 3 · 코드 반영 탭 → 4).

1. **시안 만들기** — 시안이 없으면 편집 탭 대신 안내 카드만 보인다: 「시안은 지금 앱(A)을 건드리지 않고 고쳐 보는 사본이에요. 만들면 B 화면에만 적용돼요.」 + 이름 칸(`accessibilityLabel="시안 이름"`) + 「새 시안 만들기」 · 「시안 파일 열기」 · 만들어 둔 시안.
2. **값 고치기** — 기본 보기는 **「이 화면에 쓰인 값」**: 지금 프레임(시안 프레임 → B → 첫 프레임)에 **보이는** 요소의 계산된 스타일(글자색 · 바탕 · 테두리 · 글자 크기 · 행간 · 글꼴 · 모서리 · 안쪽 여백 · 사이 간격)을 모아 같은 값의 공통 값만 묶음별로 보인다(`screenUsage.ts`). 줄마다 「N곳」, 마우스를 올리면 그 값을 쓰는 요소가 프레임에 상자로 보인다. 프레임이 불린 뒤 · `lab:route` 뒤 · 라우트가 바뀐 뒤 500ms 에 모으고, 화면이 바뀌는 동안(MutationObserver) 1초에 한 번 다시 모은다. 다섯 화면이면 그 화면에 보이는 요소의 화면별 값(Studio 등록표)도 아래에 둔다.
   **화면에서 눌러 고르기**(시안이 있으면 기본으로 켜짐): B 의 요소를 누르면 패널 위에 **요소 카드**가 열린다 — 「이 요소: 글자 『오늘 일정』」 + 그 요소의 값마다 같은 값의 공통 값(또는 화면별 값)을 바로 고치는 칸과 「이 값은 이 화면 12곳 · 앱 전체에서 함께 써요」 한 줄. 같은 값이 없으면 「앱 코드에 직접 적힌 값이라 여기서 못 바꿔요」. 시안 없이 고르면 「먼저 시안을 만들어요」 + 「시안 만들고 이 요소 고치기」(만들어도 카드가 그대로 이어진다). 테두리 · 상자는 앱 DOM 을 바꾸지 않고 프레임 `body` 끝에 붙였다 떼는 덮개로 그린다.
3. **B 화면에서 확인** — 편집은 ~300ms 모아 B 만 다시 불린다. 「바꾼 값 N」 탭이 A → B 전후를 모으고 하나씩 되돌린다.
4. **AI에게 넘기기** — 아래.

시안은 화면 보기(한 화면 · A/B)와 상관없이 하나다 — 한 번 만들면 모든 화면에 걸린다. 세밀하게 맞출 땐 한 화면, 최종 확인은 A/B.

**모든 값 목록(고급)** — 「모든 값 목록 보기」를 펴면 「모든 공통 값 (601)」(검색 · 종류 · 묶음 · 바꾼 값만 · 고칠 수 없는 값도 보기)과 「화면별 값」(다섯 화면 · 레이어)이 있다. 묶음은 자주 쓰는 아홉(글자색 · 면 · 브랜드 초록 · 상태 색 · 감정 색 · 간격 · 모서리 · 글자 스타일 · 홈 전용)만 먼저 보이고 나머지는 「묶음 더 보기」. 모든 묶음에 한국어 이름이 있다(`GROUP_LABELS` — 빠지면 `tokens.test.ts` 가 잡고, 화면에는 「기타」로 모인다).

**값의 짝 — 어림짐작이다.** 화면은 값의 이름을 남기지 않으므로 같은 값으로 찾는다. 숫자는 이름으로 좁히고(글자 크기는 `fontSize` 잎, 모서리는 `radius` 잎, 간격은 `space` · `cardPadding` · `padding/gap/inset/margin` 잎), 후보 순서는 이 화면 전용 묶음(고칠 수 있음) → 앱 공통(고칠 수 있음) → 이 화면 전용(고칠 수 없음) → 앱 공통(고칠 수 없음) → 다른 화면 묶음이다. 앞의 넷에 하나라도 맞으면 다른 화면 묶음의 우연한 일치는 뺀다.

⚠ **홈은 공통 값을 거의 안 쓴다.** 홈 v2 는 `src/design/ds/homeV2.ts`(묶음 「홈 전용」)와 `studioApproved.json` 의 `home.*` 를 쓴다 — 글자색 · 면 같은 공통 값을 바꿔도 홈은 탭바 정도만 바뀐다. 홈의 잉크(`homeV2.color.ink`)와 카드 면(`homeV2.color.card`)은 파일 안 상수(`ink` · `card`)를 가리키는 잎이라 여기서는 고칠 수 없고, 메모로 AI에게 넘긴다.

**모든 버튼 · 칩에 설명이 붙는다** — 웹은 `title`(마우스를 올리면 보인다), 네이티브는 `accessibilityHint`. 꺼진 버튼은 「지금은 못 써요 — 되돌릴 편집이 없어요」처럼 이유를 함께 말한다(`PanelButton` 의 `hint` · `disabledReason`).

### 코드에 반영 — AI에게 넘긴다

「코드 반영 · AI에게 넘기기」 탭의 주 버튼 **「AI에게 넘기기」**가 `momentory-handoff-<시안 이름>-<YYYYMMDD-HHmm>.json`(형식 `momentory-lab-handoff@1` · 정본은 `expo-lab/HANDOFF.md`)을 내려받는다. 바꾼 공통 값 · 화면별 값의 전후, 「AI에게 남길 메모」, 시안을 건 채로 지나간 화면과 「이 화면 메모」, 기기 · 데이터 세트가 실린다. 받은 파일을 AI(Claude Code · Codex)에게 「이 Lab 시안 반영해줘」라고 주면 된다(경로를 안 주면 다운로드 폴더의 가장 최근 파일을 찾는다) — 패널에 「요청 문장 복사」가 있다. A(지금 앱)는 코드가 바뀌고 앱이 다시 불러와진 뒤에야 바뀐다.

메모는 시안 타입을 바꾸지 않고 `localStorage["momentory.lab.draftNotes:<시안 id>"]`(`{ request, notes: {라우트: 메모}, visited: [라우트] }`)에 둔다. 참고 시안 이미지(`screens[].reference`)는 패널 prop `getReferences(route)` 로 주입한다 — 아직 비어 있다. 기기 · 데이터는 prop `labContext` 가 없으면 셸 주소(`#/screens?…`)에서 읽는다.

**직접 옮기기(고급)** — 「파일로 직접 옮기기 (고급)」을 펴면 예전 흐름이 그대로 있다. 「시안 파일 저장」(`{ version: 2, kind: "momentory-design-draft", name, tokens, studio }`) · 「파일을 새 시안으로 열기」 · 「파일로 지금 시안 덮어쓰기」, 그리고 저장소 루트에서:

```bash
npm run design:apply-tokens -- path/to/export.json           # 공통 값 — 통합 diff 만 출력
npm run design:apply -- path/to/export.json                  # 화면별 값 — 변경 목록만 출력
npm run design:apply-tokens -- path/to/export.json --write   # 검토 뒤 src/design/ds/*.ts 리터럴을 바꾼다
npm run design:apply -- path/to/export.json --write          # src/design/studioApproved.json
git diff -- src/design && npm run test                       # contrast.test.ts 가 대비 보정값을 지킨다
```

`apply-tokens.mjs` 는 TypeScript 파서로 ds 소스를 읽어 **키가 리터럴 하나로 정확히 떨어질 때만** 그 리터럴을 바꾼다(따옴표 · 줄 수 그대로). 계산식 · 참조 · 배열 · 최상위 값 · 두 파일에 같은 키 · 형식이 다른 값(색 자리에 색이 아닌 것) · 모르는 키가 **하나라도 있으면 아무 파일도 쓰지 않고** 키마다 이유를 낸다. 반영 뒤의 판정은 평소 게이트가 한다 — 특히 `src/design/ds/__tests__/contrast.test.ts`.

### 한계

- 값의 짝은 계산된 값 비교라 같은 값의 공통 값이 여럿이면 후보로 모두 나오고, 투명도를 섞어 그린 색은 못 찾는다. 글자 크기 · 행간은 기기 배율을 곱한 값도 약한 후보로 본다.
- 「이 화면에 쓰인 값」은 프레임 창 안에 **보이는** 요소만 센다 — 스크롤 아래 요소는 스크롤하면 다시 모인다.
- 프레임은 시안이 바뀔 때마다 다시 불린다 — 화면 안의 조작 상태(스크롤 · 연 시트)는 셸이 라우트만 이어 준다. 고른 요소의 상자도 그때 사라진다(카드는 남는다).
- 서체 교체는 `gothicFamily` 넷뿐이다. 앱 본문 서체(`fontFamily.* = HAND`)는 상수 참조라 코드에서 바꾼다(메모로 넘긴다).
- `scheduleDot` · `restRipple` 같은 최상위 값, `homeV2.color.ink` 처럼 파일 안 상수를 가리키는 잎은 편집할 수 없다.
- 대비 읽기 값은 `contrast.test.ts` 의 짝을 옮긴 것이다. 그 테스트에 짝이 늘면 `contrast.ts` 도 함께 늘린다.

#### 성능 관측

Windows Chromium 1440×1000, 동일 PC의 Expo 개발 서버, 단일 회차 관측이다. ### 검증 한계

- A/B는 같은 Mock 시나리오에서 시작하나, 각각의 터치 이후 내부 조작 상태는 독립적이다. `A 조작 초기화`/`B 조작 초기화`로 같은 출발 상태를 다시 만든다.
- 1.5배 글씨는 Web 모의 배율이다. 네이티브 iOS·Android 접근성 글꼴과 실제 터치는 이 작업에서 검증하지 않았다.
- 375pt·1.5배 홈 캡처에서 하단 콘텐츠가 도크 주변에 가까워진다. 실제 기기에서 스크롤 접근성과 잘림을 별도 확인해야 한다.
- 시각 기준선은 Windows Chromium에서 생성했다. 스크린샷 픽셀 비교 CI도 Windows에서 실행한다.
- 시각 비교는 폰 패널 시작점에서 고정된 CSS 픽셀 영역을 캡처한다. Windows 환경의 글꼴 가장자리 차이에 4% 픽셀 허용치를 두며, 큰 색·배치 변경은 계속 실패로 검출한다.
- 800×600px 브라우저에서는 세 패널을 세로로 스크롤해 접근할 수 있음을 Playwright에서 확인했다. 이는 미리보기의 375–430pt 기기 폭 검증과 별개다.
