# Momentory Expo Lab

웹에서 **앱의 모든 화면을 실제 앱 코드로** 처음부터 끝까지(스플래시 · 소개 · 로그인 · 온보딩 · 탭 · 회고 · 편지 · 쉼터 · 마이) 띄우고, 눌러서 흐름을 시험하고, 데이터 양 · 시각 · 서버 실패를 바꿔 보고, 디자인 시안을 승인본과 나란히 비교하는 **로컬 전용** 작업대다. 옛 캡처 Atlas(PNG 38장)는 지웠다 — 보이는 것은 전부 살아 있는 앱이다.

## 실행

```bash
npm ci
npm run lab:skins            # (선택) Android 에뮬레이터 스킨을 로컬 SDK 에서 복사 — 없으면 SVG 외형
npm run lab:web              # 포트 8085 고정(expo-lab/package.json) — 앱 개발 서버 8081 과 겹치지 않는다
```

`http://localhost:8085/` 를 연다. ⚠ `CI=1` 로 띄우면 Expo 가 파일 감시를 끄므로 코드를 고쳐도 다시 묶지 않는다.

## 구조 — 셸과 프레임 (2026-11-02 · 「전 화면」 네 갈래)

```
셸(최상위 창 · src/shell/ShellApp.tsx)
 ├ 왼쪽   화면 목록 — app/ 에서 생성 · 앱 순서의 접히는 묶음 · 검색 · 프레임이 지금 선 화면에 배지
 ├ 가운데 도구줄(레이아웃 설명 · 확대 · 돋보기) + 한 화면 / A·B 비교 / 모든 화면 / 기기 · 데이터별 / 상태별
 │        └ 실제 기기 외형(DeviceFrame) 안에 <iframe name={encodeFrameConfig(config)} src="/<라우트>">
 │          + 화면 위 참고 시안 층(ReferenceOverlay · 상태바 뒤)
 └ 오른쪽 화면 조건(+ 맨 아래 서버 요청 기록) · 디자인 편집(DesignEditorPanel) · 참고 시안(ReferencePanel)
프레임(iframe 안) = 실제 앱(expo-router 전체) + 가짜 서버 + 시안 적용 — 갈래 A·B·D
```

| 갈래    | 무엇                                              | 파일                                                 |
| ------- | ------------------------------------------------- | ---------------------------------------------------- |
| A       | 프레임 부트스트랩 — `window.name` 의 설정으로 앱  | `index.ts` · `src/frame/` · `metro.config.js`        |
| B       | 가짜 서버 · 데이터 세트 · `sampleParams`          | `src/fake-server/`                                   |
| C(여기) | 셸 · 라우트 목록 · 기기 외형 · 해시 상태          | `src/App.tsx` · `src/shell/` · `src/lab-devices.ts`  |
| D       | 디자인 시안 편집 · 적용                           | `src/design-editor/`                                 |
| 공유    | 프레임 설정 · 셸↔프레임 메시지 · 시안 모양 (계약) | `src/lab-contract.ts` — 바꾸면 네 갈래를 같이 고친다 |

셸은 프레임에 **설정을 iframe 이름으로** 싣고(`LabFrameConfig` — 데이터 세트 · 플랫폼 · 기기 · 고정 시각 · 시안 · 로그인 · 지연 · 실패 주소 · 오늘 다시 쓰기), **주소는 `lab:navigate` 로만** 옮긴다. 프레임은 `lab:ready` · `lab:route` · `lab:statusBar` · `lab:request` 를 보낸다(`src/shell/frameBus.ts` 가 단일 통로). 설정이 바뀌면 프레임이 새로 뜨되 **지금 서 있던 주소에서** 다시 시작한다 — 흐름 도중에 데이터 세트나 날짜를 바꿔도 제자리다. 프레임이 아직 준비 전이면(갈래 A 가 없을 때도) 메시지 대신 새로 띄운다.

### 상태는 URL 해시에

```
#/screens?route=/home&dataset=normal&platform=ios&device=iphone-16&layout=ab
         &now=2026-11-03T21:30:00%2B09:00&latency=1000&fail=/api/v1/reports&scale=1.3&repeat=0
         &zoom=1.5&nav=0&side=0
```

새로고침 · 뒤로/앞으로 · 주소 공유가 같은 화면을 다시 연다. 기본값은 적지 않는다. 형식은 `src/shell/hashState.ts`. 레이아웃은 `single` · `ab` · `grid` · `matrix` · `states`, 오른쪽 탭은 `panel=design`(기본) · `controls` · `reference`.

### 레이아웃 (위 탭 · 탭에 마우스를 올리면 한 문장 설명 · 도구줄 왼쪽에도 같은 문장)

- **한 화면** — 흐름 시험. 목록을 고르면 그 화면의 프리셋(아래)이 적용된다. 시안이 걸려 있으면 도구줄에 「시안 「X」 적용 중 · 바꾼 값 N개」와 **「원래대로 잠깐 보기」**(누르고 있는 동안 · `` ` `` 또는 `O` 키를 누르고 있는 동안)가 뜬다 — 같은 자리 아래에 승인본 프레임(`solo-base` · `designDraftId: null`)을 숨겨 두고 누르는 동안 위 시안을 `visibility: hidden` 으로 감춘다. 다시 불러오지 않으므로 앱 상태가 그대로이고, 숨은 프레임은 시안이 있을 때만 띄우며 주소는 `solo` 를 따라간다(「같이 이동」과 무관). 시안이 없으면 「시안 없음 — 지금 앱 그대로」 + 「시안 만들기」.
- **지금 앱과 비교 (A/B)** — 같은 라우트 · 같은 데이터. 기기 위 설명 줄이 「A는 지금 앱, B는 디자인 편집에서 고친 시안이에요 …」를 말하고, 기기마다 머리(「A · 지금 앱」 / 「B · 시안 「이름」」 + 「바꾼 값 N개」 = 시안의 `tokens` + `studio` 키 수)를 단다. 시안 수는 `DESIGN_DRAFTS_STORAGE_KEY` 를 **읽기만** 한다(`src/shell/draftInfo.ts` — 편집기의 `onDraftChanged` · `storage` 이벤트 · 1초 비교). 시안이 없으면 B 위에 「아직 시안이 없어서 A와 똑같아요」 + **「시안 만들기」**(디자인 편집 탭을 열고 `시안 이름` 칸에 커서 — 시안은 편집기가 만든다), 바꾼 값이 0 이면 「시안 「X」에 아직 바꾼 값이 없어요 …」. **「겹쳐서 차이 보기」**는 B 를 A 위에 겹치고 막대로 진하기를 바꾼다(겹친 동안 B 는 눌리지 않는다). 「두 화면 함께 이동」을 켜면 한쪽에서 누른 이동을 다른 쪽이 따라간다.
- **모든 화면** — 라우트마다 작은 실제 프레임. 화면 근처에 온 칸만 붙이고, 동시에 부팅하는 프레임은 4개로 묶는다. 칸을 누르면 한 화면으로.
- **기기 · 데이터별로 보기**(해시 `layout=matrix`) — 같은 라우트를 표의 모든 기기에, 또는 테스트 데이터 다섯에(칸 이름은 `datasets` 의 `label` — 「신규 사용자」 …). 축은 도구줄에서 고른다.
- **상태별로 보기**(해시 `layout=states` · 아래 절) — 같은 화면을 빈 계정 · 보통 · 많음 · 긴 문구 · 불러오는 중 · 불러오기 실패로 한꺼번에.

### 상태별로 보기 · 한 화면 「상태」 (`src/shell/screenStates.ts` · `StatesView.tsx`)

같은 화면을 상태마다 한 칸씩 띄운다. 칸 이름은 쉬운 말(「빈 계정」 · 「보통」 · 「많음」 · 「긴 문구」 · 「불러오는 중」 · 「불러오기 실패」)이고 아래 한 줄이 무엇을 바꿨는지 말한다. 칸은 화면 근처에 올 때만 붙고, 칸 수에 맞춰 줄마다 고르게 나눈다(6칸이면 3 + 3). **칸을 누르면 그 상태 그대로**(데이터 세트 · 서버 지연 · 실패 주소) 한 화면으로 연다.

| 칸            | 프레임 설정                                                    |
| ------------- | -------------------------------------------------------------- |
| 신규 사용자   | `new-user` — 로그인 전 · 온보딩 화면은 데이터 칸이 이것 하나뿐 |
| 빈 계정 …     | `empty` · `normal` · `many` · `long-copy`                      |
| 불러오는 중   | 보통 + `latencyMs` 60000                                       |
| 불러오기 실패 | 보통 + `failPaths` = **이 화면이 실제로 부른 서버 주소**       |

- **실패시킬 주소는 저절로 찾는다** — 셸이 `lab:request` 를 받을 때 그 프레임이 서 있던 화면 몫으로 모은다(`frameBus.pathsFor` · 두 단계 열기의 경유 화면 요청은 빼고). 주소는 id · 날짜 · 검색 조건을 뗀 접두사로 줄인다(`/api/v1/diaries?year=…` → `/api/v1/diaries`, `/api/v1/letters/2026-11-01` → `/api/v1/letters`). 바탕 칸(보통 · 신규 사용자)이 준비되고 1.5초 동안 새 주소가 없으면 그 목록으로 굳혀 실패 칸을 붙인다(그 전에는 「요청을 찾는 중」 자리). 칸 이름 아래에 실패시킨 주소가 보인다. 앱이 켜질 때 부르는 `/api/v1/users/me` 도 그대로 둔다 — 실패해도 앱 진입은 막히지 않는다(홈은 그대로 · 마이는 닉네임이 빈다).
- **요청이 없는 화면**(소개 · 로그인 …)은 불러오는 중 · 실패 칸을 빼고 「이 화면은 서버에 요청하지 않아요」 한 줄.
- **불러오는 중은 오래 머물지 않는다** — 앱의 요청 시간 제한(10 ~ 25초)이 지나면 앱이 실패 안내로 바꾼다. 칸 이름 옆 **「처음부터」**로 그 칸만 다시 띄운다. 두 단계로 여는 화면도 이 칸은 경유 없이 바로 연다(경유 화면의 응답까지 1분 늦어 목적지에 못 가므로 — `LabFrame` 의 `skipVia`).
- 한 화면 도구줄의 **「상태 ▾」**가 같은 상태를 폰 하나에 건다. 조건 패널에서 직접 바꾼 조건이면 「직접 고른 조건」으로 보인다.

### 확대 · 돋보기 (가운데 도구줄 — 확대 조작은 여기 한 곳)

- **화면에 맞게**(기본 · `zoom` 없음) — 무대에 꽉 차게, **크게도** 맞춘다(최대 200%). 한 화면은 무대 높이, A/B 는 두 대가 나란히, 기기 · 데이터별은 줄 수를 바꿔 가며 가장 크게 들어가는 배치(`src/shell/stageFit.ts`). 모든 화면은 맞춤이어도 30%.
- **100% · 125% · 150% · 200% · −/+**(계단 25% ~ 200%) — 해시 `zoom=1.5`(옛 0.1 ~ 2 값도 그대로 읽는다). iframe 은 늘 기기 CSS 크기 그대로이고 바깥 `transform: scale` 로만 키우며, 바깥 상자가 키운 크기만큼 자리를 잡아 스크롤이 맞는다.
- 단축키(셸에 포커스가 있고 입력칸 밖일 때 · 프레임 안에 포커스가 있으면 브라우저 확대를 건드리지 않는다): **Ctrl/⌘ + = / − / 0(화면에 맞게)**.
- **돋보기로 보기**(또는 **Z 를 누르고 있는 동안**) — 커서 주변을 둥근 렌즈(지름 220 · Shift+휠 120 ~ 420)에 2배(휠 · `[` `]` 로 1.5 ~ 4배)로 보인다. 렌즈 안은 프레임 문서의 **스냅숏**이다(`src/shell/magnifierSnapshot.ts` — 같은 출처 iframe 의 `<body>` 를 복제하고, react-native-web 이 `insertRule` 로 넣은 규칙을 `document.styleSheets` 에서 모아 싣고, 스크롤 위치 · 입력 중인 글자(`input.value`)를 옮겨 적는다 · 커서가 움직이면 150ms, 가만히 있으면 0.5초마다 다시 뜬다). **A/B 에서는 두 기기의 같은 자리**에 렌즈 둘. 렌즈를 쓰는 동안은 투명한 층이 마우스를 받으므로 앱이 눌리지 않는다(도구줄에 한 줄로 알린다) · Esc 로 끈다. 상태바 · 섬 · 홈 막대는 셸이 그리는 것이라 렌즈에는 앱 화면만 보인다.

### 참고 시안 (오른쪽 「참고 시안」 탭 · `src/reference/`)

피그마 · Claude Design 에서 뽑은 화면 그림을 실제 앱 위에 겹쳐 어긋난 곳을 찾는다. 오른쪽 탭 「참고 시안」(해시 `panel=reference`)에서 그림을 끌어다 놓거나 붙여넣거나 고르고, 비교 방법을 고른다 — **반투명 겹치기 · 다른 곳만 표시 · 밀어서 앞뒤 비교 · 옆에 나란히 놓기**. **R** 키(입력칸 밖)로 보이기 · 숨기기.

- 겹치는 층은 **주인공 프레임 하나**에만 — 한 화면은 그 폰, A/B 는 시안을 건 B. 기기 외형의 화면 상자 안, 셸이 그리는 상태바 · 가림 **뒤**에 놓아 시안의 상태바가 셸 상태바와 겹친다(`DeviceFrame` 의 `screenOverlay`). ⚠ 이 층을 z-index · isolation · opacity · transform · filter · clip-path 가 있는 상자로 감싸지 않는다 — 「다른 곳만 표시」(`mix-blend-mode: difference`)가 iframe 과 섞이지 않는다.
- **옆에 나란히 놓기**는 같은 기기 외형(상태바 · 가림 없이)에 시안 그림만 세운 칸을 하나 더한다(`reference-side-cell`) — 맞춤 배율은 칸 수를 하나 더해 한 줄로 맞춘다(`fitRow`).
- 어느 시안이 보일지는 지금 셸 라우트(패턴) · 그 프레임의 디자인 시안 · 플랫폼 · 기기로 고른다(`useReferencesFor`).
- 디자인 편집의 **「AI에게 넘기기」** 파일에 화면마다 그 시안 그림이 `{ name, dataUrl, align }` 로 실린다(`handoffReferencesFor` — `align.scale` 은 그림 1px 이 기기 화면에서 몇 CSS px 인지, `offsetX`·`offsetY` 는 그 뒤 더한 CSS px). 편집기에는 `labContext`(플랫폼 · 기기 · 데이터 세트)도 셸이 넘긴다.

### 패널 접기 · 좁은 창

- 머리줄 **「목록 보기」 · 「편집 칸 보기」**(aria-pressed), 패널 안의 **«(목록 접기) · ×(패널 닫기)** 로 양옆을 접는다 — 해시 `nav=0` · `side=0`. 접힌 자리에는 얇은 막대가 남고, 막대의 「목록 열기」 · 「조건 바꾸기」 · 「디자인 편집」을 누르면 그 탭으로 다시 열린다. 패널을 닫아도 디자인 편집기는 붙어 있어 고치던 상태를 잃지 않는다.
- 창이 **1180px 보다 좁으면**(브라우저 확대 등) 양옆이 저절로 접히고, 같은 버튼이 무대 위에 뜨는 **서랍**으로 연다(바깥을 누르거나 Esc 로 닫는다). 무대는 360px 아래로 줄지 않고, 기기 · 칸 이름은 한 줄 말줄임(칸은 120px 아래로 좁아지지 않는다)이라 글자마다 줄바꿈되지 않는다.

### 화면 목록

묶음(진입 · 소개 · 온보딩 · 탭 · 홈 시트 · 회고 · 편지 · 일기 · 쉼터 콘텐츠 · 마이 세부)은 **접혀 있고** 머리 줄(「＋/－」 · 이름 · 화면 수)을 누르면 펼친다. 여러 묶음을 함께 펼칠 수 있고(「모두 펼치기 / 모두 접기」), 펼친 묶음은 localStorage(`momentory.lab.shell.openSections`)에 남는다. 지금 화면의 묶음은 저절로 펼치고 그 줄을 강조한다. 검색어가 있으면 접힘을 무시하고 일치하는 묶음만 보인다.

### 화면 조건 패널

플랫폼 · 기기 · 테스트 데이터 · 로그인 상태 · **오늘 다시 쓰기**(켜면 오늘 이미 썼어도 일기를 다시 쓸 수 있다 · 끄면 실제 서버처럼 하루 1번) · **일기 쓰기 다시 시작**(`/retro/confirm` · 「직접 쓰기로 시작」 `/retro/write` 를 새로 띄운다) · 테스트 데이터 되돌리기(`lab:resetData` · 프레임이 못 들으면 셸이 직접 비운다) · **가상 시각**(아침 8:00 · 밤 21:30 · 03:59 = 04:00 하루 경계 직전 · **하루 넘기기 +1일 / 되돌리기 −1일**(시·분 유지) · 지금 시각으로) · 서버 응답(바로 · 1초 · 5초 늦게) · 일부 요청 실패시키기 · **글씨 크기**(작게 0.85× · 기본 · 크게 1.3× · 아주 크게 1.5× — 설정의 `textScale` 로 넘기고 프레임이 바로 적용한다 · 1.5 는 앱 상한 1.3 을 넘겨 배치를 점검하는 값) · 폰 화면 새로 불러오기. 뜻이 바로 안 보이는 조작에는 마우스를 올리면 한 문장 설명(`title`)이 뜬다. 맨 아래 접힌 **「서버 요청 기록 (개발용)」**(옛 「요청」 탭 · 해시 `panel=log` 는 이 패널로 연다)은 화면이 비거나 오류가 날 때 어떤 요청이 실패했는지 보는 자리이고, 실패(4xx · 5xx)가 있으면 접힌 머리에 빨간 숫자만 뜬다. 가짜 DB 는 `frameId:datasetId` 로 남으므로 하루를 넘겨도 쓴 기록이 쌓인다.

## 라우트 목록 — `app/` 에서 만든다

```bash
npm run lab:routes                                   # src/shell/routes.generated.ts 다시 쓰기
node expo-lab/scripts/gen-routes.mjs --check         # 어긋나면 실패 (jest 가 부른다)
```

`routes.generated.ts`(자동 · 57개) + `routeMeta.ts`(손 · 제목 · 묶음 · 순서 · 주의) = `routes.ts`. 새 라우트가 `app/` 에 생기면 `src/shell/__tests__/routes.test.ts` 가 「제목 없음」으로 깨진다 — `routeMeta.ts` 에 한 줄을 더한다.

**프리셋** — 바로 열었을 때 의미 있게 보이도록:

| 묶음                         | 세션 | 데이터 세트                                                                       |
| ---------------------------- | ---- | --------------------------------------------------------------------------------- |
| 로그인 · 소개                | 없음 | `new-user`                                                                        |
| 스플래시 `/`                 | 있음 | `new-user` + `/api/v1/users/me` 실패 — 「인터넷 연결을 기다리고 있어요」에 머문다 |
| 온보딩                       | 있음 | `new-user` (서버가 온보딩 필요)                                                   |
| 나머지                       | 있음 | 고른 것(처음 `normal`)                                                            |
| 동적 라우트(`[id]`·`[date]`) | —    | id 는 가짜 서버 `sampleParams`                                                    |

**두 단계로 여는 라우트**(`routeMeta.ts` 의 `openVia`) — 차갑게 열면 앱이 스스로 다른 곳으로 보내거나, **앞 화면이 받아 두는 데이터가 비어** 실제 흐름과 다르게 보이는 화면이다. 경유 화면을 먼저 열고, 그 화면의 데이터 응답(`lab:request`)이 온 뒤 `lab:navigate`(push)로 옮긴다.

| 라우트                                                   | 경유 → 기다리는 응답                           | 바로 열면                                          |
| -------------------------------------------------------- | ---------------------------------------------- | -------------------------------------------------- |
| `/diary/[id]`                                            | 보관함 → `/api/v1/diaries`                     | 보관함으로 돌아간다                                |
| `/home/schedule/[id]` · `/home/schedule/new`             | 홈 → `/api/v1/schedules`                       | 시트 뒤 홈이 빈다                                  |
| `/retro/confirm` · `/retro/write`                        | 홈 → `/api/v1/schedules`                       | 「적어둔 일정이 없네요」                           |
| `/retro/talk`                                            | 홈 → `/api/v1/schedules`                       | 첫 인사에 닉네임 · 오늘 일정이 빠진다              |
| `/letter`                                                | 홈 → `/api/v1/action-cards`(일기를 다 받은 뒤) | 편지마다 붙는 그날 일기 첫 줄이 빠진다             |
| `/letter/time`                                           | 홈 → `/api/v1/schedules`                       | 지금 편지 시각 대신 기본값(8:30)                   |
| `/rest/cards`                                            | 쉼터 → `/api/v1/action-cards`                  | 바람카드가 빈 목록                                 |
| `/my/nickname` · `age` · `gender` · `interests` · `rest` | 기본 정보 → `/api/v1/onboarding/options`       | 프로필이 오기 전에 칸을 채워 지금 값이 비어 보인다 |

흐름으로만 닿거나 가드 · 사용자 입력에 기대는 라우트는 프레임 위에 한 줄로 알린다(`hint`): `/retro/draft`(회고를 끝까지 — 가짜 서버 대본: 자유 입력 → 사건 고르기 → 감정 → 바람 → 완료) · `/retro/confirm`·`/retro/write`(오늘 일기가 있으면 `/retro/talk` 로 — 하루 넘기기로 새 날에서) · `/retro/done`(바람카드는 흐름에서만) · `/reading`(약 5초짜리 화면 — 끝나면 스스로 `/name` 으로) · `/about`·`/notify`(이름 단계에서 쓴 이름이 문장에 들어간다) · 소개의 감춘 두 장(`schedule` · `letter`). 앱은 진입 가드 때문에 「/ → 목적지」처럼 주소를 잠깐 거치므로 셸은 0.4초 동안 그대로인 **마지막 주소**를 프레임의 현재 화면으로 본다.

**차갑게 열기 점검(2026-11-02)** — 57개 라우트를 모두 바로 열어 본 것과 앱에서 그 화면을 여는 앞 화면(`router.push` 를 부르는 화면)부터 차례로 옮겨 온 것을 글자 · 입력값으로 견줬다. 달랐던 열 개에 `openVia` 를 새로 달았고(같은 칸을 쓰는 성별 수정도 함께 · 원래 있던 셋은 그대로 맞았다), 흐름 · 입력에 기대는 넷은 `hint` 로 알린다. 나머지는 같았다. 새 라우트를 더하면 같은 방식으로 견주고, 앞 화면이 받아 두는 데이터를 쓰면 `openVia` 를 단다.

## 디자인 편집기

오른쪽 패널에서 시안(여러 벌)을 만들고 DS 토큰 601개와 화면 속성 47개를 고치면 B(시안) 프레임의 모든 화면에 걸린다 — A 는 승인본. 「요소 선택」으로 B 화면의 요소를 눌러 속성이나 같은 값의 토큰을 찾는다. 「파일」에서 JSON 을 내보내 `npm run design:apply-tokens -- <파일>`(토큰 diff) · `npm run design:apply -- <파일>`(화면 속성)으로 검토한 뒤 `--write` 와 `npm run test` 로 반영한다. 자세한 것은 [STUDIO_VALIDATION.md](STUDIO_VALIDATION.md).

셸 연결: 패널은 첫 화면 오른쪽에 열려 있고(`panel=design` · 「화면 조건」 탭으로 바꾸면 해시에 `panel=controls`), 높이가 고정된 자리에서 스스로 스크롤한다. 시안 내용이 바뀌면(`onDraftChanged`) 그 시안을 건 프레임(A/B 면 B)만 다시 불러온다. 옛 `#studio` · `#compare` · `#atlas` 주소와 화면별 Mock 어댑터(`src/claude-home` · `src/current-home` · `src/rest` · `src/archive` · `src/my` · `src/report` · `src/diary` · `src/retro`)는 셸 진입에서 빠졌다 — 통합 때 정리한다. 셸 레이아웃별 관측은 `node expo-lab/scripts/measure-shell.mjs http://127.0.0.1:8085`(옛 `measure-studio.mjs` 자리).
