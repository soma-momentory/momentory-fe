# Momentory Expo Lab

웹에서 **앱의 모든 화면을 실제 앱 코드로** 처음부터 끝까지(스플래시 · 소개 · 로그인 · 온보딩 · 탭 · 회고 · 편지 · 쉼터 · 마이) 띄우고, 눌러서 흐름을 시험하고, 화면 상태(데이터 양 · 불러오는 중 · 서버 실패) · 시각 · 기기를 바꿔 보고, 같은 화면을 두 상태로 · AI 수정 결과와 나란히 비교하고, AI 시안 여러 개를 지금 앱과 한 줄에 놓고 하나를 골라 확정하는 **로컬 전용** 작업대다. 옛 캡처 Atlas(PNG 38장)는 지웠다 — 보이는 것은 전부 살아 있는 앱이다.

## 실행

```bash
npm ci
npm run lab:skins            # (선택) Android 에뮬레이터 스킨을 로컬 SDK 에서 복사 — 없으면 SVG 외형
npm run lab:web              # 포트 8085 고정(expo-lab/package.json) — 앱 개발 서버 8081 과 겹치지 않는다
```

`http://localhost:8085/` 를 연다. ⚠ `CI=1` 로 띄우면 Expo 가 파일 감시를 끄므로 코드를 고쳐도 다시 묶지 않는다.

## 구조 — 셸과 프레임 (2026-11-02 · 「전 화면」)

```
셸(최상위 창 · src/shell/ShellApp.tsx)
 ├ 왼쪽   「＋ 새 화면 만들기」 · 「새 화면 (작업 중)」 + 화면 목록 — app/ 에서 생성 · 앱 순서의 접히는 묶음 · 검색 · 배지
 ├ 가운데 도구줄(레이아웃 설명 · 확대 · 돋보기 · 화면 상태 고르기 · 키보드 올리기) + 한 화면 / 나란히 비교(A/B) / 모든 화면 / 기기별 / 시안 비교
 │        └ 실제 기기 외형(DeviceFrame) 안에 <iframe name={encodeFrameConfig(config)} src="/<라우트>">
 └ 오른쪽 화면 조건(맨 위 화면 상태 · B 화면 상태 … 맨 아래 서버 요청 기록) · AI에게 맡기기(AgentPanel)
프레임(iframe 안) = 실제 앱(expo-router 전체) + 가짜 서버 — 갈래 A·B
```

| B       | 가짜 서버 · 데이터 세트 · `sampleParams`         | `src/fake-server/`                                   |

| 공유    | 프레임 설정 · 셸↔프레임 메시지 (계약)            | `src/lab-contract.ts` — 바꾸면 세 갈래를 같이 고친다 |

디자인 편집기(옛 갈래 D · `src/design-editor/`) · 참고 시안 겹치기(`src/reference/`) · 「상태별로 보기」 레이아웃은 2026-11-02 에 지웠다 —
디자인 변경은 「AI에게 맡기기」에 지시 + 참고 그림으로 맡기고(아래), 상태는 「화면 조건」의 「화면 상태」로 고른다.

셸은 프레임에 **설정을 iframe 이름으로** 싣고(`LabFrameConfig` — 데이터 세트 · 플랫폼 · 기기 · 고정 시각 · 로그인 · 지연 · 실패 주소 · 오늘 다시 쓰기 · 글씨 배율 · 다른 서버면 셸 출처), **주소는 `lab:navigate` 로만** 옮긴다(키보드는 `lab:keyboard`). 프레임은 `lab:ready` · `lab:route` · `lab:statusBar` · `lab:request` · `lab:keyboardState` 를 보낸다(`src/shell/frameBus.ts` 가 단일 통로). 설정이 바뀌면 프레임이 새로 뜨되 **지금 서 있던 주소에서** 다시 시작한다 — 흐름 도중에 데이터 세트나 날짜를 바꿔도 제자리다. 프레임이 아직 준비 전이면(갈래 A 가 없을 때도) 메시지 대신 새로 띄운다.

### 상태는 URL 해시에

```
#/screens?route=/home&dataset=normal&platform=ios&device=iphone-16&layout=ab
         &now=2026-11-03T21:30:00%2B09:00&latency=1000&fail=/api/v1/reports&scale=1.3&repeat=0
         &zoom=1.5&nav=0&side=0&bdata=many&blatency=60000&bfail=/api/v1/reports
#/screens?route=/home&layout=variants&group=gmhxyz12        ← 시안 비교(보는 시안 묶음)
```

새로고침 · 뒤로/앞으로 · 주소 공유가 같은 화면을 다시 연다. 기본값은 적지 않는다. 형식은 `src/shell/hashState.ts`. 레이아웃은 `single` · `ab` · `grid` · `matrix` · `variants`(시안 비교 — `group` 이 보는 묶음 · A/B 에서도 남아 「다른 시안 다시 보기」가 그 묶음으로 돌아간다), 오른쪽 탭은 `panel=controls`(기본 · 화면 조건) · `agent` · `new-screen`(「AI에게 맡기기」 탭 안의 새 화면 칸). `bdata` · `blatency` · `bfail` 은 A/B 의 「B 화면 상태」(없으면 A와 같게). `today=1` 은 오늘 쓴 일기가 있는 프레임(쉼 추천 시트의 프리셋). 「AI 수정 결과」 미리보기는 해시에 남기지 않는다(새로고침하면 지금 앱으로 돌아온다).

**옛 주소도 그대로 열린다** — 지운 기능의 값은 기본으로 돌린다: `layout=states` → 한 화면, `matrix=datasets` → 기기별(축 없음), `panel=design` · `reference` · `log` → 화면 조건, `draft=…` 는 버린다(`src/shell/__tests__/state.test.ts`).

### 레이아웃 (위 탭 · 탭에 마우스를 올리면 한 문장 설명 · 도구줄 왼쪽에도 같은 문장)

- **한 화면** — 흐름 시험. 목록을 고르면 그 화면의 프리셋(아래)이 적용된다. 도구줄의 **「화면 상태: 기록 보통 ▾」**는 지금 상태를 보여 주고, 누르면 그 자리에서 목록이 열려 바로 고른다. 오른쪽 패널은 움직이지 않는다(2026-11-04 · 사용자 요청).
- **나란히 비교 (A/B)**(해시 `layout=ab`) — 같은 라우트를 두 대에. 처음에는 B 도 A 와 같은 상태이고, 「화면 조건」의 **「B 화면 상태」**(처음 「A와 같게」)를 고르면 B 만 그 상태로 다시 뜬다 — 기록 보통 vs 기록 많음, 기록 보통 vs 불러오는 중처럼. 기기 위 설명 줄이 지금 무엇을 견주는지 말하고(「같은 화면을 A는 「기록 보통」, B는 「기록 많음」 상태로 나란히 보여 줘요.」 · 같으면 「A와 B는 지금 같은 화면 · 같은 상태(「기록 보통」)예요. …」), **「B 화면 상태 바꾸기」**가 그 칸을 연다. 기기마다 머리(「A · 지금 앱」 / 「B · 지금 앱」 · AI 수정 결과면 「B · AI 수정 결과 (작업 이름)」)와 둘째 줄 「화면 상태: 기록 많음」(같으면 「… (A와 같게)」)을 단다. **「겹쳐서 차이 보기」**는 B 를 A 위에 겹치고 막대로 진하기를 바꾼다(겹친 동안 B 는 눌리지 않는다). 「두 화면 함께 이동」을 켜면 한쪽에서 누른 이동을 다른 쪽이 따라간다.
- **모든 화면** — 라우트마다 작은 실제 프레임. 화면 근처에 온 칸만 붙이고, 동시에 부팅하는 프레임은 4개로 묶는다. 칸을 누르면 한 화면으로.
- **기기별로 보기**(해시 `layout=matrix`) — 같은 라우트 · 같은 화면 상태를 표의 모든 기기에. (옛 「데이터별」 축은 지웠다 — 데이터는 화면 상태로 바꾼다.)
- **시안 비교**(해시 `layout=variants&group=…`) — 기존(지금 앱) + AI 가 만든 시안 최대 3개를 한 줄에. 아래 「시안 비교」 절.

### 화면 상태 (오른쪽 「화면 조건」 맨 위 · `src/shell/ScreenStatePicker.tsx` · `screenStates.ts`)

같은 화면을 **신규 사용자 · 기록 없음 · 기록 보통 · 기록 많음 · 긴 글 · 불러오는 중 · 불러오기 실패**로 바꿔 본다. 이름은 무엇에 대한 상태인지(기록의 양 · 글 길이 · 서버 응답)가 바로 읽히게 짓는다(2026-11-02 · 옛 이름 빈 계정 · 보통 · 많음 · 긴 문구 — id · 해시 값은 그대로). 이 칸이 옛 「테스트 데이터」 칸 · 도구줄 「상태 ▾」 · 「상태별로 보기」 레이아웃을 합쳤고, 한 화면의 도구줄에도 같은 목록이 있다(`ToolbarStatePicker` · 고를 수 없는 상태를 막는 규칙도 같다). 칸 아래 한 줄이 무엇을 바꿨는지 말한다. 한 화면 · A/B 의 A(와 「A와 같게」인 B) · 모든 화면 · 기기별에 함께 걸리고, A/B 에서는 **「A 화면 상태」 · 「B 화면 상태」** 두 칸이 된다.

| 상태          | 프레임 설정                                                                       |
| ------------- | --------------------------------------------------------------------------------- |
| 신규 사용자   | `new-user` — 일반 화면은 앱이 온보딩으로 보낼 수 있다(B 칸에는 없다 · 아래)       |
| 기록 없음 …   | `empty` · `normal` · `many` · `long-copy`                                         |
| 불러오는 중   | 기록 보통 + `latencyMs` 60000                                                     |
| 불러오기 실패 | 기록 보통 + `failPaths` = **이 화면이 실제로 부른 서버 주소**(고르는 순간의 목록) |

- **로그인 전 · 온보딩 화면**은 데이터가 「신규 사용자」 하나뿐이다 — 칸 아래 「로그인 전 · 온보딩 화면이라 기록이 생기기 전 상태(「신규 사용자」)로만 열려요.」 한 줄. B 도 그 세트로 연다.
- **B 칸에는 「신규 사용자」가 없다**(일반 화면) — 앱이 B 를 온보딩으로 보내면 「두 화면 함께 이동」이 A 까지 끌고 간다.
- **실패시킬 주소는 저절로 찾는다** — 셸이 `lab:request` 를 받을 때 그 프레임이 서 있던 화면 몫으로 모은다(`frameBus.pathsFor` · 두 단계 열기의 경유 화면 요청은 빼고). 주소는 id · 날짜 · 검색 조건을 뗀 접두사로 줄인다(`/api/v1/diaries?year=…` → `/api/v1/diaries`, `/api/v1/letters/2026-11-01` → `/api/v1/letters`). 아직 하나도 모으지 못했으면 「불러오기 실패 (요청을 찾는 중)」으로 막아 둔다. 고르면 칸 아래에 「실패시킨 요청: /reports/weekly」처럼 보인다. 앱이 켜질 때 부르는 `/api/v1/users/me` 도 그대로 둔다 — 실패해도 앱 진입은 막히지 않는다(홈은 그대로 · 마이는 닉네임이 빈다).
- **요청이 없는 화면**(소개 · 로그인 …)은 바탕 프레임(한 화면 · A)이 준비되고 1.5초 동안 요청이 없으면 「이 화면은 서버에 요청하지 않아요 — 「불러오는 중」 · 「불러오기 실패」는 고를 수 없어요.」 한 줄을 띄우고 두 칸을 막는다(「(요청 없는 화면)」).
- **불러오는 중은 오래 머물지 않는다** — 앱의 요청 시간 제한(10 ~ 25초)이 지나면 앱이 실패 안내로 바꾼다. 칸 아래 **「처음부터 다시 보기」**(B 는 「B 처음부터 다시 보기」)로 그 폰만 다시 띄운다. 두 단계로 여는 화면도 이 상태는 경유 없이 바로 연다(경유 화면의 응답까지 1분 늦어 목적지에 못 가므로 — `LabFrame` 의 `skipVia`).
- 아래 「서버 응답 (세부)」에서 지연 · 실패 주소를 직접 바꾸면 화면 상태는 **「직접 고른 조건」**으로 보이고, 다시 고르면 그 상태로 돌아간다.

### 확대 · 돋보기 (가운데 도구줄 — 확대 조작은 여기 한 곳)

- **화면에 맞게**(기본 · `zoom` 없음) — 무대에 꽉 차게, **크게도** 맞춘다(최대 200%). 한 화면은 무대 높이, A/B 는 두 대가 나란히, 기기별은 줄 수를 바꿔 가며 가장 크게 들어가는 배치(`src/shell/stageFit.ts`). 모든 화면은 맞춤이어도 30%.
- **100% · 125% · 150% · 200% · −/+**(계단 25% ~ 200%) — 해시 `zoom=1.5`(옛 0.1 ~ 2 값도 그대로 읽는다). iframe 은 늘 기기 CSS 크기 그대로이고 바깥 `transform: scale` 로만 키우며, 바깥 상자가 키운 크기만큼 자리를 잡아 스크롤이 맞는다.
- 단축키(셸에 포커스가 있고 입력칸 밖일 때 · 프레임 안에 포커스가 있으면 브라우저 확대를 건드리지 않는다): **Ctrl/⌘ + = / − / 0(화면에 맞게)**.
- **돋보기로 보기**(또는 **Z 를 누르고 있는 동안**) — 커서 주변을 둥근 렌즈(지름 220 · Shift+휠 120 ~ 420)에 2배(휠 · `[` `]` 로 1.5 ~ 4배)로 보인다. 렌즈 안은 프레임 문서의 **스냅숏**이다(`src/shell/magnifierSnapshot.ts` — 같은 출처 iframe 의 `<body>` 를 복제하고, react-native-web 이 `insertRule` 로 넣은 규칙을 `document.styleSheets` 에서 모아 싣고, 스크롤 위치 · 입력 중인 글자(`input.value`)를 옮겨 적는다 · 커서가 움직이면 150ms, 가만히 있으면 0.5초마다 다시 뜬다). **A/B 에서는 두 기기의 같은 자리**에 렌즈 둘. 렌즈를 쓰는 동안은 투명한 층이 마우스를 받으므로 앱이 눌리지 않는다(도구줄에 한 줄로 알린다) · Esc 로 끈다. 상태바 · 섬 · 홈 막대는 셸이 그리는 것이라 렌즈에는 앱 화면만 보인다.

### AI에게 맡기기 (오른쪽 「AI에게 맡기기」 탭 · `src/agent/` · 서버 `server/`)

지금 보는 화면을 이 PC 에 로그인된 Claude Code · Codex 에게 고치게 한다. 탭을 여는 것만으로는 아무것도 생기지 않고, 처음 「AI에게 수정 맡기기」를 누를 때 서버가 그 화면용 작업 공간(저장소 바깥 git worktree + `lab/…` 브랜치 + 수정 결과 화면)을 만든다. 규칙은 [HANDOFF.md](HANDOFF.md) 「Lab 에서 바로 맡길 때」.

- **지시는 두 칸이다**(2026-11-02) — 위는 읽기만 하는 **「AI에게 함께 보내는 정보」**(점선 칸 · `[화면] 제목 (스펙 ID) · 라우트` · `[파일] app/…`(`routes.generated.ts`) · `[환경] 기기 (플랫폼) · 데이터: 화면 상태의 데이터 이름` · 「화면 · 기기 · 화면 상태를 바꾸면 따라 바뀌어요」), 아래는 빈 칸 **「무엇을 바꿀까요?」**(예시 문장이 흐리게 · 예: 카드 사이 간격을 조금 넓히고, 제목을 한 단계 크게 해줘). 보낼 때는 둘을 이어 `instruction` 하나로 보낸다 — 함께 보내는 정보 세 줄 + `지시: ` + 적은 말(`composeInstruction` · 옛 미리 채운 칸과 같은 모양이라 서버는 그대로다). 할 말도 그림도 없으면 버튼이 꺼지고 「「무엇을 바꿀까요?」에 할 말을 적거나 그림을 붙여요」 한 줄이 뜬다. 시안 개수 2 · 3 도 같은 두 칸 · 같은 규칙이다. 다른 탭을 보고 오거나 기기 · 화면 상태를 바꿔도 적던 지시는 남고(패널을 붙여 둔다), 다른 화면을 고르면 비운다(그 화면에 맞춘 말이라).
- **디자인을 바꿀 때는 그림을 붙인다** — 원하는 모습(피그마 · Claude Design 캡처)은 「참고용」, 앱에 넣을 그림은 「앱에 넣기」(`AttachmentPicker` · 12장까지). 서버가 작업 공간의 `.lab-attachments/<실행>/` 에 풀고 프롬프트에 `[첨부]` 줄로 넘긴다. 할 말도 그림도 없으면 보낼 수 없다.
- **「수정 결과 보기」** → A/B 의 **B 자리**에 작업 공간의 미리보기 서버를 띄운다(아래 「미리보기」). 다른 화면의 작업은 「다른 작업 N개」에서 열고, 「그 작업 보기」는 그 화면으로 옮긴다. 시안 묶음은 「다른 작업」에 시안마다가 아니라 **묶음 한 줄**(「마이 · 시안 3개 · 시안 1 다 만듦 · …」)로 들어간다.
- **「시안 개수」 1개 · 2개 · 3개**(기본 1개 = 지금 그대로) — 2 이상이면 버튼이 「시안 N개 만들기 맡기기」가 되고, 같은 지시로 **방향이 다른 시안**을 작업 공간마다 하나씩 만든다(아래 「시안 비교」).
- 서버 API(`/__lab/agent/*`)는 이 개발 서버에만 달린다 — 미리보기 서버(`MOMENTORY_LAB_AGENT=off`)에는 없다.
- **작업 공간이 많아도 멈추지 않게** — 목록(`/status` · `/workspaces`)은 변경 내역을 1분 기억해 바로 주고, 오래된 것은 뒤에서 작업 공간 넷씩 나눠 읽는다. 실행 중인 시안 · 한 작업 공간을 열거나 고친 뒤 · 실행이 끝난 뒤에는 바로 새로 읽는다. 패널 폴링은 앞선 응답이 올 때까지 다음 요청을 보내지 않는다(`useAgentStatus`).

### 새 화면 만들기 (왼쪽 목록 맨 위 「＋ 새 화면 만들기」)

누르면 오른쪽에 「새 화면 만들기」 칸(해시 `panel=new-screen` · 탭은 「AI에게 맡기기」가 눌린다 · 「← 이 화면 고치기로」로 돌아간다)이 열린다 — 화면 이름 · **주소에 쓸 영문 이름**(예: sleep-log · 화면 주소 · 파일 이름이 된다) · 들어갈 곳(앱의 어느 묶음에 붙일지) · 어떤 화면인지(꼭 · 무엇을 보여 주고 무엇을 누르는지) · (선택) 그림. 보내면 `kind: "new-screen"` 작업 공간이 생기고, 왼쪽 목록 맨 위 **「새 화면 (작업 중)」** 묶음에 이름과 상태(「AI가 고치는 중」 …)로 올라온다(`GET /__lab/agent/workspaces` · 10초마다, 작업 중이면 2.5초마다 다시 읽는다 · `src/shell/AgentNav.tsx`). 줄을 누르면 그 작업 공간의 미리보기 서버에서 `newRoutes[0]`(없으면 첫 화면)을 **한 화면**으로 연다 — 미리보기가 꺼져 있으면 켜고(「수정 결과 화면을 켜는 중…」) 준비되면 저절로 연다. 새 화면은 이 서버의 `app/` 에 아직 없으므로 A/B 의 A 에는 없다.

### 미리보기 — AI 수정 결과 (B · 한 화면)

- A/B 에서 B 는 `<iframe src="<미리보기 주소>/<라우트>">` 이고 이름(설정)은 이 서버의 B 와 같다 — **「B 화면 상태」도 그대로 실린다**(AI 결과를 기록 많음 · 불러오는 중으로 보기). 머리는 **「B · AI 수정 결과 (작업 이름)」** + 둘째 줄 「화면 상태: …」 · **「AI 결과 닫기」**. 한 화면에서도 같은 폰에 띄우고, 도구줄 한 줄에 「AI 수정 결과 (이름) 보는 중」 · 「지금 앱과 나란히 보기」 · 「지금 앱으로 돌아가기」가 뜬다.
- **다른 출처**: 미리보기는 다른 포트라 다른 출처다. 셸은 설정에 `shellOrigin`(자기 `location.origin`)을 싣고, 프레임(`src/frame/messages.ts`)은 그 출처로만 보내고 **부모 창이 그 출처에서 보낸 것만** 믿는다(없으면 자기 출처 — 같은 서버 프레임은 예전 그대로). 셸(`frameBus`)은 같은 출처면 예전처럼, 다른 출처면 **그 frameId 로 붙은 iframe 의 창이 보낸 것만** 받고, 보낼 때는 iframe `src` 의 출처로 보낸다. ⚠ 이 규칙은 **미리보기 쪽 Lab 코드에도 있어야** 한다 — 작업 공간의 기준 브랜치에 이 변경이 없으면 B 가 셸에 말하지 못한다(B 는 보이지만 목록 배지 · 함께 이동 · 요청 기록이 따라오지 않는다).
- 다른 출처 문서는 셸이 읽을 수 없어 **돋보기는 B 에 쓸 수 없다** — 도구줄에 「AI 수정 결과 화면은 다른 서버라 돋보기를 쓸 수 없어요」 한 줄. 돋보기는 A 에만 렌즈를 띄운다. 겹쳐서 차이 보기는 셸이 그리는 것이라 그대로 된다.

### 시안 비교 — 시안 여러 개 → 하나 고르기 → 최종 A/B → 확정 (2026-11-02)

이미 있는 화면을 고칠 때 방향을 여럿 놓고 고르는 흐름이다. 새 화면 만들기에는 없다.

1. **시안 여러 개 만들기** — 「AI에게 맡기기」에서 **「시안 개수」**를 2 · 3 으로 고르고 지시 하나를 보낸다(`POST /__lab/agent/variants` · `count`).
   서버가 같은 화면 · 같은 지시로 작업 공간을 N개(`<라우트>-s1` … · 제목 「홈 · 시안 1」 … · 한 묶음 id `g…`) 만들고 **시안 수만큼 동시에** 돌린다(2026-11-03 — 하나씩 돌리니 너무 느렸다).
   Lab 전체에서 한 번에 한 건이라는 규칙은 그대로이고 묶음이 통째로 한 건이다 — 시안이 하나라도 도는 동안 다른 지시는 받지 않는다(「시안을 만드는 중이에요 — 다 끝난 뒤에 지시해요」).
   시안은 서로의 결과를 못 보므로 **방향을 미리 나눠 준다** — 프롬프트에 「[시안 k / N]」 · 이 시안이 맡은 방향 · 다른 시안이 맡은 방향이 붙는다(HANDOFF.md 「시안 여러 개」). 시안은 고르기 전 초안이라 바뀐 파일만 검사하게 하고(테스트는 `--maxWorkers=2`), 저장소 전체 검사는 고른 시안을 저장할 때 「저장 전 검사」가 맡는다.
   패널에는 묶음 카드(「홈 · 시안 3개」)가 생겨 **「시안 1 다 만듦 · 시안 2 만드는 중 · 시안 3 만드는 중」** 한 줄 · **「시안 비교로 보기」** · **「시안 만들기 멈추기」**(도는 시안을 모두 멈춘다 — 「멈춤」) · 시안마다 「자세히」(진행 기록 · 결과 · 이어서 맡기기)를 보인다.
2. **다 같이 보기(「시안 비교」 탭)** — 한 줄에 **「기존 · 지금 앱」 + 「시안 1」 「시안 2」 「시안 3」**. 같은 라우트 · 같은 기기 · 같은 화면 상태(「화면 조건」의 화면 상태)이고, 폰 머리 둘째 줄이 상태다 — 기존은 「화면 상태: 기록 보통」, 시안은 「준비됨 · 방향: …」(AI 요약 첫 줄) · 「만드는 중」 · 「시작하는 중」 · 「준비 중」 · 「실패」 · 「멈춤」.
   시안 폰은 그 작업 공간의 **수정 결과 화면**(미리보기 서버 · 다른 출처 — A/B 의 「AI 수정 결과」와 같은 길)이다. 화면이 없으면 폰 자리에 한 줄(「AI가 이 시안을 만드는 중이에요」 · 「곧 만들기 시작해요」 · 「수정 결과 화면을 켜는 중…」 · 실패 이유 + 「다시 켜기」)만 두고 지금 앱을 대신 띄우지 않는다.
   이 탭이 열리면 **실행이 끝났는데 꺼져 있는 시안의 수정 결과 화면을 켠다**(한 번씩 — 시안 실행이 끝나도 서버는 저절로 켜지 않는다. 다른 시안이 아직 돌 수 있기 때문이다).
   「모두 함께 이동」 · 키보드 올리기 · 화면에 맞게(네 대를 한 줄로)는 모든 폰에 걸리고, **돋보기는 「기존」에만** 쓴다(「시안 화면은 다른 서버라 돋보기는 「기존」에만 써요」 한 줄).
   같은 화면에 묶음이 여럿이면 설명 줄의 「시안 묶음」 고르기로 바꾼다. 묶음이 없으면 「이 화면의 시안이 아직 없어요 …」 + 「AI에게 맡기기 열기」.
3. **최종 A/B** — 시안 아래 **「이 시안 고르기」** → 나란히 비교(A/B)로 바뀌고 A = 지금 앱, B = 그 시안(머리 「B · 시안 2 (AI 수정 결과)」). 설명 줄이 「A는 지금 앱, B는 고른 「시안 2」(시안 3개 중)예요.」라고 말하고, **「← 다른 시안 다시 보기」**가 시안 비교로 돌아간다. 「B 화면 상태」는 그대로 쓴다.
4. **최종 결정** — 같은 줄의 **「이 시안으로 확정」** → 저장 메시지 · 검토 요청 제목(본문은 접어 둠)이 미리 채워진 칸 + **「저장하고 검토 요청 올리기」**: 그 시안 작업 공간에 기존 길을 그대로 — 저장 전 검사(`…/check`) → 통과하면 저장(`…/commit`) → 검토 요청(`…/pr`). 지적이 나오면 목록 + 「그래도 확정」 · 「그만두기」. **합치기(머지)는 하지 않는다.**
   끝나면 「확정했어요 — 시안 2 · 검토 요청 #N 열기」와 **「나머지 시안 버리기」** — 누르면 줄 안에서 「시안 1 · 시안 3의 작업 공간과 수정 결과 화면이 사라져요 …」 + 「버리기」 · 「그만두기」로 한 번 더 묻고(브라우저 대화 상자는 쓰지 않는다), 「버리기」에서야 `DELETE /__lab/agent/variants/<묶음>?keep=<고른 시안>` 을 부른다(미리보기 먼저 끄고 · junction 먼저 끊는 기존 버리기 그대로).

**미리보기 서버 상한** — 미리보기는 하나하나가 Metro 서버라 켜는 데 오래 걸린다(시안 3개 동시에 약 20초). 켜 둔 것은 하나에 0.25GB 쯤이고 가만히 있을 때 CPU 를 거의 안 쓰므로, 서버는 한꺼번에 **12개**(시안 3개 묶음 넷 · `MAX_PREVIEWS`)까지 띄워 두고 넘으면 가장 오래 찾지 않은 것을 끈다(시안 비교를 닫아도 켜 둔 것은 그대로 — 예전과 같다). 묶음을 다시 열면 그 시안을 「방금 봤다」고 알리고, 꺼져 있었으면 다시 켠다.

### 키보드 올리기 · 내리기 (가운데 도구줄)

입력칸을 누르면 프레임의 화면 키보드(`src/frame/keyboard/`)가 저절로 올라온다. 도구줄의 **「키보드 올리기 / 내리기」**는 입력 없이 키보드 올린 모습을 볼 때 쓴다 — 한 화면은 그 폰, A/B 는 두 폰, 시안 비교는 떠 있는 폰 모두에 함께 `lab:keyboard {open}` 을 보낸다. 눌림 상태(`aria-pressed`)는 프레임이 알린 `lab:keyboardState {open, height}` 를 따르고(입력칸을 눌러 올라와도 눌린다), 프레임을 다시 띄우면 내려간 것으로 돌린다. 셸이 연 키보드는 포커스가 빠져도 내려가지 않는다 — 이 단추나 앱의 `Keyboard.dismiss()` 로 내린다.

### 패널 접기 · 좁은 창

- 머리줄 **「목록 보기」 · 「오른쪽 칸 보기」**(aria-pressed), 패널 안의 **«(목록 접기) · ×(패널 닫기)** 로 양옆을 접는다 — 해시 `nav=0` · `side=0`. 접힌 자리에는 얇은 막대가 남고, 막대의 「목록 열기」 · 「조건 바꾸기」 · 「AI 맡기기」를 누르면 그 탭으로 다시 열린다. 「AI에게 맡기기」는 한 번 열면 붙어 있어 다른 탭을 보고 와도 적던 지시를 잃지 않는다.
- 창이 **1180px 보다 좁으면**(브라우저 확대 등) 양옆이 저절로 접히고, 같은 버튼이 무대 위에 뜨는 **서랍**으로 연다(바깥을 누르거나 Esc 로 닫는다). 무대는 360px 아래로 줄지 않고, 기기 · 칸 이름은 한 줄 말줄임(칸은 120px 아래로 좁아지지 않는다)이라 글자마다 줄바꿈되지 않는다.

### 화면 목록

묶음(진입 · 소개 · 온보딩 · 탭 · 홈 시트 · 회고 · 편지 · 일기 · 쉼터 콘텐츠 · 마이 세부)은 **접혀 있고** 머리 줄(「＋/－」 · 이름 · 화면 수)을 누르면 펼친다. 여러 묶음을 함께 펼칠 수 있고(「모두 펼치기 / 모두 접기」), 펼친 묶음은 localStorage(`momentory.lab.shell.openSections`)에 남는다. 지금 화면의 묶음은 저절로 펼치고 그 줄을 강조한다. 검색어가 있으면 접힘을 무시하고 일치하는 묶음만 보인다.

**라우트가 아닌 줄**(`routeMeta.ts` 의 `screenOf`) — 라우트 위에 뜨는 시트를 바로 고르는 줄이다. 지금은 「쉼터 콘텐츠」 맨 앞의 **「쉼 추천 시트」** 하나다: 앱이 일기 완료 뒤에 쓰는 주소(`/rest?afterDiary=1`)에 오늘 쓴 일기(프레임 설정 `todayDiary` · 해시 `today=1`)를 더해 쉼터를 열면 0.6초 뒤 시트가 올라온다. 오늘 일기는 **따로 쓰는 가짜 DB**(`…:today-diary`)에만 심어 같은 데이터 세트의 다른 화면에는 번지지 않는다 — 앱 코드는 그대로다. 프레임이 `/rest` 에 있는 동안 목록은 이 줄에 머물고, 닫은 뒤 줄을 다시 누르거나 화면 상태를 바꾸면 시트가 다시 뜬다. 「불러오는 중」 · 「불러오기 실패」는 일기를 못 받으므로 시트 없이 쉼터만 보인다.

### 화면 조건 패널

처음 여는 오른쪽 탭이다. 위에서부터 **화면 상태**(+ A/B 면 B 화면 상태 · 위 절) · 플랫폼 · 기기 · 로그인 상태 · **오늘 다시 쓰기**(켜면 오늘 이미 썼어도 일기를 다시 쓸 수 있다 · 끄면 실제 서버처럼 하루 1번) · **일기 쓰기 다시 시작**(`/retro/confirm` · 「직접 쓰기로 시작」 `/retro/write` 를 새로 띄운다) · 쓴 기록 되돌리기(`lab:resetData` · 프레임이 못 들으면 셸이 직접 비운다) · **가상 시각**(아침 8:00 · 밤 21:30 · 03:59 = 04:00 하루 경계 직전 · **하루 넘기기 +1일 / 되돌리기 −1일**(시·분 유지) · 지금 시각으로) · 서버 응답 (세부)(바로 · 1초 · 5초 늦게 · 일부 요청 실패시키기 — 화면 상태보다 세밀하게 바꿀 때) · **글씨 크기**(작게 0.85× · 기본 · 크게 1.3× · 아주 크게 1.5× — 설정의 `textScale` 로 넘기고 프레임이 바로 적용한다 · 1.5 는 앱 상한 1.3 을 넘겨 배치를 점검하는 값) · 폰 화면 새로 불러오기. 뜻이 바로 안 보이는 조작에는 마우스를 올리면 한 문장 설명(`title`)이 뜬다. 맨 아래 접힌 **「서버 요청 기록 (개발용)」**(옛 「요청」 탭 · 해시 `panel=log` 는 이 패널로 연다)은 화면이 비거나 오류가 날 때 어떤 요청이 실패했는지 보는 자리이고, 실패(4xx · 5xx)가 있으면 접힌 머리에 빨간 숫자만 뜬다. 가짜 DB 는 `frameId:datasetId` 로 남으므로 하루를 넘겨도 쓴 기록이 쌓인다.

**차갑게 열기 점검(2026-11-02)** — 57개 라우트를 모두 바로 열어 본 것과 앱에서 그 화면을 여는 앞 화면(`router.push` 를 부르는 화면)부터 차례로 옮겨 온 것을 글자 · 입력값으로 견줬다. 달랐던 열 개에 `openVia` 를 새로 달았고(같은 칸을 쓰는 성별 수정도 함께 · 원래 있던 셋은 그대로 맞았다), 흐름 · 입력에 기대는 넷은 `hint` 로 알린다. 나머지는 같았다. 새 라우트를 더하면 같은 방식으로 견주고, 앞 화면이 받아 두는 데이터를 쓰면 `openVia` 를 단다.
